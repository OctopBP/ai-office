# tools/imagegen — генератор картинок как MCP-сервер

Инструмент, которого нет у самого Claude Code: умение нарисовать картинку.
Подключается ролям каталогом офиса (`src/server/mcp.ts`, сервер `imagegen`),
по умолчанию — иллюстратору.

```
server.mjs            MCP-сервер: три инструмента, ожидание, отчёт
save.mjs              куда ложатся файлы и почему только туда
providers/index.mjs   контракт провайдера и реестр
providers/nanobanana.mjs   nanobananaapi.ai: задачами, исходники ссылками
providers/gemini.mjs       Gemini напрямую: синхронно, исходники файлами
```

Зависимость одна — `@modelcontextprotocol/sdk` из корневого `node_modules`.
Свой `package.json` не заводится намеренно: `tools/props` — отдельный пакет,
потому что тянет `sharp` и `@google/genai`, а здесь хватает встроенного
`fetch`, и лишний `npm install` стоил бы дороже, чем экономит.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `generate_image` | нарисовать по описанию и сохранить файлом; ждёт результат внутри вызова |
| `get_image_task` | забрать задачу, которая не успела за отведённое время |
| `get_image_providers` | что подключено, с каким ключом, какие стороны и сколько вариантов |

Имена не косметика: разбор рисков офиса (`src/server/permissions.ts`) считает
инструменты с префиксом `get_` безопасными и не спрашивает про них человека.

## Ключи и настройки

Всё через окружение процесса офиса — в настройки офиса ключ попасть не может,
они уезжают на фронт в каждом снимке.

| Переменная | Зачем |
|---|---|
| `NANOBANANA_API_KEY` | ключ nanobananaapi.ai — https://nanobananaapi.ai/api-key |
| `GEMINI_API_KEY` | ключ Google AI Studio; тот же, что у `tools/props` |
| `IMAGEGEN_PROVIDER` | какой провайдер по умолчанию; пусто — первый в списке |
| `OFFICE_WORKDIR` | рабочая копия сотрудника; кладёт офис, руками не задаётся |
| `IMAGEGEN_WAIT_MS` | сколько ждать картинку внутри вызова (55 000 по умолчанию) |
| `IMAGEGEN_POLL_MS` | как часто спрашивать провайдера (3 000) |
| `NANOBANANA_BASE_URL` | адрес API, если он переедет |
| `NANOBANANA_CALLBACK_URL` | куда провайдеру стучаться по готовности |

Про колбэк: поле в API обязательное, а слушать его офису негде, поэтому по
умолчанию туда уходит адрес в зарезервированной зоне `.invalid` — он не
резолвится ни у кого, то есть уведомление гарантированно уходит в никуда, а не
чужому хосту.

## Границы, о которых надо знать заранее

**Писать можно только внутрь рабочей копии.** Сервер поднимает процесс офиса,
а не сессия: его текущая директория — корень офиса, и про ветку задачи он не
знает. Поэтому относительные пути считаются от `OFFICE_WORKDIR`, а всё, что
ведёт наружу, отклоняется с объяснением.

**Правка картинки зависит от провайдера.** У nanobanana нет эндпоинта загрузки
файла вовсе — исходник передаётся ссылкой, локальный png приложить нечем. У
Gemini наоборот. Провайдер объявляет это полем `refs`, и запрос не того вида
отклоняется до того, как за него заплатили.

**Прозрачности у моделей нет.** Картинка с альфа-каналом делается генерацией на
плоском ключевом цвете и хромакеем после — ровно так работает пайплайн спрайтов
в `tools/props`.

**Расход не виден офису.** Деньги списываются с чужого ключа, и на доске
расходов офиса (там считаются токены моделей Anthropic) их нет. Сколько
осталось у провайдера, показывает `get_image_providers` — там, где API умеет
отвечать про кредиты.

## Проверка

```bash
npm run test:imagegen
```

Сети в проверке нет: `fetch` подменяется, и проверяются форма запроса к чужому
API, разбор его ответа, периметр записи и то, что сервер отвечает по протоколу
MCP. Настоящий запрос стоит денег, и в наборе проверок ему не место.

Поговорить с сервером руками:

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' '{"jsonrpc":"2.0","method":"notifications/initialized"}' '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_image_providers","arguments":{}}}' | node tools/imagegen/server.mjs
```

## Как добавить провайдера

1. Положить файл в `providers/`, экспортировать объект по контракту из
   `providers/index.mjs`: `id`, `title`, `keyEnv`, `aspects`, `maxCount`,
   `refs`, `start`, `poll`, необязательный `credits`.
2. Дописать его в `PROVIDERS`. Первый в списке — тот, что по умолчанию.
3. Если API синхронное, `start` возвращает результат сразу полем `done` —
   опрашивать тогда нечего.
4. Дописать переменную ключа в каталог офиса (`DEFAULT_MCP_SERVERS`
   в `src/server/mcp.ts`), иначе она не доедет до процесса сервера.

Больше нигде ничего трогать не надо: инструменты, отчёты и периметр записи
общие для всех провайдеров.
