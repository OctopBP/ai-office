# Пакеты сотрудников

Здесь лежит то, что роль умеет сверх своего брифа. Имя папки — id роли:
пакет `employees/design/` достаётся роли `design` и больше никому.

```
employees/<роль>/
  .claude-plugin/plugin.json     имя, версия, описание
  skills/<навык>/SKILL.md        свои навыки
  pack.json                      ссылки на чужие плагины и отбор скилов
```

Формат не наш: это обычный **плагин Claude Code**. Своего мы не заводим
намеренно — такой пакет ставится и работает в обычном Claude Code без офиса
вовсе, а у плагинов уже есть маркетплейсы. То есть пакет сотрудника можно
однажды опубликовать, не изобретая ни хранилища, ни установщика.

Пакета может не быть: роль без папки запускается ровно так же, как до
появления этого каталога.

## Что здесь уже есть

| Пакет | Роль | Навыки |
|---|---|---|
| `design/` | UI/UX дизайнер | `figma-screen` — порядок вызовов моста, авто-лэйаут вместо координат, формат id, проверка скриншотом; `figma-tokens` — работать по переменным и стилям файла, а не по выдуманным цветам |

## Бриф или скил

Делятся они не по важности, а по цене и по времени чтения.

**Бриф** уезжает в системный промпт целиком и платится токенами в каждой
сессии роли. Поэтому в нём — обязанности и границы: за что сотрудник отвечает,
чего не делает, что считается сделанной работой.

**Скил** лежит на диске. Модель постоянно видит только его описание и читает
целиком лишь тогда, когда дело дошло до этого навыка. Поэтому в нём —
подробная инструкция к одному делу: порядок шагов, устройство инструмента,
чем проверить результат.

Отсюда правило: **«как пользоваться инструментом» — это всегда скил.** Если
бриф роли распухает инструкцией к Figma или к генератору спрайтов, значит скил
не написан.

Второе правило — про отбор: **скил берётся тогда, когда без него агент делает
шаг неправильно или дорого.** Не «на всякий случай»: каждое описание лежит в
контексте всех сессий роли, а промах в срабатывании обходится дороже, чем
отсутствие навыка.

Третье — про согласованность: **скил, которому нужен инструмент, требует и
подключения.** Навык про Figma в пакете роли, у которой нет `figma-bridge`
(см. `src/server/mcp.ts`), хуже отсутствия навыка: агент потратит ходы на
попытки вызвать то, чего нет.

## Чужие наборы: ссылаться, а не копировать

Готовый набор подключается через `pack.json`, файлами в репозиторий он не
кладётся:

```json
{
  "use": ["~/.claude/plugins/cache/claude-plugins-official/figma/*"],
  "skills": ["figma-design-to-code", "figma-use"]
}
```

`use` — пути к уже установленным плагинам; `~` раскрывается, `*` в последнем
сегменте берёт старшую версию (плагины ставятся в папку с номером, и прибитая
версия сломала бы пакет при первом обновлении). `skills` — необязательный
отбор: у большого чужого набора роли обычно нужна половина, а каждый навык
платится описанием в контексте всех её сессий.

Причина ссылок не техническая, а правовая. У официальных скилов Figma,
например, **нет лицензии вовсе** (репозиторий `figma/mcp-server-guide`
опубликован без неё), а их README требует согласия с Figma Developer Terms.
Положить такие файлы в свой репозиторий — значит раздавать чужое. Ссылка
снимает вопрос: плагин ставит пользователь, файлы остаются у установщика,
обновление плагина не требует пересборки пакета.

Второе, что показал тот же разбор: **чужой набор написан под чужие
инструменты.** Скилы Figma требуют `use_figma` и `get_design_context` из
официального Figma MCP, а у нашего дизайнера подключён `figma-bridge` с другим
набором (`create_frame`, `set_auto_layout`). Поэтому пакет `design/` — свой:
брать готовое имело бы смысл только вместе с переключением подключения.

И третье, про безопасность: скил — это инструкции, которые попадут в контекст
вашего агента и будут им исполнены. Прежде чем сослаться на чужой набор,
прочитайте его целиком.

MCP-серверы пакета офис намеренно не читает — ни своего, ни чужого по ссылке.
Чем роль ходит наружу, решает каталог в `src/server/mcp.ts`, там же живут
доверие и разбор рисков. Пакет объявляет умения, подключения выдаёт офис.

## Язык

Навыки написаны по-английски, хотя офис говорит по-русски. Это не небрежность:
скил читает модель, а офис бывает и англоязычным (`Settings.language`), и
русский текст навыка тянул бы ответы на русский в английском офисе. Бриф роли
переводится словарём (`src/server/i18n/`), скил — нет: он один на оба языка.

## Проверка

```
npm run test:skills                  # разбор пакета и имена скилов, без токенов
SKILLS_LIVE=1 npm run test:skills    # плюс живая сессия: видит ли она скил
```
