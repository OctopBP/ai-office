# Как участвовать

Спасибо, что заглянули. Здесь то, чего не угадать по коду: как поднять
окружение, что гонять перед PR и какие правила проект держит сознательно.

Два вида вклада:

- **Код офиса** — сервер, интерфейс, 3D-сцена, промпты. Про это весь файл.
- **Пакеты ролей в маркет** — новый сотрудник для офиса без правки офиса.
  Пакет живёт в своём репозитории, а в этот приходит PR с одной строкой в
  `registry/registry.json`; CI проверяет, что по ссылке лежит годный пакет.
  Формат и авторский путь (`npm run office-agent`) описаны в
  [packages/README.md](packages/README.md).

## Окружение

- Node 22 (`.nvmrc`), Git и **Git LFS**. Модели, анимации и текстуры лежат в
  LFS, а vite импортирует их из `design/`: без `git lfs install` до клонирования
  вместо моделей приедут файлы-указатели, и сцена не соберётся.
- Claude Code CLI, залогиненный через `claude` → `/login`, либо
  `ANTHROPIC_API_KEY`. Проверка: `npm run smoke`.
- Blender и python3 — только для 3D-сцены (`npm run scene`, `npm run model`).

```bash
git lfs install
git clone git@github.com:OctopBP/ai-office.git
cd ai-office
npm ci
npm run dev          # сервер под tsx watch + vite, http://localhost:5173
```

`npm run dev` перезапускает сервер на каждую правку и обрывает живые сессии
агентов. Если нужно, чтобы офис работал, пока вы правите код, запускайте
`npm run office` и перезапускайте осознанно: `npm run office -- --restart`.
Подробнее — [docs/guide/running.md](docs/guide/running.md).

Переменные окружения — в [.env.example](.env.example).

## Проверки

Перед PR:

```bash
npm run typecheck
npm run build
```

и наборы затронутых частей. Все `npm run test:*` кроме `test:pm` работают
без сети и токенов и проходят за секунды; полный список с тем, что каждый
проверяет, — в [docs/guide/running.md](docs/guide/running.md#полезные-команды).
CI гоняет их все на каждый PR.

**Промпты — это код.** Правили `src/server/i18n/prompts-*.ts` или инструменты
менеджера — прогоните регрессионные тесты менеджера:

```bash
npm run test:pm
```

Они стоят токенов и поэтому не в CI. Запускайте только через `npm run test:pm`:
он поднимает на каждый сценарий свой сервер. Прямой запуск
`scripts/test-pm.ts` цепляется к серверу на порту 3002 и сбрасывает его офис.

## Язык

Код, комментарии, коммиты, документация и обсуждения в PR — **по-русски**.
Это решение, а не случайность: проект пишется на одном языке, и смесь
хуже любого из двух.

Единственное исключение — фразы, которые видят пользователь и агенты. Они не
живут в коде вовсе: и подпись кнопки, и системный промпт лежат в словарях
`src/web/i18n/` и `src/server/i18n/` и достаются по ключу. Базовый словарь —
английский, он задаёт набор ключей; русский типизирован по нему, и забытая
фраза становится ошибкой сборки. Добавляете фразу — добавляйте в оба.

## Коммиты

Заголовок — что изменилось для пользователя или офиса, а не что сделано с
кодом. Хорошо читается форма «что: как теперь, а не как раньше»:

```
Посадка на месте: подъём на сиденье едет вместе с клипом, а не по таймеру
Клонов больше нет: второй такой же сотрудник — отдельная роль
Диалог папки на macOS: панель AppKit вместо System Events
```

Тело — почему: что было не так, как устроено теперь, что при этом
проверено. Один коммит — одно изменение; правку по пути не подмешивайте.

## Pull request

- Небольшой и про одно. Большую фичу лучше начать со спеки в
  `docs/design/<имя>/spec.md` и обсудить её issue, прежде чем писать код:
  так делаются все крупные части офиса, примеры лежат рядом.
- В описании — что и почему, как проверить, для интерфейса скриншот до и
  после. Шаблон подставится сам.
- CI должен быть зелёным, ревью делает владелец. Изменения в `registry/` и
  `packages/` дополнительно проверяет валидатор реестра.
- Отправляя PR, вы соглашаетесь, что вклад публикуется под
  [Apache-2.0](LICENSE) (раздел 5 лицензии). Отдельного CLA нет.

Ищете, с чего начать, — метки `good first issue` и `help wanted`.

## Как проект устроен

Карта файлов и главный принцип — в [OFFICE.md](OFFICE.md). Это бриф, который
офис подклеивает к промпту каждого агента, когда работает над собой, поэтому
он короткий и всегда актуальный. Остальное — в [docs/guide/](docs/guide/).

Правила, которые проект держит сознательно и которые в PR лучше не ломать:

- **Офис — визуализация, а не источник правды.** Логика живёт в доске задач и
  ленте событий; ходьба, пузыри и анимации рендерятся из событий и ничего не
  блокируют. Не заводите логику в компонентах отрисовки.
- **Режим вместо настройки.** Если хочется добавить галочку, спросите, не
  просится ли на её месте режим с гарантией: «офис на паузе» вместо
  «не запускать задачи», «readonly» вместо трёх флажков на инструменты.
- **Хранилище — JSON-файл, не база.** Данных мало, а нативный модуль добавил
  бы риск сборки.
- **Ключей в состоянии не бывает.** Файл состояния целиком уезжает в
  интерфейс. Токены — только ссылкой `${NAME}` на окружение сервера.
- **Изоляция не на доверии.** Границу исполнителя держат песочница и ветка
  задачи, а не просьба в промпте.

Нашли уязвимость — см. [SECURITY.md](SECURITY.md), не через issue.
