## Минимальное изменение

При неуспехе runProjectCheck возвращает необязательную диагностику: код выхода (включая инфраструктурный строковый код), сигнал, таймаут, действующий лимит, первую распознанную строку ошибки и путь к локальному файлу. Первая ошибка ищется по маркерам ❌, AssertionError, Error, TS, npm ERR!, not ok; null означает, что маркер не найден, а не что ошибок нет. Потоки записываются отдельными секциями stdout/stderr; хронологический порядок между ними не восстанавливается.

Полный собранный вывод до обрезки хвоста пишется только для неуспеха в <tmpdir>/office-check-<уникальный суффикс>/вывод.log, каталог 0700, файл 0600, максимум 64 МиБ. Существующий opts.mask применяется до записи. Переполнение буфера сборщика или лимита файла явно помечается выводОбрезан; сверх лимита обещания полного вывода нет. Файлы локальны машине сервера и могут быть удалены системой очистки временных файлов: после следующего сбоя нужно сохранить нужный файл сразу. Ошибка записи отражается в результате и не меняет исход проверки. В промпт попадают короткая причина, статус, путь и прежний хвост, а не полный лог.

premerge переносит диагностику в report.failed, toGateView — в gate.failed. Имеющийся review.ts уже сохраняет её без новых изменений конвейера. Для группового запуска сохранён код завершения, таймер отделён от снятия по лимиту буфера, усечение также отмечается. Таймауты, бюджеты, workflow, тестовые утверждения и обязательное ревью не изменялись.
