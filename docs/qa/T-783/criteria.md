# Критерии проверки T-783

Источник: бриф T-783. Дата: 02.11.2026.

1. В текущем MCP browser установить доступность обновлённого UI: зафиксировать фактический URL, состояние приложения и возможность выбрать вкладку/перейти к штатному приложению. Версию beta.21 desktop-70 считать подтверждённой в браузере только при наличии доказательства загрузки.
2. На доступном реальном рейле проверить две строки 5h/1w, стоимость, признаки неполноты и неизвестного значения, соответствие шкал окнам. Отсутствующие состояния не считать PASS.
3. Проверить читаемость подсказок обоих рядов при наведении и клавиатурном фокусе, обычный и узкий рейл, светлую и тёмную темы.
4. Отделить проверенное от ограничений; сохранить доказательства только доступного рейла. Не изменять живые данные, бюджеты и провайдеров, не запускать новый стенд и не запрашивать ручной preview.

## Матрица «устройство × сценарий»

| Окружение | Доступность UI | Строки и шкалы | Подсказки: наведение/фокус | Неполнота/неизвестное | Темы |
|---|---|---|---|---|---|
| Текущий browser, 1440×900, DPR 2, landscape-primary, онлайн | Проверить первой | При доступном UI | При доступном UI | Только существующие данные | Светлая/тёмная при доступном UI |
| Узкий рейл | После доступа к UI | Оба ряда | Читабельность | Только доступные состояния | Обе |

Условие остановки из брифа: если browser показывает только about:blank/app=null и не предоставляет путь в приложение, зафиксировать это и остановиться без повторов. Невыполненные визуальные сценарии получают BLOCKED; это не завершение визуальной приёмки.
