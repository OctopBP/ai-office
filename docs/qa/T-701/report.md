# Отчёт QA: T-701 — вложения в чате с менеджером

**Вердикт: FAIL**

FAIL — не по найденным дефектам продукта, а потому что критерии 1–5 (пользовательская часть) не выполнены: инструменты браузера QA не умеют выбрать файл, перетащить его и вставить из буфера, а на стенде нет провайдера, без которого скрепка заблокирована. Серверная часть и история проверены и работают.

## Критерии

| № | Критерий | Результат |
|---|---|---|
| 1 | Скрепка, один и несколько файлов | НЕ ПРОВЕРЕНО в интерфейсе (см. ограничения). Загрузка одного и нескольких файлов через API — работает |
| 2 | Drag-and-drop, подсветка | НЕ ПРОВЕРЕНО (нет жеста перетаскивания файла). Код `shell/Composer.tsx` прочитан: подсветка включается при `Files` над окном |
| 3 | Перетаскивание мимо чата | НЕ ПРОВЕРЕНО руками. По коду `dragover`/`drop` на `window` вызывают `preventDefault` для файлов, то есть браузер не должен открывать файл |

## Находки

### MINOR-1. Текст ошибки про 20 МБ сам себе противоречит
- Критерий: 6. Устройство: десктоп 1440×900, DPR 2, онлайн (запрос curl к API).
- Шаги: `POST /api/chat/attachment?office=o-1&chat=C-1&name=big.bin` с телом 21 000 000 байт.
- Ожидание: сообщение называет размер файла, например «больше 20 МБ (21 МБ)».
- Факт: `File “big.bin” is larger than 20 MB (20 MB) — not saved.` — размер округлён вниз до 20 МБ, выходит «больше 20 МБ (20 МБ)».
- Скриншота нет: ответ API, не экран.

### MINOR-2 (наблюдение, не дефект). Скрепка без провайдера
- На стенде нет выбранного провайдера, баннер «No provider selected». По коду `canAttach = thread === 'pm#1' && !noProvider`, вложения в этом состоянии выключены; клик по скрепке (shots/02) ничего не делает. Видна ли скрепка «неактивной», на снимке сказать трудно — она выглядит так же, как обычная. Рекомендую проверить внешний вид отключённого состояния.

## Ограничения проверки (почему FAIL)
- Инструменты `browser` не выбирают файл в диалоге, не делают drag-and-drop файла и не вставляют из буфера; JS на странице выполнить нельзя.
- На стенде (dry-run) нет провайдера, и скрепка выключена.
- Поэтому интерфейсные сценарии 1–5, ошибки лимитов в UI и подсветка зоны не пройдены. Их надо пройти человеку или QA с возможностью загрузки файлов (на стенде с выбранным провайдером).

## Проверено руками
- 1 устройство: десктоп 1440×900, DPR 2, онлайн, светлая тема.
- Экраны: главная, офис, вкладка «Chat»; тапы: открыть офис, вкладка «Chat», скрепка, клик по миниатюре; перезагрузка страницы (`open`) с проверкой истории.
- Серверная часть скриптами (curl и ws): загрузка png и txt, 21 МБ, ровно 20 МБ, 11 файлов, удаление неотправленного и отправленного, GET картинки, отправка с текстом и вложениями и только с вложением.
- Мобильные и тёмная тема не проверялись.

## Консоль и сеть (сводка)
- Консоль: 2 ошибки 403 на шрифты sora/inter (файлы из `node_modules` основного репозитория вне корня vite стенда — особенность стенда), предупреждения THREE.Material и WebGL. К вложениям не относятся.
- Падений запросов вложений нет, `get_errors` исключений не показал.
