# Доступ QA к штатному интерфейсу — T-784

Проверено 02.11.2026. Причина T-783 — неизвестный адрес и неверная предпосылка о необходимости выбрать окно Electron. Ошибка доставки `open` не обнаружена. Визуальная приёмка рейла остаётся отдельной работой QA.

## Доказательства доставки

- В сохранённой конфигурации офиса `office/offices/o-2.json` роль `qa` подписана на `mcp: ["browser"]`, инструменты Read/Write/Edit/Glob/Grep/Bash/TodoWrite, `permissionMode: auto`, `allowLocalBinding: true`. Явной сохранённой записи browser в каталоге нет: `mcpCatalog()` дополняет его встроенными серверами. Это штатное поведение, не потерянная настройка.
- Встроенная запись в `src/server/mcp.ts` задаёт `tools/browser/server.mjs`, `alwaysLoad: true`, `QA_ALLOWED_ORIGIN` через окружение. Локальные адреса разрешены самим browser. `agents.ts:3556–3560` передаёт browser отдельно от обычных инструментов роли. `providers/codex-tools.ts:143–177` получает `tools/list`, добавляет инструменты MCP независимо от списка Bash/Read роли; `providers/codex.ts:260–271` передаёт их как dynamicTools. `permissions.ts:198` классифицирует browser как safe.
- Проверена именно сессия T-783 `codex:01a19ae7-fe5a-7061-9c7d-bd9b0d7f2e8f`: файл `office/codex-runtime/sessions/2026/11/02/rollout-2026-11-02T09-17-37-01a19ae7-fe5a-7061-9c7d-bd9b0d7f2e8f.jsonl`, ordinal 2, `additional_tools`. В описании functions.exec доставлены все 15 browser-инструментов, включая `office_cda4949a3a4f_mcp__browser__open` с обязательным `url` и необязательным `waitUntil`. Ordinal 19 подтверждает реальный успешный вызов `office_050dbdfea2d1_mcp__browser__get_state({})`. Вызовов `open` в этой сессии нет. QA в собственном отчёте также признаёт наличие `open`, но останавливается из-за отсутствия адреса/выбора окна.
- Установленный `/Applications/AI Office.app/Contents/Resources/tools/browser/server.mjs` проверен отдельным MCP initialize + tools/list, без открытия страницы: 15 инструментов, первый — `open`, схема `url: string`, `waitUntil: load | domcontentloaded | networkidle`. В установленном файле регистрация `open` найдена на строке 31538, в исходнике — tools/browser/server.mjs:673; исходный обработчик вызывает `page.goto(target, ...)`. Подключение к Electron ему не требуется: browser управляет собственной страницей Chromium.

## Точный адрес и следующая проверка

Адрес штатного приложения: **http://127.0.0.1:50954/**.

Основания, без угадывания и сканирования:

- `~/Library/Application Support/AI Office/port.json`: `{"port":50954}`; desktop/paths.js:55 описывает этот файл как сохранённый порт.
- `~/Library/Logs/AI Office/server.log`: запуск 2026-11-01T21:19:37.275Z, порт 50954, сообщение «откройте http://localhost:50954».
- `~/Library/Logs/AI Office/main.log`: запуск 0.14.0-beta.21 в 21:19:36.687Z и сообщения веб-страницы 21:20:14 с URL `http://127.0.0.1:50954/assets/index-DYXLwzTL.js`. Это свидетельство загрузки UI при штатном запуске; текущую HTTP-доступность оно не доказывает.
- desktop/main.js:150 загружает `http://127.0.0.1:${port}/`.

В следующей обычной задаче роли QA найти инструмент по имени/описанию `mcp__browser__open` и выполнить:

```js
const инструмент = ALL_TOOLS.find(пункт => /mcp__browser__open$/.test(пункт.name));
if (!инструмент) throw new Error('В этой сессии не доставлен browser open');
text(await tools[инструмент.name]({
  url: 'http://127.0.0.1:50954/',
  waitUntil: 'domcontentloaded',
}));
```

Имя в T-783 — `office_cda4949a3a4f_mcp__browser__open`; в новом каталоге искать по суффиксу. Сохранить фактические status/url/title ответа. Затем вызвать `mcp__browser__get_state({})`. `app: null` означает отсутствие `window.__QA_STATE__`, а не отсутствие интерфейса: оценивается вместе с URL/ответом open. Не требовать выбора вкладки Electron. Для нужного офиса использовать обычную навигацию UI, не менять бюджеты/провайдеры. Перед применением инструкции сверить port.json, если приложение перезапускалось.

## Единственная оставшаяся возможность и граница результата

**Не хватает выполнения `browser.open` к указанному адресу в обычной QA-сессии с подключённым browser.** Нынешняя backend-сессия этого сервера не имеет; вызванный через ask_colleague QA в режиме ответа также проверил ALL_TOOLS и получил пустой список browser, поэтому выполнить навигацию не смог. Это не каталог рабочей сессии T-783 и не свидетельство поломки её доставки.

Адресная попытка HTTP из разрешённого Bash выполнена к одному установленному адресу: curl завершился кодом 7; Node http.get уточнил причину: `connect EPERM 127.0.0.1:50954 - Local (0.0.0.0:0)`, `syscall: connect`. sandbox_status подтверждает разрешённые хосты localhost/127.0.0.1, но эта проверка всё равно ограничена песочницей. Это не HTTP-отказ приложения и не доказательство остановленного сервера. Просмотр процессов тоже запрещён (`ps: Operation not permitted`); после отказа проверен sandbox_status. Ограничения не обходились.

Минимальное исправление — эта адресная инструкция вместо предпосылки о подключении к окну. Проверены фактический каталог T-783, установленный tools/list и схема open; оснований менять код/настройки нет. **Текущий HTTP 200 и доступность UI не подтверждены. Восстановление доступа до успешного open не объявляется.** Новая рабочая QA-сессия должна выполнить один указанный вызов; запрос владельцу, новый стенд, сборка, установка или перезапуск для этого не обоснованы.

Ветка T-783 и живые данные не менялись, визуальная приёмка не выполнялась. Этот документ не заменяет отчёт по строкам, шкалам и подсказкам рейла.
