# T-368. Ресёрч: замена Figma с компонентами и автолейаутом для агентов

Продолжение [T-364](../T-364/research.md). Там выбран HTML на токенах, а холст оставлен «если владелец захочет»; Penpot назван кандидатом на пробную задачу. Теперь владелец хочет именно холст: агенты создают компоненты, варианты, стили, переменные и автолейаут, а владелец смотрит и комментирует.

Метки достоверности: **[П]** — проверено по странице документации, README или типам Plugin API (страницу открывал и читал); **[О]** — взято из описаний, поисковой выдачи или статей, первоисточник не открывал. Исходники MCP-серверов не клонировал (по условию ничего не ставим), состав инструментов брал из README и документации. Замеров расхода токенов нет нигде — только оценка по формату ответа. Документ сведён из первого прохода и трёх проверок (verify, rework, verify 2) 2026-10-06; всё непроверенное собрано в конце, в разделе «Открытые вопросы — проверяет пилот».

## Кандидаты

### 1. Penpot + официальный MCP (`@penpot/mcp`)
- Холст: веб-редактор Penpot (облако или свой Docker), комментарии, режим «поделиться» с правом комментировать без аккаунта [О].
- MCP: пять инструментов — `execute_code` (агент пишет JS под Plugin API и он исполняется в открытой вкладке редактора), `high_level_overview`, `penpot_api_info`, `export_shape`, `import_image` [П, help.penpot.app/mcp]. Подключение: удалённый (хостинг Penpot, ключ MCP из настроек аккаунта) или локальный `npx @penpot/mcp@stable`; локально HTTP `localhost:4401/mcp`, плагин по WebSocket `4402` [П]. Node 22 проверен, 20 «должен работать»; пометки «бета» на странице нет [П].
- Ограничения удалённого режима [П, справка MCP]: нет `import_image` с локальных путей, `export_shape` урезан. Лимиты удалённого сервера на странице не описаны (см. «Открытые вопросы»). Для обоих режимов: нужна открытая и активная вкладка Penpot, одна MCP-вкладка за раз, запись идёт на текущую страницу, нужна сильная модель с vision (VLM).
- Репозиторий `penpot/penpot-mcp` заархивирован 2026-02-03, код влит в основной репозиторий `penpot/penpot`, каталог `mcp`, лицензия MPL-2.0 [П].
- Что может — по публичным типам Plugin API (`plugins/libs/plugin-types/index.d.ts`, ветка develop) [П]; сама страница справки MCP компоненты, варианты, flex и комментарии как поддержанные не перечисляет:
  - компоненты и слои, группы;
  - варианты: `VariantContainer`, `transformInVariant()`, `addVariant()`;
  - автолейаут: `Board.addFlexLayout()` → `FlexLayout`;
  - страницы: `Context.createPage()`;
  - токены: `Library.tokens: TokenCatalog`, создание — `TokenCatalog.addSet({name, active})` и `addToken(...)`, у набора есть свой `addSet`;
  - комментарии: запись — `addCommentThread()`, чтение — `findCommentThreads(criteria)`.
  Токены в формате W3C DTCG, начиная с Penpot 2.14, доступны через Plugins API [О]. То, что эти методы **работают на деле**, ещё не проверено (см. «Открытые вопросы»).
- Расход: нет выгрузки деревьев, схем всего пять. Агент сам решает, что вернуть из `execute_code`, то есть может запросить один узел без поддерева — самое важное против проблемы T-368. Но «меньше расход» — довод разработчиков, независимых замеров нет [П: в статье прямо «design rationale, not a measured result»]. Пакетность: в одном `execute_code` можно создать хоть весь блок за один вызов.
- Хранение: `.penpot` — ZIP с JSON и бинарными файлами, в git кладётся, но дифом не читается [О]. Можно экспортировать как zip с SVG и JSON [О].
- Импорт Figma: плагин Penpot Exporter в Figma выгружает `.penpot` с компонентами; качество неполное [О]. Наш макет мелкий — проще перерисовать.
- Лицензия и цена: MPL-2.0; тариф Penpot Cloud «Professional» бесплатный — без лимита на файлы и команды, «без ограничений инструментов»; платный Unlimited — $7/редактор/мес (хранение и история файлов) [П, penpot.app/pricing]. Проект живой, релизы регулярные [О].

### 2. Penpot + сторонний MCP (`ancrz/penpot-mcp-server`)
- 68 инструментов: проекты, файлы, чтение дерева (`get_shape_tree`, `get_shape_details`, `get_shape_css`, `search_shapes`), создание (`create_frame`, `create_text`…), правка (`set_layout`, `set_fill`…, 12 инструментов правки формы), токены, комментарии (6: создать, ответить, закрыть…), снимки, экспорт PNG/SVG [П, README]. Группа «Components & Tokens» — 4 инструмента, это только чтение токенов и библиотек; создания компонентов и вариантов не видно [П].
- Работает через RPC-API бэкенда и прямое чтение БД: 66 из 68 инструментов обходятся без браузерной вкладки [П, README]. Но рассчитан на **self-hosted** Penpot; с облачным design.penpot.app он, вероятно, не заработает [вывод].
- Минусы: 11 звёзд, 7 коммитов, Apache-2.0; схемы 68 инструментов съедят контекст при каждом вызове — та же болезнь, что у figma-bridge [П/вывод].
- Комментарии агенту доступны и через официальный MCP (`findCommentThreads`, `addCommentThread`), поэтому `ancrz` нужен только если на практике упрёмся в комментарии и будем на self-hosted. Не основной.

### 3. Pencil (pencil.dev → www.pen.dev)
Сайт теперь pen.dev (pencil.dev редиректит), «CLI» в доках называется `pen`. doc.pencil.dev не резолвится, docs.pencil.dev даёт только обзор.
- Что подтверждено [П, pen.dev, docs.pencil.dev]: «agentic canvas», векторный редактор в IDE (Cursor/VS Code), десктоп-приложении и headless CLI; формат `.pen` — открытый JSON, лежит в репозитории рядом с кодом; компоненты (`reusable: true`, экземпляры `ref` с переопределением по пути, слоты), flex-раскладка (`layout`, `justifyContent`, `alignItems`, `gap`, `padding`, `fit_content`), переменные цвета и чисел с темами (day/night — ровно наш случай); импорт Figma, экспорт HTML/CSS/Tailwind, PDF, PNG, JPEG, WEBP; поддерживаются Claude, Codex, Gemini и др. Отдельных страниц в списке типов нет (холст бесконечный); вариантов как сущности нет — вариант делается отдельным компонентом [вывод].
- MCP по stdio к запущенному приложению через локальный сокет. CLI: `pen --in a.pen --out b.pen --prompt "…"`, `pen interactive` — оболочка для прямых вызовов инструментов; нужен Node 22.19+; вход `pen login` или `PEN_CLI_KEY` для CI, то есть **для работы нужна учётная запись** [П].
- Состав инструментов расходится между источниками: документация CLI называет `get_style`, `read_skill`, `get_app_state`, `execute`, `browser` (только десктоп), `spawn_agents` (флаг) [П]; сторонние описания навыков — `get_editor_state`, `batch_get`, `batch_design` (вставка, копирование, обновление, замена, перенос, удаление; не больше 25 операций за вызов) [О]. Возможно, версии отличаются; формат и глубина ответов не проверены.
- Не подтверждено [О]: цена и бесплатность (страницы цен нет; поиск даёт другой продукт с таким же названием — маркетинговый сервис Pencil от Brandtech), лицензия приложения (вероятно, закрытое; проект из a16z speedrun), комментирование владельцем (в документации нет; есть «prompt»-блоки на холсте, но это команды агенту), варианты, расход токенов. Если бесплатность только на время раннего доступа — риск для требования «только бесплатно».
- Импорт Figma: вставка из буфера Figma сохраняет слои и автолейаут [О].

### 4. Framer
- Редактор сайтов с холстом; бесплатный тариф есть (неограниченное число проектов, публикация на поддомене, ≤1000 страниц, 10 коллекций CMS, 100 МБ трафика в месяц) [О]. Сторонние MCP-серверы оборачивают Server API для сайтов и CMS: страницы, компоненты, обновление записей, публикация [О].
- Это инструмент для сайтов, не для UI приложения: компоненты на React-коде, облако, в git не лежит. Страница Framer с описанием MCP ничего конкретного не дала [П].
- Вывод: не подходит.

### 5. Excalidraw (+ MCP)
- Официальный `excalidraw-mcp` [П, README]: лицензия MIT, MCP App Server, рисует схемы в чате (`https://mcp.excalidraw.com` или локально); сохранение в файл в README не описано. Сторонний `yctimlin/mcp_excalidraw` — 26 инструментов [О]. Формат `.excalidraw` — JSON.
- Компонентов, вариантов, токенов, автолейаута нет — это доска для схем. Не замена Figma.

### 6. tldraw (+ agent starter kit)
- SDK холста для встраивания; agent starter kit (MIT) строит агента, управляющего холстом [О]. Лицензия SDK своя: использовать можно с водяным знаком «Made with tldraw»; ключ без знака платный (старт около $6000 в год, 100 дней триала), «hobby» — на усмотрение авторов [О].
- Встроить можно, но это не дизайн-инструмент: компонентов, токенов и автолейаута из коробки нет. Не подходит.

### 7. Storybook + MCP (code-first)
- Storybook 10.x: `npx storybook add @storybook/addon-mcp`, сервер на `localhost:6006/mcp` [П, документация, функция в preview — API может меняться]. Три набора инструментов:
  - *dev*: `stories-changed`, `get-storybook-story-instructions`, `stories-preview`, `stories-find-by-component`, `review-create`;
  - *docs*: `docs-show`, `docs-show-story`, `docs-list` (нужен манифест компонентов; React, Angular, Vue);
  - *testing*: `test-run` с проверкой доступности.
  Агент может создавать и править истории.
- Компоненты и варианты = истории (story) и свойства; токены — наш `tokens.css`; автолейаут — настоящий CSS flex. Холста нет; владелец смотрит собранную страницу Storybook, **комментировать не умеет** (в open-source Storybook нет). Что даёт `review-create` («подборка изменений на ревью»), не проверено; облачная часть ревью, скорее всего, платная [О]. Хранение — код в git. Лицензия MIT, проект очень живой [О].
- Это не макет «до кода», а уже код. Но как следующий шаг после макета (компонент `TaskGroup` в `kit.css` и истории состояний) полезен. Стенд `?kit=1` в проекте уже есть и играет эту роль.

### 8. HTML на токенах проекта (путь из T-364, как база сравнения)
- Файл на экран, PNG через `tools/browser`; в git, нулевой расход на инструмент. Комментирование — только в чате/«Нужны правки». Отдельным кандидатом не считаем, держим как точку отсчёта.

## Рекомендация

**Основной кандидат: Penpot + официальный `@penpot/mcp`.** Единственный полноценный бесплатный открытый аналог Figma с компонентами, вариантами, токенами, flex-лейаутом, страницами и комментариями владельца в браузере; всё это есть в публичных типах Plugin API. Решает причину падения: агент пишет скрипт и сам решает, сколько данных вернуть, а не получает поддерево узлов. Слабое место: зависимость от открытой вкладки (как у нашего моста) и отсутствие измеренного расхода, поэтому нужен пилот.

**Запасной: Pencil**, если владелец готов смириться с закрытым приложением и аккаунтом: `.pen` в git, чистый JSON, темы переменных. Комментариев не нашёл, бесплатность не подтверждена — поэтому второй, а не первый.

**Откат: HTML на токенах из T-364.**

Сторонний `ancrz` MCP — только если упрёмся в комментарии и будем на self-hosted Penpot; Storybook — следующий слой после макета, не замена. Framer, Excalidraw, tldraw не подходят.

## План пилота (Penpot)

1. **Поставить.** Вариант А: аккаунт на design.penpot.app (бесплатно), ключ MCP из настроек, вписать удалённый сервер в MCP-конфиг роли «Дизайн». Вариант Б: локально `npx @penpot/mcp@stable`, Node 22 (20 «должен работать»). Начать с А; если упрёмся в ограничения удалённого режима (`export_shape`, лимиты), перейти на Б.
2. **Подготовка.** Один файл «AI Office UI», страница `Токены`: создать токены из `src/web/styles/tokens.css` (цвета day/night как две темы, отступы `--space-1..4`, радиусы, `--fs-small/row/body`) одним `execute_code` через `TokenCatalog.addSet`/`addToken`. Без рисования сотен узлов. Запасной вариант, если создание токенов не заработает: завести токены вручную в UI или обычными стилями/локальной библиотекой цветов.
3. **Малый макет.** Шапка группы фичи (`.task-group-head`, ряд A) и подшапка (ряд B) из `docs/design/T-349/spec.md` §3: компонент `TaskGroupHead` с вариантами статуса (active, done, planned, ждёт согласия) и свёрнуто/развёрнуто, автолейаут горизонтальный (`addFlexLayout`), шеврон + бейдж `F-N` + название с обрезкой + чипы + справа прогресс и счётчики. Затем подшапка с кнопками «Запустить»/«Снять». Только токены, без новых цветов.
4. **Замер.** Для сравнения взять три прошлых макета: T-347, T-350, T-357 (в Figma, входные токены запуска и число вызовов уже известны). На пилоте записать: число вызовов MCP, входные токены запуска (счётчик офиса), размер самого большого ответа, число правок после первого прохода, время. Критерий успеха: запуск стабильно ниже предохранителя в 2 млн (цель — в 4–5 раз ниже, то есть ≤ 500 тыс.), в Penpot создан компонент с вариантами и автолейаутом без ручной доводки хотя бы в 80% свойств.
5. **Правила для агента.** В бриф роли: не запрашивать всё дерево; сначала `high_level_overview` один раз, дальше `execute_code` с возвратом только id и нужных свойств; создание пачкой (весь блок за один вызов); скриншот только `export_shape` одного узла.
6. **Проверка владельцем.** Дать ссылку на страницу с правом комментирования; проверить, что агент читает комментарии владельца через `findCommentThreads` и отвечает через `addCommentThread`. Если не работает — ответ в чате (`ancrz` только на self-hosted).
7. **Решение.** По итогам записать в журнал офиса расход и вердикт; если пилот не прошёл — возвращаемся к HTML из T-364, Pencil проверяем следующим.

## Допущения

- Владельцу достаточно холста Penpot с комментариями; миграцию уже готовых макетов Figma не делаем.
- Наличие методов Plugin API (flex, варианты, страницы, токены, комментарии) принято по публичным типам; их работу на практике проверяет пилот.

## Открытые вопросы — проверяет пилот

Это осознанно оставленные пробелы, а не недоделка: ресёрч без установки их закрыть не может. Всё, что не проверено, собрано здесь.

**Penpot**
- Расход токенов: реальный расход на операцию не измерен ни у одного кандидата; довод «меньше, чем у figma-bridge» — рассуждение разработчиков, не замер [О]. Шаг 4 пилота.
- Лимиты удалённого MCP Penpot: страницы с лимитами (число запросов, размеры ответов, время сессии) нет; про бесплатный тариф облака сказано «без ограничений инструментов», но именно про MCP — ничего [О]. Шаги 1 и 4; запасной путь — локальный `@penpot/mcp` или свой Docker.
- Работа flex и вариантов на практике: `addFlexLayout()`, `transformInVariant()`, `addVariant()` есть в типах, но что они дают по полноте свойств и без ручной доводки — не проверено [О]. Шаг 3 пилота; проверять до того, как переходить на Penpot окончательно.
- Создание токенов на деле: `TokenCatalog.addSet`/`addToken` есть в типах, работоспособность и соответствие DTCG — не проверены [О]. Шаг 2 пилота, проверять первым.
- Чтение и запись комментариев на деле: `findCommentThreads`/`addCommentThread` есть в типах, поведение с комментариями владельца без аккаунта — не проверено [О]. Шаг 6.
- Импорт из Figma: качество плагина Penpot Exporter (компоненты, автолейаут, варианты) — по описаниям, не пробовали [О]. Не блокирует: макет мелкий, проще перерисовать.
- Связка `ancrz` с облачным Penpot: вероятно, не работает (рассчитан на self-hosted), не проверено [О].

**Pencil [О]** — всё ниже не подтверждено:
- [О] цена и бесплатность после раннего доступа, лицензия приложения (закрытое или нет);
- [О] вход без аккаунта (в CLI нужен `pen login` или `PEN_CLI_KEY`);
- [О] комментирование владельцем;
- [О] варианты (по документации нет, вариант = отдельный компонент);
- [О] реальный состав инструментов: `execute`/`get_app_state` против `batch_get`/`batch_design` — смотреть `tools/list` живого сервера;
- [О] глубина и размер ответов `batch_get`, расход токенов;
- [О] качество импорта Figma из буфера.
Если дело дойдёт до Pencil — проверять в таком порядке: цена, вход без аккаунта, глубина `batch_get`.
