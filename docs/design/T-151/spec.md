# Страница настроек агента: разделы и автосохранение (T-151)

Статус: макет и спека, код не менялся. Макеты — в Figma, файл «Office», страница «Office», группа «T-151 · …» (список кадров в конце).

## 1. Что сейчас и почему владелец путается

«Страница агента» — правая панель окна «Команда», вкладка «В офисе». Собирается в `src/web/TeamWindow.tsx:295-324` из четырёх кусков, которые лежат друг под другом одной длинной колонкой:

1. `EmployeeCard` (`src/web/EmployeeCard.tsx`) — шапка, стол, личный режим доступа, расходы, «Уволить».
2. `PackageLine` (`TeamWindow.tsx:345`) — из какого пакета собран и кнопка «Обновить».
3. `RoleReport` (`src/web/RoleReport.tsx`) — табель роли.
4. `RoleEditor` (`src/web/RoleEditor.tsx`) — форма роли на 12 полей, экспорт в пакет, архив/удаление/отвязка. Единственное место с кнопкой «Сохранить» (`RoleEditor.tsx:360-364`).

Причины путаницы, найденные в коде:

- **Половина применяется сразу, половина по кнопке.** Имя сотрудника (`AgentName.tsx:22`, по потере фокуса) и личный режим доступа (`EmployeeCard.tsx:77`) уходят на сервер сразу, всё из `RoleEditor` — только по «Сохранить». Внешне поля одинаковы, поэтому человек не знает, что из изменённого уже применилось.
- **Кнопка внизу длинной формы.** До неё нужно доскроллить через табель, расходы и 12 полей; она не закреплена.
- **Табель, расходы и строка пакета стоят над формой** и сдвигают её вниз: то, ради чего пришли, — за экраном.
- **Причины отказа спрятаны в `title`**: у заблокированных «Убрать в архив», «Удалить насовсем», «Уволить» причина видна только при наведении.
- **Единственная подсказка про момент применения** — `role.note` («Изменения применяются к новым сессиям…») — висит в начале формы и неверна для имени, внешности и режима доступа, которые действуют сразу.
- Два одинаковых по смыслу селекта режима доступа («Разрешения» у роли и «Личный режим доступа» у сотрудника) стоят в разных концах страницы.

Вне рамок задачи, но замечено:

- Ветка «создание роли» (`role: null`, кнопка `role.create`, `RoleEditor.tsx:56,100,362`) из интерфейса не достижима — `RoleEditor` вызывается только с ролью (`TeamWindow.tsx:316`). Автосохранение к ней не применяется (сущности ещё нет, у создания должна быть явная кнопка). В спеку она не входит.
- `src/web/AgentDrawer.tsx:130-157` дублирует селект личного режима доступа. Поведение там уже «сразу» и менять его не нужно; при желании селект можно заменить бейджем и ссылкой «роль, модель, права →» (она уже есть).
- Поля `emoji` и `color` есть в `RoleEditable`, но в форме их нет — не трогаем.

## 2. Принятая структура

Рекомендацию менеджера принимаю почти целиком: шапка закреплена, под ней вкладки, автосохранение, кнопки «Сохранить» нет. Отличия и обоснования:

| Решение | Почему |
|---|---|
| **5 вкладок**, а не 4 | Расходы и табель читают, а не настраивают — им нужна своя вкладка «Результаты», иначе они снова встанут над формой. Пакет и инструкция — одна тема, поэтому «Пакет» отдельной вкладкой не нужен. |
| Вкладки — **подчёркнутые**, не пилюли `.seg` | Пилюля `.seg` уже занята вкладками верхнего уровня окна («В офисе» / «Маркет»). Две одинаковые полосы друг под другом читаются как один уровень. Подчёркнутая вкладка — новая деталь кита из тех же токенов (см. §7). |
| **Занятость не блокирует правку** | Сервер уже так устроен: сессия работающего агента держит снимок роли (`state.ts` `updateRole`, «снимок… обязан остаться прежним»), правка ляжет в следующую задачу. Блокировать было бы хуже: владелец правит бриф как раз глядя на то, что агент делает сейчас. Вместо блокировки — баннер и пометки «Со следующей задачи» (§5). |
| Текстовые поля — **не все по таймеру** | Число и путь по таймеру сохранять нельзя: ввод «12» пройдёт через «1» и сохранит лимит в один ход. Таймер только у длинных текстов (§4). |
| Подтверждения — только там, где шаг **нельзя откатить одним движением** | Разбор в §6. |

Шапка (закреплена над вкладками, не скроллится): аватар `lg`, имя сотрудника (правится по клику, как сейчас — `AgentName`), подстрока «роль · провайдер · модель», чип состояния (`agent.state.*`), кнопка «+ Ещё один» (`team.hire`, как сейчас), справа — **индикатор сохранения** (§4.2). Строка пакета переезжает в подстроку шапки («@office/backend 1.4») и в бейдж «Есть обновление» на вкладке «Инструкция».

Вкладка запоминается на время открытого окна: при переходе к другому сотруднику остаётся та же вкладка — так удобно сравнивать, например, модели у разных людей. По умолчанию — «Профиль». Клавиатура: `role="tablist"`, стрелки влево/вправо переключают, Tab уходит в панель.

## 4. Сохранение

### 4.1. Правила по типам полей

Общее: у каждого поля — **своя локальная копия** значения; на сервер уходит патч только с изменившимися полями; кнопки «Сохранить» нет нигде.

| Тип | Поля | Когда уходит на сервер | Проверка до отправки | Ошибка |
|---|---|---|---|---|
| **Мгновенные** — селект, чекбокс, плитка внешности | провайдер+модель, модель (select), режим доступа роли, личный режим, «своя ветка», внешность, каждый MCP-сервер, каждое умение | сразу при выборе | не нужна (значения из списка) | значение **откатывается** к серверному, под полем «Не применилось — вернули прежнее» + причина сервера; общий индикатор — «Ошибка сохранения» |
| **Короткий текст** | имя сотрудника, название роли | по потере фокуса или Enter; Esc — отмена и возврат старого текста | название не пустое и ≤ 60 (`ROLE_TITLE_LIMIT`); имя ≤ 40 (`MAX_AGENT_NAME`); пустое имя допустимо — снимает имя | текст **остаётся** (пользователь не теряет набранное), поле красное, причина под ним |
| **Число** | лимит ходов | по потере фокуса или Enter | пусто или целое 1–1000 (`parseTaskMaxTurns`) | как у короткого текста; невалидное на сервер не уходит |
| **Путь** | репозиторий роли | по потере фокуса или Enter; пустое — законно | серверная проверка (git, `checkRolePatch`) идёт асинхронно | пока идёт — «Проверяю репозиторий…» со спиннером; отказ — под полем, значение остаётся |
| **Длинный текст** | инструкция, приписка | через **800 мс** после последнего нажатия, а также по потере фокуса, при переключении вкладки/сотрудника и закрытии окна | пустой текст **по таймеру не сохраняется**, только по потере фокуса (чтобы «выделить всё и заменить» не сохранило пустоту) | текст остаётся, ошибка под полем |
| **Мульти-выбор** | MCP, умения | каждый клик — сразу; быстрые клики склеиваются в один патч с полным списком | — | список откатывается к серверному |

Почему так, а не «всё по 800 мс»: число и путь проходят через заведомо неверные промежуточные значения («1» → «12», «/Us» → «/Users/…»), и путь каждый раз гонял бы проверку git.

Механика (для исполнителя, контракт `types.ts` не меняется):

1. **Очередь на роль.** В полёте не больше одной команды `update_role` на роль. Пока она не ответила (`role.saved` / `role.error` с `op: 'update'` и тем же `roleId`), новые правки копятся и уходят одним патчем следом. Ответы приходят по порядку, поэтому в ответе не нужен номер запроса.
2. **Провайдер и модель — один патч.** Как и сейчас (`RoleEditor.tsx:209-212`): смена провайдера без модели сервер всё равно сбросит модель на умолчание, а форма должна показать то же самое сразу.
3. **Ответ забирает один хук.** Слот `roleFeedback` в сторе одиночный и очищается первым, кто его прочитал (`RoleEditor.tsx:87-98`). Автосохранение владеет им целиком — иначе ответ исчезнет между полями.
4. **Пришедшее с сервера не затирает набираемое.** Событие `roles`/`instance` обновляет только те поля, которые пользователь сейчас не правит и которые не ждут ответа.
5. **Нет связи.** `store.updateRole` при закрытом сокете молча ничего не делает (`socket?.send`). Автосохранение обязано это проверять: нет сокета — состояние «Нет связи», правка не считается сохранённой.
6. **Имя сотрудника и личный режим не возвращают ответ** (`agent_name` пишет отказ текстом в чат офиса, `agent_permission` молчит). Для честного индикатора нужен ответ. Прошу бэкенд ответить на `agent_name` событием ошибки поля (или дать этим двум командам `role.saved`/`role.error`-подобный ответ). Пока ответа нет — считать сохранённым, когда пришло событие `instance` с новым значением, и ошибкой — если оно не пришло за 3 секунды. Это единственная просьба к контракту.
7. **Сброс к «как при открытии».** Автосохранение стирает прежний текст инструкции без шанса передумать, поэтому для длинных текстов клиент помнит значение на момент открытия страницы и даёт ссылку «Вернуть как было при открытии» под полем (показывается, когда текст отличается). Это только клиентская память, сервер не хранит истории.

### 4.2. Индикатор состояния

Один на всю страницу, в правой части шапки (закреплён, всегда на виду, какая бы вкладка ни была открыта). Высота 20, кегль `--fs-small`, `role="status"` с `aria-live="polite"`; ошибка — `aria-live="assertive"`.

| Состояние | Вид | Когда |
|---|---|---|
| **Сохранено** | галочка `--ok-ink` + «Все изменения сохранены», цвет `--ink-3`; первые 2 секунды после записи текст «Сохранено» цветом `--ok-ink` | ничего не ждёт ответа |
| **Есть несохранённое** | точка `--warn` + «Не сохранено» | поле изменено, но ещё не отправлено (набор в длинном поле до таймера; короткий текст, число и путь до выхода из поля). Подсказка по наведению — когда сохранится |
| **Сохраняется** | `.spinner` + «Сохраняется…» | команда отправлена, ответа нет. Показывается не меньше 400 мс — иначе быстрое сохранение мигает |
| **Ошибка** | иконка `alert-triangle` `--danger` + «Ошибка сохранения» + кнопка `mini` «Повторить» | сервер отказал или нет связи. «Повторить» отправляет тот же патч. Автоповторов нет: причина обычно в значении, а не в сети |
| **Нет связи** | то же, что ошибка, текст «Нет связи с офисом. Правки не сохранены» | сокет закрыт |

Локально, у поля: после успешной записи справа от подписи на 1,5 секунды появляется «Сохранено ✓» (`--ok-ink`, `aria-hidden` — за озвучку отвечает общий индикатор). При ошибке — красная рамка поля (`--danger`) и текст причины под ним (`.hint.error`, как сейчас). На вкладке с ошибкой — красная точка справа от названия; так ошибку видно, даже если она на соседней вкладке.

**Уход со страницы.** Переключение вкладки, выбор другого сотрудника и закрытие окна сначала **досылают** всё, что ждёт (таймер длинного текста не должен «терять» последние секунды набора). Если в момент закрытия есть ошибка — окно не закрывается молча, а спрашивает: «Есть несохранённые правки: {поля}. Закрыть без сохранения?» — «Остаться» / «Закрыть без сохранения».

## 5. Агент занят задачей

«Занят» — у сотрудника есть `currentTaskId` (тот же признак, что блокирует «Уволить», `EmployeeCard.tsx:39`).

Что верно про применение (проверено по коду):

- **Сразу, даже в середине задачи:** режим доступа (роль и личный) — он вычисляется на каждый вызов инструмента (`agents.ts:585`, `effectiveMode(inst, role, office)`), а также имя, название роли и внешность.
- **Со следующей задачи:** модель, провайдер, инструкция, приписка, внешние инструменты, лимит ходов — сессия работающего агента держит снимок роли (`state.ts` `updateRole`); репозиторий — фиксируется на задаче при старте (`task.repoDir`); «своя ветка» — решается при старте задачи.

Поведение страницы:

1. **Правка не блокируется.** Все поля доступны, автосохранение работает как обычно.
2. **Баннер** над вкладками (класс `.form-banner`, плёнка `--film`, не красный): «Сейчас работает над задачей {task}. Модель, инструкция, инструменты, лимит ходов, репозиторий и ветка применятся со следующей задачи. Режим доступа, имя и внешность — сразу.» Со ссылкой-идентификатором задачи (открывает карточку). Вместо статичного `role.note`, который убираем.
3. **Пометки у полей**, пока агент занят: чип `.chip` «Со следующей задачи» рядом с подписью полей из второй группы и «Действует сразу» у режима доступа. Так владелец видит разницу там, где правит, а не только в баннере.
4. **Репозиторий, пока идёт задача:** под полем добавляется строка «Текущая задача остаётся в прежнем репозитории».
5. **Индикатор сохранения** для занятого агента не меняется: «Сохранено» означает «записано в роль», а не «уже действует» — эту разницу несут пометки из п. 3.
6. **Что по-прежнему заблокировано:** «Уволить» (причина видна текстом «Занят задачей {task} — сначала остановите или дождитесь», `employee.busyHint`), «Убрать в архив» (пока в роли есть сотрудник — `RoleEditor.tsx:139`).
7. Состояния `waiting_approval` и `paused` считаются занятыми, если есть текущая задача: у них та же особенность со снимком.

## 6. Опасные и дорогие настройки: нужно ли подтверждение

Критерий: подтверждение нужно, когда шаг **необратим** или **немедленно даёт агенту больше власти**, и его нельзя вернуть одним движением. Всё остальное — без модального шума: обратимо, применится к следующей задаче, а ошибка вернёт прежнее значение.

| Настройка | Подтверждение | Обоснование и вид |
|---|---|---|
| **Режим «Полный доступ» (`auto`)** у роли и у сотрудника | **Да, остаётся** | Действует сразу, даже посреди задачи: агент без вопросов удаляет файлы и пушит. Как сейчас — блок `.access-confirm` с `fullAccessWarning()` и кнопками «Отмена» / «Да, включить полный доступ». Значение не применяется и не показывается выбранным, пока не подтверждено. Обратно (на любой более строгий режим) — без подтверждения |
| **Своя ветка на задачу — выключить** | **Да, при выключении** (включение без подтверждения) | Без ветки агент правит общую рабочую копию: правки смешиваются с чужими и мешают слиянию других задач. Откатить одним переключением можно, но испорченную копию — нет. Инлайн-блок в стиле `.access-confirm` |
| **Отвязать от пакета** | **Да, остаётся** | Необратимо («Обратного пути нет», `role.detach.hint`): бриф превращается в обычный текст, обновления перестают приходить. Как сейчас |
| **Удалить насовсем** | **Да, добавить** (сейчас нет: `RoleEditor.tsx:416-421` шлёт `remove_role` сразу) | Необратимо: роль исчезает без следа. Инлайн-блок: «Удалить роль «{title}» насовсем? Вернуть её будет нельзя» — «Отмена» / «Удалить» |
| **Уволить** | **Да, добавить** (сейчас нет) | Сотрудник уходит из офиса, имя и личный режим доступа пропадают. Роль остаётся вакансией, нанять снова можно, но настройки сотрудника потеряны. Инлайн-блок |
| **Убрать в архив** | Нет | Обратимо кнопкой «Вернуть роль из архива»; сервер сам не даст архивировать роль с людьми или живыми задачами — причина видна текстом |
| **Репозиторий роли** | **Нет** | Обратим (вернуть путь), не влияет на идущую задачу (репозиторий зафиксирован на ней), а сервер проверяет путь до записи. Защита — поведение поля: сохраняется только по потере фокуса/Enter, показывает «Проверяю репозиторий…», под ним видно последствие («Ветка задачи, её diff и слияние идут туда же», `role.repo.hint`), при занятом агенте — строка про текущую задачу |
| **Провайдер** | Нет | Обратим; сервер сбрасывает модель на умолчание нового провайдера — страница сразу показывает новую модель и строку «Модель сброшена на {model}» |
| **Инструкция (`brief`)** | Нет подтверждения, но есть страховка | Автосохранение может затереть хорошую инструкцию. Защита — не сохранять пустое по таймеру и ссылка «Вернуть как было при открытии» (§4.1, п. 7) |
| **Внешние инструменты (MCP)** | Нет | Каталог серверов одобрен владельцем в «Настройки → Инструменты»; подписка роли обратима и вступает со следующей задачи. Выключенный в каталоге сервер остаётся в списке с пометкой «выключен в каталоге» |
| Модель, лимит ходов, умения, имя, название, внешность | Нет | Обратимо и безопасно |

**Отмена вместо подтверждения** там, где действие обратимо: после сохранения мгновенного поля индикатор не даёт «Отменить» — прежнее значение восстанавливается тем же селектом. Исключение — инструкция (§4.1, п. 7).

## 9. Критерии приёмки для реализации

1. Кнопки «Сохранить» нет ни на одной вкладке.
2. Изменение любого мгновенного поля видно на сервере без каких-либо дополнительных действий; индикатор проходит «Сохраняется…» → «Сохранено» → «Все изменения сохранены».
3. Набор в инструкции и закрытие окна через 300 мс не теряет текст.
4. Ввод лимита ходов «12» не отправляет «1».
5. Отказ сервера (занятое название, неверный путь репозитория) оставляет введённое значение, подсвечивает поле и переводит индикатор в «Ошибка сохранения» с рабочей кнопкой «Повторить».
6. У занятого агента поля доступны, виден баннер и пометки; «Уволить» заблокирован с видимой причиной.
7. «Полный доступ», выключение «своей ветки», «Отвязать», «Удалить», «Уволить» требуют подтверждения; остальное — нет.
8. Работа с клавиатуры: вкладки стрелками, Enter в коротком поле сохраняет, Esc отменяет.
9. `npm run typecheck` чист; словари ru/en содержат одинаковый набор ключей.
