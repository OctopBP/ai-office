# T-336. Скилы ui-self-check, ui-standards и правила ролей

## Что сделано
- `packages/@office/design/skills/ui-self-check/SKILL.md` — чек-лист A–G (токены, доступность, состояния, Нильсен, тексты, Figma, вёрстка); итог по каждому разделу — в отчёт.
- `packages/@office/design/skills/ui-standards/SKILL.md` — справочник: WCAG 2.2 AA в числах, эвристики, сетка, типографика, состояния, движение, десктоп.
- 17 правил §4 ресёрча T-329 — в приписки «## Правила офиса» брифов `design` (16 правил) и `frontend` (15), ru и en. Правило про деструктивные действия и Figma — только дизайнеру, про масштаб 200 % — только фронтенду; в брифе одна строка «пройди ui-self-check».
- Общий `RULES.md` не создан и не тронут (лимит 4000 знаков на все роли).

## Источники и лицензии
Тексты написаны заново по открытым стандартам (WCAG 2.2 — W3C, эвристики Нильсена — NN/g). Ничего не скопировано из наборов, в том числе из trevorgrogers/ux-designer-skills (нет LICENSE) и tommyjepsen/awesome-ux-skills. Заимствований из MIT/Apache нет, поэтому `THIRD_PARTY.md` не нужен; источник стандартов указан в шапке `ui-standards`.

## Ограничение
Для роли из пакета панель «Правила» читает приписку из состояния офиса (`briefExtra`), а не из файла брифа пакета. Правила из брифа пакета едут в промпт как часть брифа, но в панели не видны и не правятся инструментами менеджера. Чтобы их увидеть там, владелец может перенести блок в «Приписку к инструкции» роли.
