# Окно «Документы» — макет

Задача T-308. Библиотека документов офиса: три типа, markdown, история версий,
архив, поиск. Согласований нет — документ либо лежит в библиотеке, либо в архиве.
Документы пишут агенты и владелец; каждая правка — версия с автором.

Только текстовое описание на существующих токенах и деталях кита; ничего нового в
`tokens.css` и `kit.css` не вводится. Макет в Figma не делался: в этой задаче
макетом служит спека, раскладка целиком собирается из готовых классов.

## 1. Принципы

- Окно — **страница главной области** (`ShellPage`), как «Команда», «Расходы» и
  «Настройки». Не модалка: рейл и сегменты остаются под рукой.
- Раскладка «список слева — карточка справа» ровно как в «Команде»
  (`.team-window-body`, `.team-list-pane` 380 px, `.team-detail`).
- Офис остаётся визуализацией: окно показывает данные документов, логики в
  компонентах отрисовки нет; данные приходят от сервера, как и остальное.
- Владелец правит текст; агенты — через инструмент записи документа. Любая правка
  создаёт новую версию. Прямая правка поверх версий невозможна.

## 2. Вход в окно

- Новый пункт рейла **«Документы»** (`WINDOWS` в `Rail.tsx`), иконка `book`
  (есть в `icons.tsx`). Место: между «Расходами» и «Совещаниями», рядом с тем, что
  про знание офиса; пункт горит (`.rail-win.on`), пока страница открыта.
- В сторе — новое значение `RailView = 'docs'`; плашка клавиши — `D`
  (в `HOTKEY.docs`, обработчик в `App.tsx` + русская раскладка `В`). Если буква
  занята — решает разработчик, плашка берётся из `HOTKEY`.
- Бейдж у пункта не нужен. Свёрнутый рейл — иконка с подсказкой (`Tooltip`).
- Из других мест: ссылка на документ в карточке задачи (поле «Спека») и в
  ленте событий открывает окно сразу на нужном документе
  (`docsRequest = { id }` в сторе по образцу `teamRequest`).
- Новый офис: пункт есть всегда, окно открывается пустым (см. §10).
- Шапка (`ShellPage`): заголовок «Документы», справа действия:
  `[ + Новый документ ]` (`button.primary mini`), `Kbd` с `D`, `✕` (`button.sq ghost`).

## 3. Структура окна

```
┌ Документы ───────────────── [+ Новый документ]  D  ✕ ┐
│ [ Основа 4 | Документация 9 | Рабочие 3 ]   (seg)     │
├────────────────────────┬───────────────────────────────┤
│ 🔍 Поиск по документам │ Название документа            │
│ ▢ Показывать архив     │ [тип ▾] · правил Иван, 2 ч назад │
│ ───────────────────    │ [Править] [История] [⋯]       │
│ ▌Видение продукта      │ ───────────────────────────   │
│   Ради чего всё…       │  markdown                     │
│   backend · вчера      │                               │
│  Бренд                 │                               │
│   …                    │                               │
└────────────────────────┴───────────────────────────────┘
```

Корень — `.team-window-body` (flex), слева `.team-list-pane`, справа
`.team-detail`. Рамка и тело — `ShellPage` с `bodyClass="fixed"`.
Ниже 900 px ширины окна список и карточка не стоят рядом: показывается список,
по выбору — карточка с кнопкой «‹ Назад» (`button.ghost mini`).

## 4. Вкладки по типам

Первый уровень — сегмент `.seg.team-tabs` слева в шапке (приём окна «Команда»),
три вкладки, в каждой счётчик `.team-tab-count`:

| Вкладка | Что внутри | Подсказка под списком (`.team-group-hint muted small`) |
|---|---|---|
| **Основа** | видение, GDD, персонажи, бренд — то, что не меняется с каждой задачей | «Что офис строит и зачем. Агенты читают это перед работой.» |
| **Документация** | как устроено сейчас: архитектура, UX, дизайн-система | «Как всё устроено сейчас. Обновляется вместе с кодом.» |
| **Рабочие материалы** | спеки к задачам; после закрытия задачи уходят в архив | «Спеки к задачам. Закрыли задачу — спека уходит в архив.» |

- Название третьей вкладки в сегменте — «Рабочие» (коротко), полное — в заголовке
  подсказки и в тултипе.
- Активная вкладка запоминается в сторе на время сессии. При поиске вкладки
  остаются, но счётчики показывают число совпадений (см. §8).
- Архивные документы в счётчик не входят.

## 5. Список

Строка списка — `.team-role-row` (`.selected` у выбранной), двухстрочная:

1. **Название** (`--ink`, `--fs-md`, 500) и справа чип `.chip` с типом только в
   режиме поиска по всем вкладкам; у рабочих материалов — чип привязанной задачи
   `.chip` «T-308» (клик — открыть задачу, не выбирая документ).
2. **Описание** — одна строка, обрезка с многоточием, `--ink-3`, `--fs-small`
   (описание — первая строка/поле `description` документа; если пусто — первые
   80 символов текста).
3. **Кто и когда правил** — `--ink-4`, `--fs-small`: бейдж автора (`.agent-tag`
   для агента, для владельца — слово «Вы») · относительное время
   (`formatDayLabel`/`formatClock` из `dates.ts`). Если правок было несколько —
   «+2 автора» серым.

Сортировка: последняя правка сверху. У «Основы» — ручной порядок не нужен.
Группировки внутри вкладки нет; у рабочих материалов открытые задачи выше
закрытых не поднимаем — они и так в архиве после закрытия.

Состояния строки: обычная, hover (`--film`), выбранная (`--film-2` + `--hairline`),
архивная (`.archived`, `opacity .55`) — только когда включён показ архива.
Если документ правится прямо сейчас агентом — справа маленький `.spinner` и
подсказка «Правит backend».

## 6. Просмотр

Правая панель `.team-detail`.

**Шапка карточки (закреплена):**
- Название — `h2`, `--fs-head`, `--ink`.
- Строка метаданных `--ink-3`, `--fs-small`: селект типа (см. §9) · «Правил:
  `.agent-tag` backend, 2 ч назад» · «Версия 7 из 7».
- Для рабочих материалов — чип с задачей и её статусом.
- Действия (кнопки кита, ряд справа): `Править` (`button`, владелец), `История`
  (`button` с `.tabs-badge`-счётчиком версий), `⋯` (`button.sq ghost`) — меню
  `.float`: «Копировать текст», «Копировать ссылку», «В архив» / «Из архива».

**Тело:** компонент `Markdown` (`Markdown.tsx`, стили `markdown.css`) без новых
правил: заголовки, списки, код с подсветкой, таблицы, ссылки на файлы проекта.
Ширина текста ограничена читабельной колонкой, отступы `--space-5/--space-6`.
Шапка файла (`---`) скрывается самим `Markdown`.

**Просмотр старой версии** (из истории, §7): над телом плашка
`.team-notice` (но не красная — нейтральная `--film` вместо danger-фона):
«Вы смотрите версию 4 от 12 мая, автор — design. Это не текущая версия.» и
кнопки `[Вернуться к текущей]` (`button.mini`) и `[Восстановить эту версию]`
(`button.primary mini`). Восстановление не стирает историю, а создаёт новую
версию с текстом старой. Редактирование в режиме старой версии недоступно.

**Архивный документ:** плашка «Документ в архиве с 3 июня» + `[Вернуть из
архива]`; правка недоступна, пока документ не возвращён.

## 7. Редактирование владельцем

- Кнопка `Править` переключает тело в режим редактора: `textarea` (кит, моно-шрифт
  `--font-mono`, `--fs-md`) на всю высоту, слева — исходник, справа живой
  предпросмотр `Markdown`, если окна хватает (≥ 1100 px), иначе переключатель
  `.seg` «Текст | Просмотр».
- Название и описание — поля `input` над редактором (описание — одна строка,
  счётчик «0/140» `--ink-4`).
- Шапка в режиме правки: `[Сохранить]` (`button.primary`), `[Отмена]`, справа
  `.save-status` («Не сохранено» — `.save-status-dirty` с точкой `--warn`).
  Поле «Что изменили» (необязательное, `input`, плейсхолдер «Коротко: что и
  зачем») — станет подписью версии в истории.
- Автосохранения черновика на сервер нет; черновик держится в сторе, пока окно
  открыто. Закрытие окна или смена документа при несохранённом тексте — тот же
  вопрос, что в «Команде» (`.team-close-ask`): «Сохранить / Не сохранять /
  Остаться».
- Конфликт: если пока владелец правил, агент записал новую версию, при
  сохранении `.team-notice` (danger): «Документ уже изменил backend. Откройте
  его версию или сохраните свою поверх.» Кнопки: `[Посмотреть их версию]`,
  `[Сохранить поверх]`. Сохранение поверх — новая версия, ничего не теряется.
- Горячие клавиши: `⌘/Ctrl + Enter` — сохранить, `Esc` — отмена (через вопрос,
  если есть правки).

## 8. Поиск

- Поле `input` с иконкой `search` вверху списка (`.team-list-head`), плейсхолдер
  «Поиск по названию и тексту».
- Ищет по названию, описанию и тексту текущей версии; регистр не важен. Один
  запрос — без операторов. Задержка ввода 200 мс.
- Пока в поле есть текст, поиск идёт по **всем** типам, вкладки показывают число
  совпадений в каждом, активная остаётся выбранной; ниже счётчика — ссылка
  «Показать все типы» (`button.ghost mini`) включает единый список с чипом типа.
  Решение: по умолчанию ищем в текущей вкладке и подсказываем, сколько
  совпадений в соседних, — владелец не теряется в чужом типе.
- В строке результата: фрагмент текста вокруг совпадения вместо описания,
  совпавшая часть — `--ink` + 500.
- Нет совпадений — пустое состояние (§10). Крестик в поле очищает запрос.
- Архив: чекбокс «Показывать архив» под полем поиска (по умолчанию выключен);
  при включении архивные документы идут в конце списка с `.archived`.

## 9. Смена типа

- В шапке карточки тип — `select` (кит) с тремя значениями, видимый только
  владельцу (агентам тип меняет сервер по инструменту; в просмотре для остальных
  — чип).
- После выбора — подтверждения нет (обратимо), вместо него тост (`Toasts.tsx`):
  «Документ перенесён в «Основа». [Отменить]» на 6 секунд. Кнопка «Отменить»
  возвращает прежний тип.
- Вкладка с документом не переключается сама: он уходит из текущего списка, а в
  панели остаётся выбранной следующая строка; тост подсказывает, куда он делся
  (ссылка «Показать» переключает вкладку и выделяет документ).
- Перенос в «Рабочие материалы» требует задачи: селект типа раскрывает второй
  `select` «Задача» (список открытых задач, поиск по номеру); без задачи
  сохранить нельзя. Перенос **из** «Рабочих» привязку задачи не стирает
  (хранится в истории), но в списке она больше не показывается.
- Смена типа записывается в историю как отдельная запись («Тип изменён: Рабочие
  → Основа», автор), текст версии не меняется.

## 10. История версий

- Кнопка `История` открывает **правую колонку-ящик** внутри `.team-detail`
  (ширина 300 px, граница `--hairline`); текст остаётся слева, так версию можно
  сравнивать на глаз. Закрытие — повторный клик или `✕`.
- Элемент истории (`.team-role-row`): «Версия 7 · 2 ч назад», автор
  (`.agent-tag` / «Вы»), подпись правки (если есть), размер правки «+12 −3
  строк» (`--ok-ink` / `--danger`, `--fs-small`). Записи об изменении типа и
  архивации — без номера, серым.
- Текущая версия отмечена `.chip` «Текущая». Выбор строки открывает версию
  (плашка из §6). Ряд кнопок в элементе: `Открыть`, `Сравнить` (дифф с текущей:
  удалённые строки фоном `rgba(var(--danger-rgb), .1)`, добавленные —
  `rgba(var(--ok-rgb), .1)`, как в `diff.css`), `Восстановить`.
- Загрузка — `.spinner`; ошибка загрузки — строка `.team-notice` с «Повторить».
- Версий всего одна (документ только создан) — в ящике «Правок пока не было. Здесь
  появится каждая новая версия с автором.»
- Всего версий много — список подгружается порциями по 30 («Показать ещё»,
  `button.ghost mini`), как постраничная выдача журнала (limit + cursor).

## 11. Архив

- **Автоматически:** когда задача, к которой привязан рабочий материал, закрыта,
  документ уходит в архив. Один тост-уведомление при следующем открытии окна:
  «2 спеки ушли в архив после закрытия задач».
- **Вручную:** `⋯ → В архив` в карточке (любой тип, подтверждение не нужно —
  обратимо; тост с «Отменить»).
- Архив — не отдельная вкладка, а режим списка: чекбокс «Показывать архив» (§8).
  Решение: вкладка с одним переключателем перегрузила бы сегмент; архивные
  документы остаются в своём типе и в той же сортировке.
- Архивный документ читается, ищется (при включённом чекбоксе), история доступна;
  править нельзя до возврата.
- Удаления в этой версии нет (история и авторы должны сохраняться).
  Забывание старых архивных — отдельное решение, в спеку не входит.

## 12. Пустые состояния

Все — по образцу `.team-detail > .muted` (по центру, `--ink-3`) плюс одна главная
кнопка кита. Иконки не рисуем, кроме `book` в крупном размере в «Основе».

1. **Пустая «Основа» в новом офисе** (главное).
   - Только что созданный офис: ни одного документа. Вкладка «Основа» активна по
     умолчанию, счётчик «0».
   - Список слева — не пуст по виду, а содержит **карточку-приглашение** на
     всю ширину панели (`.card`, `--space-4`): «Основа — то, что агенты читают
     первым делом. Начните с видения: что вы строите и для кого.»
   - Ниже три строки-шаблона `.team-role-row` (пунктирные, `button.dashed`):
     «+ Видение продукта», «+ Персонажи и тон», «+ Бренд». Клик создаёт
     документ с шаблоном-заголовками и сразу открывает редактор.
   - Справа в `.team-detail` — `book` 40 px (`--ink-4`), заголовок «Здесь
     живёт всё, что не меняется от задачи к задаче», текст «Без основы агенты
     гадают, что вы хотите. С ней — пишут то, что нужно.», две кнопки:
     `[Написать видение]` (`button.primary`) и `[Попросить менеджера]` —
     кнопка отправляет менеджеру задачу «Предложи черновик видения проекта по
     коду и целям» и показывает `.spinner`, пока документ не появится.
   - Если у офиса есть проект с кодом, а «Основа» пуста — над приглашением
     `.chip` «Менеджер может собрать черновик по репозиторию».
2. **Пустая «Документация»:** «Пока нет описания, как всё устроено.
   Агенты пишут сюда архитектуру и дизайн-систему по мере работы.»
   Кнопка `[Новый документ]`.
3. **Пустые «Рабочие материалы»:** «Спеки к задачам появятся здесь, когда
   исполнители начнут их писать. Закрытые уходят в архив.» Кнопки нет,
   ссылка `[Показать архив]`, если в архиве что-то есть.
4. **Ничего не найдено:** «Ничего не найдено по «запросу»» + `[Сбросить поиск]`;
   если совпадения есть в других типах — «Есть в «Документация»: 2»
   (`button.ghost`).
5. **Документ не выбран** (справа): «Выберите документ слева» (`.muted`).
6. **Загрузка списка:** `.spinner` по центру списка; строки-заглушки не рисуем.
7. **Ошибка загрузки:** `.team-notice` «Не удалось загрузить документы» +
   `[Повторить]`.
8. **Нет связи с сервером:** окно читает последний снимок, кнопки правки
   недоступны (`disabled`), над списком — `.team-notice` «Нет связи с офисом».

## 13. Тексты интерфейса (ключи `docs.*`, ru + en в словарях `src/web/i18n`)

Окно: `docs.title` «Документы» / Documents; вкладки `docs.tab.foundation`
«Основа» / Foundation, `docs.tab.reference` «Документация» / Docs,
`docs.tab.work` «Рабочие» / Work; `docs.new` «Новый документ»;
`docs.edit` «Править»; `docs.history` «История»; `docs.archive.toArchive`
«В архив»; `docs.archive.restore` «Вернуть из архива»; `docs.search.ph`
«Поиск по названию и тексту». Остальные подписи — в тексте выше; английские
эквиваленты пишет разработчик в паре со словарём.

## 14. Токены и компоненты — сводка

Используется только готовое:
- Токены: `--surface`, `--film`, `--film-2`, `--hairline`, `--ink`…`--ink-4`,
  `--accent`, `--accent-ink`, `--ok-ink`, `--ok-rgb`, `--danger`, `--danger-rgb`,
  `--warn`, `--space-1…8`, `--radius-row/card/pill`, `--fs-small/body/md/title/head`,
  `--font-mono`, `--control-h`, `--mini-h`.
- Кит: `button` (`primary`, `ghost`, `mini`, `sq`, `dashed`), `.chip`, `.card`,
  `.float`, `.seg`, `.tabs-badge`, `.save-status`, `.agent-tag`, `.spinner`,
  `kbd`/`Kbd`, `Tooltip`, поля `input`/`textarea`/`select`.
- Готовые компоненты: `ShellPage`, `Markdown`, `Icon` (`book`, `search`, `plus`,
  `archive`, `x`, `dots`, `copy`), `Toasts`, `Avatar`, `AgentName`, раскладка
  `.team-*`.
- Новые классы допустимы только как раскладочные (`.docs-*` в новом `docs.css`:
  ширина ящика истории, колонка текста), без новых цветов и размеров.
  Тёмная тема работает автоматически — цвета только через токены.

## 15. Допущения

- Тип документа — один из трёх фиксированных; пользовательских типов нет.
- Права: править может владелец; агенты пишут через инструмент, UI им не нужен.
- Привязка рабочего материала — ровно к одной задаче.
- Версии неизменяемы, удалить версию или документ нельзя.
- Горячая клавиша `D` — предложение, не требование.
