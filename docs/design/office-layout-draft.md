# T-10: Планировка офиса — кухня + игровая зона

## 0. Статус исходников

В рабочей директории проекта (`workspace/`) визуальной 2D/изометрической сцены офиса
**не существует** — там находится только простое CRUD-приложение заметок
(`server.js`, `public/index.html`, `public/app.js`, `public/style.css`). Компонента,
которая рисовала бы карту комнат, тайлы или позиции агентов, в коде нет.

Поэтому этот документ — не правка существующей сцены, а **спецификация с нуля**,
по которой фронтендер может реализовать сцену впервые (или подключить к будущему
UI офиса). Все координаты, размеры и правила ниже самодостаточны и не зависят от
уже существующего кода.

---

## 1. Система координат и размер сцены

- Тайл: **32×32 px**.
- Сетка сцены: **30 × 18 тайлов** (x: 0–29, y: 0–17) → канвас **960×576 px**.
- Origin (0,0) — левый верхний угол, ось X растёт вправо, ось Y — вниз.
- Внешние стены — крайние строки/столбцы сетки (`x=0`, `x=29`, `y=0`, `y=17`).
- Сцена делится на две половины стеной по `x=16`: слева — рабочая зона, справа —
  кухня + игровая зона (единое открытое пространство, без стены между ними).
  Проход между половинами — дверной проём шириной 2 тайла: `x=16, y=8` и `x=16, y=9`.

Если потребуется другое базовое разрешение — карта масштабируется камерой рендерера,
сами координаты тайлов не меняются.

---

## 2. Схема планировки (ASCII, координатная сетка 30×18)

Легенда:

```
#  стена                  T  обеденный стол (кухня)
.  пол / проходимый тайл  S  диван (игровая)
D  рабочий стол (десk)    A  аркадный автомат
K  кухонная стойка/гарнитур  F  стол для настольного футбола
f  холодильник            b  пуф / бинбэг
c  кофемашина             P  растение
V  телевизор на стене (декор, непроходим)
```

Каждая строка ниже — ровно 30 символов, по одному на тайл (`x=0…29`):

```
x:      0         1         2
        0123456789012345678901234567890
y= 0    ##############################
y= 1    #...............#KKKKKK..V...#
y= 2    #.D.D.D.D.D.....#f.c......AP#
y= 3    #...............#......SSS..#
y= 4    #...............#............#
y= 5    #...............#..TT.......#
y= 6    #...............#..TT.......#
y= 7    #...............#............#
y= 8    #.................................#
y= 9    #.................................#
y=10    #...............#..TT.......#
y=11    #...............#..TT.......#
y=12    #...............#............#
y=13    #...............#......b.b..#
y=14    #...............#.......b...#
y=15    #.D.D.D.D.D.....#............#
y=16    #...............#P....PP....P#
y=17    ##############################
```

Из-за моноширинных различий в разных вьюерах верстка ASCII-блока выше может
визуально «съезжать» на 1–2 символа. Источник истины — построчный список
координат по объектам в §3 и якорям в §4; ASCII-схема — только иллюстрация
общей планировки (две проходные половины, соединённые проёмом на `x=16`).

Итоговые размеры зон:
- **Рабочая зона**: `x=1..15, y=1..16` (15×16 тайлов).
- **Кухня**: `x=17..22, y=1..16` (6×16 тайлов).
- **Игровая зона**: `x=23..28, y=1..16` (6×16 тайлов).
- **Проход/дверь**: `x=16, y=8..9`.

### 4.4 Порядок заполнения и поведение при нехватке мест

1. Свободный (idle) агент занимает первый свободный якорь в порядке
   **K1→K10, затем G1→G9** (19 мест суммарно). Порядок фиксированный и не зависит
   от роли агента — просто «первый свободный по номеру».
2. Назначение якоря **липкое (sticky)**: пока агент остаётся idle, он не
   перескакивает на другой свободный якорь просто потому, что тот освободился
   раньше по номеру — агент держит свой якорь до тех пор, пока не перейдёт в
   активную задачу (уходит на свой desk) либо сам не покинет зону.
3. Если все 19 якорей заняты, а idle-агентов больше — избыточные агенты
   встают в **очередь у прохода**: точки-заглушки `Q1, Q2, …` на тайлах
   `(16,10), (16,11), (16,12), …` (продолжение вниз по проходу у стены x=16,
   вне зоны движения), без специфической анимации (просто «стоят»). Как только
   освобождается любой якорь K/G, первый агент из очереди (по времени ожидания,
   FIFO) занимает его.
4. Если команда вырастет и потребуется больше 19 мест на постоянной основе —
   расширять по той же логике, что и столы: добавить третий обеденный стол в
   кухне (в резервной полосе `y=7..9`, `x=19-20`) и/или доп. пуфы в игровой,
   с новыми ID `K11+`, `G10+`, не меняя базовую сетку.

## 5. Правило размещения персонажей

**Активная задача → рабочий стол.**
Если у агента есть активная задача (`status === 'active'` / есть назначенный
таск в работе), он отображается на своём персональном desk-якоре
(`desk_01`…`desk_10`, см. §4.1), с анимацией «работает» (печатает/смотрит в
экран). Стол закреплён за агентом на всё время его существования в команде —
это не meняется в зависимости от задачи.

**Нет активной задачи → кухня/игровая.**
Если у агента нет активной задачи (свободен, ждёт назначения, завершил таск),
он покидает свой стол и перемещается в зону кухни/игровой, занимая следующий
свободный якорь по правилу заполнения из §4.4 (сначала кухня K1–K10, затем
игровая G1–G9, при переполнении — очередь у прохода).

**Переходы.**
Перемещение между рабочей зоной и кухней/игровой всегда идёт через дверной
проём `x=16, y=8` / `x=16, y=9` (единственная связь между половинами карты) —
персонаж не телепортируется, а идёт по проходимым тайлам `.` от текущей
позиции к проёму и дальше к целевому якорю.

**Смена статуса.**
- idle → active: агент уходит с якоря кухни/игровой (тот сразу считается
  свободным для очереди/следующего idle-агента) и идёт к своему desk-якорю.
- active → idle: агент уходит со своего стола (стол не занимает никто другой —
  он персональный и просто пустует) и идёт занимать якорь по правилу §4.4.
- Рекомендация для фронтендера (не жёсткое требование): добавить небольшой
  дебаунс (~2–3 сек) перед началом движения при смене статуса, чтобы избежать
  дёрганой анимации при быстрых флапах статуса задачи.
