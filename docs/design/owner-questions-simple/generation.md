# Формулировка вопросов владельцу

Русские инструкции генерации вопросов (T-752). Контракты вопросов, согласований и доступа сохранены.

## Правило

Техническую работу решает команда. До обращения к владельцу команда проверяет доступные код, состояние и результаты проверок, при необходимости привлекает коллег. PM поручает подготовку исполнителю; ритуал без инструментов передаёт техническое расследование команде.

Владельцу нужен вопрос только за необходимым решением, согласием или доступом. В `question` — понятная причина или польза и одно точное действие владельца, 1–2 коротких предложения, понятных без открытия задачи. `title` — короткая понятная суть и действие (карточка показывает его первым). PID, пути, id задач, диагностические термины и основания — в `details`, если конкретный путь его поддерживает; иначе — в отчёте команды.

При выборе из альтернатив обязательны 2–4 `options` до 40 символов каждый. Для свободного ответа — пустой список. Суть выбора должна быть понятна из самого вопроса.

В `assumption` — безопасное поведение команды до ответа: какую независимую разрешённую работу продолжают и какое действие ждёт согласия или доступа. Это не поручение владельцу чинить систему. Допущение не заменяет разрешение и не позволяет обходить ограничения. Необходимые вопросы согласия сохраняются.

Перед просьбой об обновлении команда проверяет доступный артефакт и результаты проверок. При недоступной проверке это прямо указывается в подробностях: непроверенное обновление не объявляется готовым.

## Пример после проверки артефакта

Условный пример: команда действительно проверила сборку и подтвердила наличие исправления.

- `question`: «В новой сборке исправлено зависание проверки задач. Разрешаете обновить приложение сейчас?»
- `title`: «Обновить приложение для исправления зависания?»
- `options`: «Обновить сейчас», «Отложить обновление».
- `assumption`: «До согласия сохраняем текущую версию и продолжаем независимые задачи».
- `details`: результаты проверки сборки, её версия, диагностические основания, пути и ссылки на задачи.

Если сборка не проверена, такая формулировка о готовом исправлении неприменима. Сначала команда выполняет доступную проверку, а при необходимости просит конкретное согласие или доступ с честным указанием оставшейся неопределённости.

Для свободного ответа: «Чтобы подготовить обращение к вам, укажите удобное имя». `options: []`.

## Действующие точки

Общее русское правило находится в `src/server/i18n/prompts-ru.ts` (`правилоВопросаВладельцу`); оно включено в инструкции PM, исполнителей, консолидации, поиска противоречий и рефлексии, а также описания ask_owner. Описания полей того же словаря задают формат основного текста, допущения и подробностей. Английский словарь в этой задаче не менялся.

| Путь | Инструкции и передача |
| --- | --- |
| PM | `pmPrompt` → `prompt.pm.life`; инструмент ask_owner передаёт options, title, details, replaces и чат в askOwner |
| Исполнитель в работе | Основной промпт включает `prompt.worker.life`; `workerTools` передаёт options, title, details и sandboxRequest |
| Исполнитель на паузе / доработке | `workerSystemPrompt` теперь тоже включает `prompt.worker.life`; ask_owner передаёт те же поля и роль исполнителя |
| Ритуалы | Системные промпты и `ritualTools` → `RitualOutput.questions` → `applyOutput` в rituals.ts; обычный вопрос через officeAsks, замена через askOwner; оба пути сохраняют options, title, details |

В пакетах ролей отдельная инструкция ask_owner найдена в `packages/@office/unity/brief/ru.md`: она согласована с общим правилом и сохраняет sandbox_status и структурный sandboxRequest. У остальных ролей нет собственного правила ask_owner: они получают общее правило при сборке промпта. Пакет PM не содержит отдельного брифа.

В questions.ts исправлен комментарий о продолжении работы: сессия не простаивает, но действие с обязательным разрешением ждёт ответа. Приём вопросов не ограничен новым фильтром стиля: необходимые согласования не отклоняются по форме текста. Сохранены обратная совместимость, запасной разбор вариантов, лимиты и защита согласований. Для запросов доступа сервер по-прежнему добавляет точный перечень запрашиваемых прав и использует собственные кнопки согласия/отказа; эти сведения не удаляются ради краткости.

## Проверка T-752

Все проверки прошли без живых сессий моделей и без запуска test:pm или scripts/test-pm.ts:

- `npm run typecheck`.
- `node --import tsx --import ./scripts/_isolate.ts scripts/test-question-meta.ts`: 26 проверок разметки, подробностей, вариантов, подтверждений и совместимости.
- `node --import tsx --import ./scripts/_isolate.ts scripts/test-life.ts`: варианты выбора и свободный ответ, защита открытых согласований, очередь и ритуалы.
- `npm run test:access`: согласие/отказ, сохранность sandboxRequest, применение прав только со следующей сессии, свободный текст не выдаёт права.
- `npm run test:lost-question`: технический разбор потерянных вопросов внутри команды, сохранение вариантов и сути при перезадании.
- Адресная проверка через Node с тем же изолятором: собранные промпты PM и workerSystemPrompt, русские инструкции исполнителей и трёх ритуалов содержат общее правило; все четыре схемы и обработчика ask_owner сохраняют options/title/details.
- В той же адресной проверке агент консолидации заменён локальной заглушкой: обычный вопрос и вопрос с replaces прошли через runRitual и applyOutput с сохранением текста, допущения, вариантов, заголовка и деталей; свободный ответ пришёл без кнопок.

Проверки подтверждают инструкции и передачу данных, но не гарантируют соблюдение формулировки любой живой моделью. Обновление установленного приложения и переформулировка старых вопросов не входят в изменение инструкций.
