# Вопросы владельцу: подача «сначала суть» (T-586)

Макет: [`mockup.html`](mockup.html) — открывается в браузере сам по себе, светлая тема, значения скопированы из `src/web/styles/tokens.css`. В коде брать переменные, не числа.

Где живёт: вкладка «Вопросы» окна «Жизнь офиса» (`LifePanel.tsx`, `Questions` / `QuestionRow`).

## 1. Принципы

1. **Сначала суть.** В карточке — одна фраза вопроса (≤ 120 символов) и кнопки. Всё остальное — под «Подробнее».
2. **Человеческий заголовок.** Без `J-…`, `T-…`, хешей коммитов, номеров строк. Они остаются в подробностях.
3. **Офис уже решил сам** → карточка-подтверждение: «Офис считает: X» + `[Согласен] [Нет, иначе]`.
4. **Две группы:** «Нужно ваше решение» и «На подтверждение»; по умолчанию — очередь «1 из N», переключатель «Списком».
5. **Без дублей кнопок.** Приписки вроде «Нажмите „Выпускай“… или „Не сейчас“» не показываются. Допущение — мелко, одной строкой: «Пока считаем: …».
6. **Однотипные вопросы** сворачиваются в «3 похожих вопроса» с общим ответом.

Сохраняется: кнопки `options` (2–4, до 40 символов), ссылка «Ответить своими словами», «Пусть офис разберётся» у противоречий (всегда последняя), управление (править / слить / удалить) — внутри «Подробнее».

## 2. Карточка вопроса на решение

Порядок сверху вниз:

| Часть | Вид | Источник |
|---|---|---|
| Мета-строка | `--fs-caption`, `--ink-4`: цветная точка вида (`--accent-1` допущение, `--accent-5` противоречие, `--warn` устарело), подпись вида, «N ч назад». Без номеров | `kind`, `askedAt` |
| Заголовок | `--fs-title` 15, 600, `--ink`; до 2 строк, без Markdown | `title` |
| Ряд кнопок | `options` как `.mini`-пилюли; первая — акцентная (`--accent`) только если вариантов 2 и это выбор «да/нет»-типа; иначе все нейтральные. Следом ссылка «Ответить своими словами» (ghost, подчёркнута). Последней — «Пусть офис разберётся» (контур `--hairline`, значок ✦ `--accent-3`), только у `kind: 'contradiction'` | `options`, `kind` |
| Допущение | `--fs-small`, `--ink-4`: «Пока считаем: …», одна строка с обрезкой по ширине, полный текст — в подробностях | `assumption` |
| «Подробнее ▾» | справа в нижней строке | — |

Нет `options` → вместо кнопок сразу поле ввода и «Ответить» (как сейчас). Кнопка «Снять без ответа» уезжает в подробности (в ряду кнопок её нет: это не ответ).

Высота свёрнутой карточки ≈ 120–140 px, на экран влезает 3–4.

### «Подробнее» (раскрыто)

Разделитель пунктиром, затем блоки (показывается только то, что есть):

1. **Полный вопрос** — `details` в Markdown (как сейчас `text`).
2. **Цитаты** — `quotes[]`: «две записи журнала» с подписью-ссылкой (`J-351 · ваш ответ …`) и словом «против» между ними.
3. **Что показал разбор** — `basis`: основание, хеши и строки — здесь.
4. **Допущение целиком** — если не поместилось в строку.
5. **Связано** — `refs[]` чипами (`--font-mono`, `--film`): записи, задачи, коммиты; клик ведёт на запись/задачу.
6. **Файлы результата** — `files` (как сейчас `ResultFiles`).
7. **Управление** — Править · Слить с другим · Удалить (ghost, `.mini`, как сейчас `.life-manage`).

Состояние раскрытия — локальное, в `useState` карточки; в очереди при переходе к следующей сбрасывается.

## 3. Карточка подтверждения

Для вопросов с `proposal`. Фон `rgba(var(--accent-rgb), .04)`, рамка `rgba(var(--accent-rgb), .25)` — отличается от решений без нового токена.

- Мета-строка та же (источник: «Проверка свежести», «Планёрка» …).
- Тело вместо заголовка: «Офис считает: **{proposal}**.» (`--fs-md`, акцентная часть — `--accent`, 600). Если proposal длиннее 120 — берётся первое предложение, остальное в подробности.
- Кнопки: `[Согласен]` (акцент) и `[Нет, иначе]`. «Нет, иначе» разворачивает поле ввода «Как тогда?» + `[Отправить]` и ссылку «Вернуться к „Согласен“». `options` у подтверждения игнорируются.
- «Пока считаем: …» — по умолчанию то, что произойдёт при согласии (если `assumption` пуст, строка скрыта).
- «Подробнее» — на основании: `details`, `basis`, `refs`.
- Отправка «Согласен» = `answerQuestion(id, "Согласен: {proposal}")` (префикс `CONFIRM_ANSWER = 'Согласен'` — константа в `shared/questions.ts`; сервер распознаёт его, пишет решение «подтверждено» в журнал и применяет `proposal`). «Нет, иначе» отправляет текст владельца как обычный ответ.
- В группе «На подтверждение» в заголовке — ghost-кнопка «Согласен со всеми» (с подтверждением «Согласиться с 2?»; только открытые карточки этой группы).

## 4. Группа похожих вопросов

Условие: ≥ 2 открытых вопроса с одинаковым `groupKey` в одной группе (решение / подтверждение). Вопросы разных групп вместе не сворачиваются.

**Свёрнута:** карточка со «стопкой» (тонкая вторая рамка снизу), мета-строка + бейдж `×N`, заголовок «N похожих вопроса/вопросов — {groupTitle}» (склонение по правилам языка интерфейса, через i18n plural), блок общего ответа, ссылка «Раскрыть все», допущение группы (`assumption` первого вопроса, если у всех совпадает, иначе строка скрыта).

**Общий ответ** — кнопки показываются, если у всех открытых вопросов группы совпадает набор `options` (сравнение по тексту, без регистра) или у группы есть `groupOptions`. Клик закрывает все открытые вопросы группы тем же ответом; отвеченные уже раньше не трогаются. Для противоречий общий ответ — и «Пусть офис разберётся» (последним). Нет общих вариантов — блока нет, остаётся только раскрытие.

**Раскрыта:** сверху блок «Общий ответ — на все N», ниже подкарточки (фон `--canvas`, рамка `--hairline`, радиус `--radius-row`): заголовок вопроса, его кнопки, «Подробнее». Отвеченный внутри группы — зачёркнутый заголовок и «✓ Отвечено: …»; когда все отвечены, группа исчезает из активных. Внизу «Свернуть».

В очереди группа — **одна карточка** (один шаг).

## 5. Очередь «1 из N» и список

**Переключатель** `[Очередь | Списком]` — сегмент в шапке вкладки (стиль `.seg` оболочки). Справа счётчик: «7 вопросов · 5 карточек» (в режиме списка — «7 вопросов»).

**Очередь (по умолчанию):**
- Шаг = карточка (одиночный вопрос, подтверждение или группа). «1 из 5» — по карточкам, счётчик вопросов показан рядом.
- Порядок: сначала все «Нужно ваше решение» (старые сверху — по `askedAt`), затем «На подтверждение».
- Над карточкой — подпись группы («Нужно решение · 1 из 5») и полоса прогресса из сегментов: сделанные `--accent`, текущий `--ink-2`, решения — обычные, подтверждения — бледные. Так видно, где граница групп.
- Ответил — карточка сменяется следующей; короткий подтверждающий кадр не нужен (счётчик и полоса сдвигаются).
- «Пропустить →» уводит карточку в конец своей группы, вопрос остаётся открытым. Без «Назад»: вернуться можно через «Списком».
- Переход между группами: когда решения кончились, перед первым подтверждением короткий заголовок «Решений больше нет — осталось 2 подтвердить».
- Если во время просмотра пришёл новый вопрос — он встаёт в конец своей группы, текущая карточка не прыгает; счётчик «из N» обновляется.

**Списком:**
- Две секции: «Нужно ваше решение» (акцентный заголовок, число) и «На подтверждение» (число, «Согласен со всеми»). Разделитель — линия `--hairline`.
- Карточки в том же виде, что и в очереди; группы — одной карточкой.
- «На подтверждение» сворачивается в строку «N на подтверждение ▸», если решений ≥ 3 (чтобы подтверждения не отодвигали решения).
- В списке можно отвечать на любые карточки в любом порядке; открытое «Подробнее» не сбрасывается при ответе на соседние.

**Связь режимов:** выбор запоминается в `localStorage` (`life.questions.view`, `'queue' | 'list'`). Переключение в «Списком» прокручивает к текущей карточке очереди, обратно — делает текущей первую неотвеченную в порядке очереди (пропущенные не помнятся). Число в табе «Вопросы · N» — число открытых вопросов (не карточек), как сейчас.

**Закрытые:** ссылка «Показать закрытые (N)» внизу обоих режимов; внутри — как сегодня раздел «Закрытые и влитые», без групп.

## 6. Пустое состояние

- Нет открытых: значок ✓ (`--ok-ink` на 12% фоне), «Все вопросы разобраны», «Офис спросит, когда ему придётся что-то допустить без вас.», ссылка «Показать закрытые (N)».
- Нет ни одного вопроса за всё время: тот же заголовок без ссылки.
- Конец очереди — то же состояние.
- Остались только подтверждения: заголовок «Решений нет, осталось N подтвердить», ниже обычные карточки.

## 7. Схема данных

Все новые поля **необязательные** — старые вопросы продолжают читаться. Расширение `OwnerQuestion` (`src/shared/types.ts`):

```ts
interface OwnerQuestion {
  // уже есть: id, from, taskId, chatId, kind, text, assumption, options,
  // files, askedAt, answer, answeredAt, dismissedAt, mergedInto, …

  /** Короткий заголовок карточки, ≤ 120 символов, человеческий язык,
   *  без J-/T-номеров и хешей. Нет — веб берёт titleFallback(text). */
  title?: string;

  /** Подробности, Markdown: полный текст вопроса. Нет — подробности
   *  строит из `text`. Сюда уходят все приписки, номера и хеши. */
  details?: string;

  /** Цитаты спорящих записей (у противоречий). */
  quotes?: { ref: string; text: string; note?: string }[];  // ref — «J-351»; note — «ваш ответ …»

  /** «Что показал разбор»: основание решения офиса. Markdown, любые хеши и строки. */
  basis?: string;

  /** Связанные записи, задачи, коммиты — чипы в подробностях. */
  refs?: { kind: 'journal' | 'task' | 'commit' | 'file'; id: string; label?: string }[];

  /** «Пока считаем: …» — уже есть, как `assumption`. Для карточки ≤ 140
   *  символов; длиннее — обрезается, полный в подробностях. */

  /** Признак подтверждения: офис уже решил и ждёт «Согласен» / «Нет, иначе».
   *  Есть proposal → карточка подтверждения, группа «На подтверждение».
   *  Нет → «Нужно ваше решение». Короткая фраза без «Офис считает:» (приставку ставит веб). */
  proposal?: string;

  /** Ключ группы однотипных вопросов; одинаковый ключ → «N похожих». */
  groupKey?: string;
  /** Тема группы для заголовка: «про прошлые выпуски». Берётся у первого вопроса группы. */
  groupTitle?: string;
  /** Общие варианты группы, если не совпадают по options. Необязательно. */
  groupOptions?: string[];
}
```

### Что нужно каждой части карточки

| Часть карточки | Поля | Если нет |
|---|---|---|
| Мета-строка | `kind`, `from`, `askedAt` | — (обязательные уже есть) |
| Короткий заголовок | `title` (≤ 120) | `titleFallback(text)`: первое предложение `text` без Markdown, J-/T-номеров, хешей `[0-9a-f]{7,40}`, обрезка до 120 по слову с «…» |
| Кнопки вариантов | `options` (2–4 × ≤ 40) | поле ввода |
| «Ответить своими словами» | — (есть при `options`) | — |
| «Пусть офис разберётся» | `kind === 'contradiction'` | не показывается |
| Допущение | `assumption` | строка скрыта |
| Подробности | `details`, `quotes`, `basis`, `refs`, `files`, `text` | блок скрыт, если пуст; если пусто всё — «Подробнее» не рисуется |
| Признак подтверждения | `proposal` | считается решением |
| Ключ группы | `groupKey`, `groupTitle`, `groupOptions` | вопрос не группируется |

### Правила для бэкенда

- **Записывать вопрос так:** `title` — одна фраза-вопрос; `details` — всё остальное; номера и хеши — только в `details`/`quotes`/`basis`/`refs`. Серверная проверка: `title` > 120 символов или содержит `\bJ-\d+\b`/хеш → ошибка инструмента `ask_owner` с подсказкой «сократи, детали — в details».
- **Не писать в `text`/`details` инструкции к кнопкам** («Нажмите…», «Ответьте „Выпускай“ или…») и сервисные приписки («Обе записи — ваши решения…»). Для старых записей веб режет эти хвосты шаблонами (список — в `shared/questions.ts`, `stripBoilerplate`); цель — убрать их в источнике (ритуалы противоречий, выпуски).
- **`proposal`** заполняют ритуалы, которые уже вывели решение сами (свежесть журнала, разбор противоречий, когда офис разобрал и просит подтвердить). Если `proposal` есть, `options` не нужны.
- **`groupKey`** — стабильная строка из вида и темы: `contradiction:releases`, `stale:facts`, `assumption:T-586`. Ставит автор вопроса; веб ничего сам не группирует.
- Ответ на группу — N вызовов `answerQuestion` по открытым вопросам (бэкенд не обязан знать про группы); веб шлёт их подряд и показывает один тост.
- Сортировка очереди — на вебе: группа → `askedAt` по возрастанию. Серверу порядок не нужен.

### Состояние на вебе (без сервера)

```ts
type QuestionsView = 'queue' | 'list';          // localStorage: life.questions.view
// в памяти панели:
```

## 8. Тексты интерфейса (RU)

«Нужно ваше решение» · «На подтверждение» · «Очередь» · «Списком» · «N из M» · «Пропустить» · «Подробнее» / «Скрыть подробности» · «Пока считаем: …» · «Офис считает: …» · «Согласен» · «Нет, иначе» · «Согласен со всеми» · «N похожих вопроса/вопросов» · «Раскрыть все» / «Свернуть» · «Общий ответ — на все N» · «Ответить своими словами» · «Пусть офис разберётся» · «Все вопросы разобраны» · «Показать закрытые (N)».

Ключи — в `life.questions.*`; склонения — через существующий механизм plural в i18n (если нет — завести).

## 9. Доступность и мелочи

- Кнопки вариантов — обычные `button`, порядок табуляции: варианты → «Ответить своими словами» → «Пусть офис разберётся» → «Подробнее».
- «Подробнее» — `aria-expanded`; очередь — `aria-live="polite"` на счётчике «N из M».
- Контраст: мета-строка и «Пока считаем» на `--ink-4` ≥ 4.5:1 на `--surface` (проверяется `npm run test:contrast`); `--accent` для текста «Нужно ваше решение» на белом — 5.2:1.
- Тёмная тема: всё на токенах, оттенок подтверждения через `--accent-rgb` работает в обеих.

## 10. Допущения дизайнера

- Файлы лежат в `docs/design/owner-questions-simple/` по тексту критериев, а не в `docs/design/T-586/`.
- Макет — HTML, не Figma: макет не рисовался в Figma, значения 1:1 из `tokens.css`.
- «Согласен со всеми» оставлен только для подтверждений, для решений его нет намеренно.
- Шаг очереди — карточка, а не вопрос; группа — один шаг.
- Подтверждение «Согласен» кодируется префиксом в тексте ответа, а не новым видом ответа — чтобы не менять `answerQuestion` и протокол.
