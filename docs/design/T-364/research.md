## 1. Что такое open-design

**Это** open-source «рабочее место дизайн-агента», заявленная замена Claude Design от Anthropic. Через кодового агента делает веб-прототипы, слайды, картинки и видео. Это не редактор с холстом, как Figma.

| Вопрос | Ответ |
|---|---|
| Как работает агент | Три пути: (1) MCP-сервер (`od mcp install <агент>`, любой MCP-агент читает файлы локальных проектов OpenDesign); (2) CLI/адаптеры к 26 кодовым агентам, среди них Claude Code и Codex; (3) файлы: агент берёт навык (skill) плюс `DESIGN.md` и пишет файлы проекта |
| Формат макетов | Дизайн-система и результат — файлы: `DESIGN.md` («контракт бренда»), `manifest.json`, `tokens.css`, HTML-артефакты. **Но сами проекты open-design хранит в SQLite** (беседы, сообщения, вкладки, шаблоны), с локальным демоном на 127.0.0.1; требует Node ~24 и pnpm 10.33 (проверено по странице репозитория, 2026-10-06). Значит, «лежит в git рядом с кодом» верно только для экспортированных HTML и DESIGN.md, а не для проекта целиком. Куда демон пишет артефакты, не проверено |
| Экспорт | HTML (с инлайном), PDF (печать браузера), PPTX (через агента), ZIP, Markdown, MP4 (HyperFrames). **PNG в списке нет**, но он делается скриншотом HTML |
| Figma | Есть плагин `od-figma-migration`: Figma → React/Next/Vue-код. То есть Figma читается, обратной записи нет |
| Лицензия | Apache-2.0, у вложенных шаблонов свои (часть MIT) |
| Живость | ~99,6 тыс. звёзд, ~11,5 тыс. форков, ~3,7 тыс. коммитов, 530 открытых issues и 625 открытых PR, есть релизы десктопа для macOS и Windows. Звёзды, форки и число коммитов подтверждены на странице репозитория 2026-10-06; свежих коммитов и issues не смотрели. Проект очень живой, но очень быстрый и шумный: 100+ навыков, 151 дизайн-система, 277 плагинов. Версия и API могут меняться быстро |
| Не проверено | Точный список MCP-инструментов и размер ответов (в документации их нет, см. «Закрытые пробелы»). Демон нужен запущенный (MCP читает проекты через него); данные лежат в `RUNTIME_DATA_DIR`, вне репозитория. Комментирование макета в open-design частично выпущено |

**Вывод по сути:** open-design — это HTML-прототипы на дизайн-системе, которыми управляет агент. По принципу он ближе к нашему варианту «HTML/CSS на токенах», чем к Figma, но с большой обвязкой (приложение, 277 плагинов), которая нам, скорее всего, не нужна.

## 2. Расход токенов

Причины сгорания 2 млн токенов в Figma: (а) `get_node`, `get_document`, `get_design_context` отдают большие поддеревья JSON; (б) ~40 вызовов на макет, и каждый пересылает весь накопленный контекст. Скриншоты ещё и тяжёлые.

| Подход | Что агент получает на операцию | Оценка (грубо, не измерялось) |
|---|---|---|
| figma-bridge | JSON поддерева узлов со всеми свойствами | 5–50 тыс. токенов на чтение, сотни токенов на запись; макет — 30–40 вызовов с мелкими правками |
| open-design (файлы) | Агент пишет один HTML-файл целиком, читает назад только по необходимости | Запись 3–8 тыс. токенов за экран; правка — точечный Edit, десятки токенов; вызовов 5–10 на экран |
| open-design (MCP) | Чтение файлов проекта | Зависит от размера файла, сравнимо с чтением HTML. Реальные ответы не измерены |
| HTML на наших токенах | То же, что выше, без чужих навыков | Как у open-design за вычетом его системного контекста (навыки, `DESIGN.md` 151 системы раздувают промпт) |

Ключевая разница: текстовый файл правится дифом, а Figma-дерево нужно перечитывать. Сверх этого выигрыш даёт сам формат «весь экран одним файлом»: число вызовов падает в 4–6 раз, а значит и повторная пересылка контекста.

## 4. Рекомендация

**Основной путь: HTML/CSS-прототип на наших токенах, скриншот через `tools/browser`.** open-design не внедряем как зависимость: из него берём идею (`DESIGN.md` как контракт бренда плюс файл на экран), а саму систему не ставим.

Почему:
- в проекте уже есть `src/web/styles/tokens.css` и `kit.css` (стенд `?kit=1`), то есть дизайн-система уже готова, а макет на ней сразу совпадает с тем, что соберёт фронтенд;
- макет лежит в git, правится дифом, ревьюер видит изменения;
- меньше всего вызовов и токенов, нет повторной пересылки деревьев Figma;
- ноль новых установок и платных сервисов.

**Что отдаём владельцу:** PNG дневной и ночной тем в `docs/design/<задача>/` плюс сам `.html` (открывается двойным щелчком). Правки владелец пишет ответом на согласование, как сейчас.

**Figma оставляем** как запасной путь только для случая, когда владелец явно просит холст; тогда работаем не больше 10 вызовов, без `get_document`, только `get_node` на конкретный узел с малой глубиной.

**Если нужен холст с комментариями, лучше Penpot, а не open-design:** ближе к Figma, MCP бесплатный. Но это отдельная пробная задача.

### Шаги внедрения
1. Фронтенд или дизайнер создаёт `docs/design/_template/mock.html`: подключает `tokens.css` и `kit.css` по относительному пути, переключатель темы `data-theme` (значения в tokens.css — `day` и `night`, не light/dark; файлы PNG тоже называть day/night), рамка окна 1440×900. Один файл на экран (или состояние).
2. Скрипт `scripts/mock-shot.mjs` (обёртка над `tools/browser`): `file.html` → `day.png` и `night.png`. `tools/browser` **не открывает `file://`** (проверено по `tools/browser/server.mjs`: `open` принимает только http(s) на localhost/127.0.0.1). Зато есть инструмент `serve`: раздаёт папку рабочей копии без порта на адрес `http://127.0.0.1:<порт>/`, его и отдаём в `open`. Макет и `tokens.css` должны лежать под одной раздаваемой папкой (раздавать `docs/design/<задача>` с относительным путём к `src/web/styles` не выйдет — раздавать корень рабочей копии и открывать `/docs/design/<задача>/mock.html`).
3. Правило в `RULES.md` офиса / бриф роли «Дизайн»: «Макет делается HTML на токенах проекта, одним файлом на экран; в Figma — только по прямой просьбе владельца и не больше 10 вызовов; сначала `Write` файла целиком, потом точечные `Edit`».
4. Добавить `docs/design/DESIGN.md` — краткий контракт: токены, радиусы, отступы, типографика, запреты (по образцу open-design, ~1–2 страницы), чтобы агенту не приходилось читать весь `tokens.css` каждый раз.
5. Пилот: следующая задача на макет выполняется по новому пути; сравнить расход токенов с T-347/T-350/T-357 и записать в журнал офиса.
6. Решение владельца нужно по одному пункту: устраивает ли смотреть макеты как PNG и HTML, а не в Figma. Допущение: устраивает (вопрос в отчёте).

## Закрытые пробелы (шаг rework, 2026-10-06)

Источники: README и `AGENTS.md` репозитория `nexu-io/open-design`, поиск по Penpot MCP.

- **Инструменты MCP open-design.** Документация перечисляет только команды CLI (`od project list --json`, `od files list`, `od files read`, `od plugin list --json`, `od skills list --json`). Список MCP-инструментов и размер их ответов нигде не описаны; для точного ответа надо читать `apps/daemon/src/cli.ts`. По составу команд это чтение списков и файлов проекта, то есть ответы сравнимы с чтением файла, но замеров нет. Для решения это не меняет ничего: зависимостью не берём.
- **Куда демон пишет данные.** Всё под одним корнем `RUNTIME_DATA_DIR` (задаётся `OD_DATA_DIR`): `PROJECTS_DIR` (проекты), `ARTIFACTS_DIR` (сгенерированные артефакты), SQLite, токены и настройки MCP, состояние плагинов, учётные данные коннекторов, логи. Это каталог демона вне репозитория; проекты, импортированные из папки, остаются на месте (`metadata.baseDir`). Следовательно, в git макет попадёт только руками, экспортом. Довод против зависимости усиливается.
- **Как владелец комментирует макет в open-design.** Режим комментариев на дорожной карте помечен «частично выпущен, точечные правки в работе», панель твиков от ИИ «не реализована». Рабочего сценария «владелец оставил комментарий — агент поправил» опираться нельзя.
- **Свежесть.** Последний названный релиз 0.10.0, в планах 0.11.0; 3 708 коммитов. Это сырой, быстро меняющийся продукт (до 1.0). Свежие коммиты и issues по одному не разбирали: для вывода достаточно версии 0.x и статуса комментариев.
- **Penpot MCP (по поиску, не по коду).** Официальный сервер отдаёт пять инструментов: `execute_code` (агент пишет JS для Plugin API внутри запущенного редактора), `high_level_overview`, `penpot_api_info`, `export_shape` (PNG/SVG выбранной фигуры), `import_image`. Ответы маленькие, и в этом токены экономнее моста Figma: нет выгрузки деревьев. Но работает только при открытом редакторе с плагином, как и наш мост, и вызовов на макет будет немало (код на JS на каждую фигуру). Есть и сторонний сервер на 68 инструментов с комментариями, его качество не проверено. Вывод прежний: кандидат на отдельную пробную задачу, если владелец захочет холст, не основной путь.
- **Расход токенов.** Оценки в п. 2 остаются расчётом по формату данных, замеров нет. Замер даст пилот (шаг 5): записать входные токены запуска и число вызовов.

## Проверка (шаг verify)
