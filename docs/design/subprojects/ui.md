# Подпроекты: интерфейс

Статус: макет, кода нет. Задача T-451. Развивает «§8 Интерфейс (словами)» из
`docs/design/subprojects/spec.md`; модель, допуск и границы правок — там, здесь
только то, что видит человек. Макеты — `docs/design/T-451/mockups.html`
(все экраны, обе темы, генератор `gen.py`; лежат в ветке `task/T-451`, в основную
вольются вместе с ней). Номера «макет N» ниже — номера экранов в этом файле.

Принцип тот же, что у всего интерфейса: **веб ничего не решает.** Допуск,
зона задачи, `problem` и отказы считает сервер; экран показывает
`SubprojectView`, `TaskView.subprojectId` и тексты отказов как есть.

Токены берутся из `src/web/styles/tokens.css`, свои не заводим:

| Что | Токен |
|---|---|
| Цвет зоны | `--accent-1..8` (хранится в `Subproject.color` именем токена, а не hex) |
| Подложки, поля, чипы | `--surface`, `--film`, `--film-2`, `--film-3` |
| Границы карточек | `--hairline` |
| Текст | `--ink`, `--ink-2`, `--ink-3`, `--ink-4` |
| Ошибка / предупреждение | `--danger`, `--warn-ink` |
| Радиусы | `--radius-card` 12, `--radius-row` 10, `--radius-pill` |
| Размеры | `--control-h` 32, `--chip-h` 28, `--mini-h` 26; отступы `--space-*` |
| Слои | форма — `--z-modal`, подложка — `--veil` |

Тёмная тема отдельных значений не вводит: все токены переопределяются в
`[data-theme='night']`. Цвета зон — фиксированные, из `:root`, поэтому метка
зоны одинакова днём и ночью, а текст на ней берёт `--accent-N-ink`.

## 1. Настройки офиса → «Подпроекты» (макеты 1–5)

Новый раздел в `SettingsPage`, после «Секретов». Скрывается ли он в офисе без
зон? Нет: пустое состояние и есть вход в функцию.

### 1.1. Список

Шапка: заголовок «Подпроекты», подпись «Зоны ответственности: у каждой свои
задачи, документы и правила», справа кнопка «+ Добавить» (`btn pri`).

Карточка зоны (высота по содержимому, `--radius-card`, рамка `--hairline`):

```
▌ Сервер   [Папка server/]                      (BE)(B2)(RV)
▌ Агенты, состояние, HTTP и WebSocket            4 задачи
▌ ⚠ Папка не найдена: ../shop-api. Задачи зоны не стартуют.
```

- Слева цветная вертикальная метка 6 px — цвет зоны.
- Имя (`--ink`, 13 px, 600), чип вида: «Папка» / «Репозиторий» + корень моноширинным
  шрифтом `--font-mono`.
- Строка `summary` (`--ink-3`, 11 px); пусто — строки нет.
- Справа: аватарки закреплённых (до 4, дальше «+N»), под ними «N задач»
  (открытые, `SubprojectView.openTasks`; ноль — «нет задач»).
- `problem` — отдельная красная строка (`--danger`) с ⚠; задачи такой зоны не
  стартуют, и карточка говорит это сама.
- Клик по карточке открывает форму (§1.2). Закреплённых нет — вместо аватарок
  серый текст «никто не закреплён».
- Под списком одна подсказка: «Сотрудники без закрепления («Весь проект»)
  работают во всех зонах и в коде вне их».
- Порядок — как в `state.subprojects` (порядок создания); порядок же задаёт
  раскладку участков в 3D (§5), перетаскивания в этой версии нет.

### 1.2. Форма (модалка 430 px, правка и создание — одна)

Заголовок: «Новый подпроект» / «Подпроект «Веб»». Под ним `id` — при
создании «будет web (после создания не меняется)», при правке «web · не
меняется». `id` строится из имени (`slugifyRoleId`) и не редактируется.

| Поле | Элемент | Поведение |
|---|---|---|
| Название | текстовое поле | обязательное; пусто — красная рамка и «Назовите зону.» |
| Корень | поле + кнопка «Выбрать папку…» | диалог — тот же `pickfolder.ts`, что в мастере; руками тоже можно. Под полем подсказка «Определили: папка внутри репозитория офиса» / «отдельный репозиторий» |
| Вид | сегмент «Папка · Репозиторий» | вид определяет сервер по пути; сегмент переключается руками, только когда сервер вернул «неоднозначно» (путь вне репозитория офиса, но не корень git); иначе виден, но неактивен |
| Описание | текстовое поле | одна строка, её видит менеджер |
| Цвет | 8 свотчей `--accent-1..8` | занятые другими зонами — приглушены (`opacity .35`), но выбираемы: палитра на 8, зон может быть больше |
| Общие файлы | поле со списком путей через запятую | **только вид «Папка»**; для репозитория поле скрыто. Подсказка: «что вне корня можно менять задачам зоны» |
| Свои проверки слияния | свёрнутая секция | свёрнута с подписью «Общий набор офиса»; раскрыта — по команде в строке, «Добавить», «Вернуть общий набор» |
| Бриф и правила | две ссылки | «`web/OFFICE.md` — открыть» или «создать»; то же для `RULES.md` |

Низ формы: слева «Удалить…» (`danger`, только при правке), справа «Отмена» и
«Сохранить» / «Создать». Основная кнопка неактивна, пока есть ошибки.

### 1.3. Ошибки (макет 4)

Сервер проверяет инварианты (`spec.md` §2.1) и возвращает текст — форма
показывает его под полем, к которому он относится. Проверка — по blur поля
корня и при отправке, не по каждому символу.

| Где | Текст |
|---|---|
| Название | «Назовите зону.» · «Зона с таким названием уже есть.» |
| Корень пуст | «Укажите корень. Весь репозиторий — это «весь проект», не зона.» |
| Корень не найден | «Папка не найдена: `<путь>`.» |
| Вложенность | «Корень лежит внутри зоны «Сервер» (`server/`): вложенности нет.» и обратное «Внутри этого корня уже есть зона «Веб».» |
| Корень `..` / абсолютный у папки | «Папка зоны должна лежать внутри репозитория офиса.» |
| repo не корень git | «Это не корень git-репозитория. Корень: `<путь>`» с кнопкой «Взять его» |
| repo = репозиторий офиса | «Это сам репозиторий офиса — он и есть «весь проект».» |
| `sharedPaths` | «Путь `../x` выходит за репозиторий.» |
| Сеть / сервер | красная полоса над кнопками «Не сохранилось: `<текст>`. Повторить»; введённое не теряется |

Сервер недоступен целиком — раздел показывает общее «Нет связи с офисом»
вместо списка; форма не открывается.

### 1.4. Удаление (макет 5)

Модалка подтверждения. Удалить нельзя, пока у зоны есть **открытые задачи**:
кнопка неактивна, под заголовком красным перечислены задачи («4 открытые
задачи: T-451, T-460…» — ссылки на карточки). Если есть закреплённые роли,
жёлтая строка перечисляет их, а действие называется «Открепить всех и
удалить» (одно действие — spec §2.2). Закрытые задачи зоны остаются на доске с
серым бейджем «зона удалена».

### 1.5. Пустое состояние (макет 2)

По центру: «Подпроектов пока нет» / «Весь проект — одна зона: любой сотрудник
берёт любую задачу. Заведите зоны, если часть команды должна работать только с
бэкендом или только с фронтендом.» Кнопки «Что это даёт» (ссылка на
руководство) и «+ Добавить первый».

## 2. «Команда» и окно роли (макеты 6–7)

### 2.1. Карточка сотрудника

Под именем и ролью — ряд чипов зон (`--chip-h` 22 в карточке):
`[■ Сервер]`, цветной квадрат 8 px (цвет зоны) + название. Правила:

- нет закрепления → один серый чип «Весь проект» (`--ink-4`);
- больше трёх зон → три чипа и «+N», полный список в подсказке;
- менеджер: вместо чипов текст «видит все зоны» (его не закрепляют);
- зона удалена вручную, id остался в `state.json` → красная рамка чипа и
  строка «закреплена за несуществующей зоной — задач не получит»;
- у зоны есть `problem` → в чипе ⚠, подсказка с текстом проблемы;
- в офисе без подпроектов чипов нет вообще, как и поля в окне роли — старые
  офисы выглядят ровно как раньше;
- во вкладке «Маркет» закрепления нет: оно относится к офису, а не к пакету.

Закрепление относится к **роли** (spec §2.2): у «Фронтендера 2» свои чипы, и
экземпляры роли показывают те же.

### 2.2. Окно роли → поле «Подпроекты»

Вкладка «Роль», рядом с «Репозиторий роли». Мультивыбор: сверху чипы выбранных
с крестиками, под ними список «☐ Весь проект (пусто) · ☑ Веб · ☑ Сервер».

- Выбор «Весь проект» снимает все зоны и наоборот — взаимоисключающие.
- Зона с `problem` в списке есть, но подписана причиной и недоступна для
  новых закреплений (уже стоящая остаётся).
- Снятие зоны, у которой у роли есть задачи в `planned`/`backlog`:
  предупреждение до сохранения «N задач останутся без исполнителя» (жёлтая
  строка `--warn-ink`); сохранять можно — решение за человеком, офис потом
  отметит задачи `attention` (spec §3.3).
- Поле неактивно у менеджера с подписью «Менеджер видит весь офис».
- Подпись про влияние: «Роль получает задачи только этих зон. Чужой код
  читать может, менять — нет.»

## 3. Фильтр по зоне: доска, документы, лента (макеты 8–14)

Один и тот же компонент `ZoneFilter` на все три места: ряд чипов над
содержимым, `--chip-h` 28, переносится на вторую строку.

`[Все] [■ Сервер] [■ Веб] [Весь проект]`

- «Все» — по умолчанию; активный чип `--accent` с `--accent-ink`.
- Один выбор (не мультивыбор): три-четыре зоны — мультивыбор оправдан
  позже, если попросят. «Весь проект» — задачи и документы без зоны.
- Ряд **не показывается**, пока в офисе нет подпроектов; с одной зоной
  показывается — рядом есть «Весь проект».
- Состояние — веб, хранится по офису, как размеры окон (`routeSync` не
  трогаем). Единое на три места или своё у каждого? Предлагаю **своё у
  каждого экрана**: доска и документы отвечают на разные вопросы.
- Подпись в шапке экрана при активном фильтре: «Фильтр: Веб · 2 из 6 задач».

### 3.1. Доска

- Карточка задачи получает бейдж зоны: цветной квадрат + имя в `--film` пилюле
  (`10 px`). «Весь проект» — серый квадрат; у закрытой задачи удалённой зоны —
  «зона удалена».
- Бейдж не показывается в офисе без зон.
- Заголовок фичи показывает фильтр по своим задачам: фича, у которой после
  фильтра не осталось задач, скрывается; счётчики колонок считают отфильтрованное.
- Пустое состояние (макет 10): «В зоне «<имя>» нет задач» + «Задачи зоны
  появятся, когда менеджер заведёт их с этой зоной» + кнопка «Показать все
  задачи».
- Ничего не нашлось в одной колонке — как сейчас, дефис.

### 3.2. Документы

- Тот же ряд чипов; при фильтре зоны показываются документы зоны **и** основа
  проекта (`foundation` без зоны) — иначе зона без своих документов выглядела
  бы пустой, хотя читать есть что. Документы «Весь офис» показываются при чипе
  «Весь проект».
- Строка документа: название, тип, бейдж зоны (как на доске).
- Карточка документа: поле «Область» — выпадающий список «Весь офис» /
  зоны. Закреплённая роль чужую область не правит: поле только для чтения
  (владелец правит всё, spec §4.2).
- Диалог нового документа: выбор области; по умолчанию — активный фильтр,
  иначе «Весь офис».
- Пустое состояние (макет 12): «У зоны «<имя>» пока нет документов» + «Основа
  проекта и документы «Весь офис» остаются доступными — выберите «Все»» +
  «Показать все» и «+ Документ зоны».

### 3.2.1. Рабочие материалы задач

Наследуют зону задачи (spec §4.2), поэтому в фильтре попадают в зону задачи
без отдельных действий.

### 3.3. Лента и «Жизнь офиса»

- События задач и документов несут зону (бейдж справа). Записи без зоны
  (планёрки, лимиты, выпуски, вопросы владельцу) **видны всегда**: фильтр
  режет только то, у чего зона есть.
- Пустое состояние (макет 14): список общих записей остаётся, под ним «В зоне
  «<имя>» пока тихо» + «События её задач и документов появятся здесь».
- Лента — не источник правды, фильтр ничего не удаляет и не отмечает
  прочитанным.

### 3.4. Ошибки и загрузка

- Фильтр выбрал зону, которую удалили (другой клиент): чип пропадает, фильтр
  сбрасывается на «Все», тост «Зона «Веб» удалена — показано всё».
- Зоны ещё не пришли в снимок: ряд не рисуется, экран работает как без зон.
- Нет связи: экраны работают как сейчас, фильтр применяется на клиенте к уже
  загруженному.

## 5. Зоны в 3D-офисе (макеты 15–17)

**Только визуализация.** Зоны рисуются из `SubprojectView` и закреплений; ни
один клик и ни одно решение сервера от них не зависит. Выключили графику —
офис работает так же.

### 5.1. Что рисуется

1. **Участок пола** — плоская цветная плита поверх пола комнаты, цвет зоны
   (`--accent-N`), прозрачность 0.22 днём и 0.30 ночью (на тёмном полу нужна
   плотнее); без теней и без рельефа. Высота — 2 см над полом комнаты и
   1 см под сеткой `FloorGrid`, чтобы не мерцало (z-fighting, как разбирает
   комментарий к `FloorGrid`).
2. **Табличка** с именем — плоская надпись на полу у южного края участка
   (камера смотрит с юга, `Camera3D`), цвет зоны, текст `--accent-N-ink`. Видна
   при приближении (расстояние камеры меньше порога), издали остаётся
   цвет.
3. **Общий участок** — штриховка нейтрального цвета (`--film-3`) с табличкой
   «Общая»: там сидят универсалы и роли с несколькими зонами.
4. **Чипы зон над головой** — только у роли с несколькими зонами: маленькие
   цветные квадраты рядом с бейджем роли (`AgentAvatar`/`Agents3D`).
5. **Чипы камеры** — к существующим `CameraChips` («Опенспейс», «Переговорка»)
   добавляются чипы зон: наводят камеру на участок.
6. Столы **не двигаются**: рисуется поверх, раскладка и `deskIndex` в
   сохранении остаются как есть.

### 5.2. Откуда берутся участки: «с учётом текущей раскладки»

Раскладка (`Layout`) знает комнаты и столы, зон не знает. Участок — это
**прямоугольная полоса опенспейса**, вычисляемая из того, где стоят столы
закреплённых; новое поле в пресетах раскладок не нужно.

1. Берём комнату, где стоят рабочие столы (комната с наибольшим числом
   `desk`; в `studio_4/5/small/severance` это «Опенспейс» `open`). Стол
   менеджера (`desk_pm`) в зоны не входит.
2. Ось полос — вдоль **длинной стороны** рамки рабочих столов. В
   `studio_5` (24×16, два ряда по семь столов) рамка вытянута по X → полосы
   режут по колонкам (макет 15). В `studio_small` (опенспейс 8×16 по Y: два
   столбца, четыре ряда) → полосы режут по рядам (макет 16).
3. Зонам по порядку списка достаются подряд идущие полосы, ширина полосы —
   число закреплённых-только-за-ней, округлённое вверх до целой колонки (ряда)
   столов. Универсалы и мульти-зонные садятся в оставшуюся (общую) полосу;
   хвост — между зонами, чтобы общий участок оказывался в середине, где его
   видно с любой стороны.
4. Участок = рамка занятых полосой столов, расширенная на 0.5 тайла по
   сторонам и на 1 тайл у южного края под табличку; в стены и в чужую
   комнату не заходит (обрезается по `LayoutRoom.rect`).
5. Рассадка по полосам — дело `seating.ts`: **предпочтение**, а не требование.
   Нет свободных столов в своей полосе — человек садится в любой свободный, и
   участок тянется до него (рамка считается от фактических столов, а не от
   плана).

Откат: если после обрезки по комнате участок меньше 2×2 тайла, или зон больше
четырёх, или в комнате меньше четырёх столов — участки не рисуются, остаются
чипы зон над головой и чипы камеры. Ничего не ломается.

### 5.3. Состояния

| Состояние | Что видно |
|---|---|
| В офисе нет зон | как сейчас, ничего нового |
| Зона без закреплённых | участка нет; в легенде серый чип «Сервер · 0» |
| Фильтр зоны на доске включён | остальные участки гаснут до 35 %, столы и сотрудники не меняются |
| У зоны `problem` | участок штрихуется, табличка «Магазин API ⚠» |
| Графика выключена | ничего не рисуется |
| «Простая» графика | только цвет, без таблички и штриховки |
| Тёмная тема | цвета зон те же, прозрачность выше (0.30) |

Палитра 3D (`palette.ts`) получает цвета зон из тех же `--accent-1..8`,
отдельных значений для 3D не заводим — иначе их цвета разъедутся с бейджами
(история с тремя наборами цветов, `T-41`).

### 5.4. Легенда

Под сценой в нижней полосе — легенда зон: чип «■ Сервер · 3» (имя, число
закреплённых), общий — «▨ Общая». Нужна, потому что табличку издали не
прочесть. Клик по чипу наводит камеру (§5.1, п. 5). Она — часть сцены, не
HUD.

---

## 6. Что заведомо не делаем

- Перетаскивание зон по полу и ручное рисование участков.
- Клик по участку как действие (фильтр, назначение).
- Мультивыбор в фильтре зоны.
- Деньги по зонам (spec §10, вопрос 6).
