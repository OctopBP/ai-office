# Офис в 3D: где мы и что дальше

Передача дел между сессиями. Ниже — состояние ветки `feat/office-3d` и
решение, принятое в конце последней сессии.

---

## Что уже сделано

Ветка `feat/office-3d` (воркtree `.claude/worktrees/office-3d`), 30 коммитов
поверх `main`. Трёхмерный офис доведён до паритета с плоским и обогнал его.

- Комната из данных раскладки: пол, стены, проёмы, окна.
- Перспективная камера 25° с облётом; ближние стены гаснут.
- Мебель — модели Kenney «Furniture Kit» (CC0, `design/models/furniture`,
  140 предметов в репозитории). Стол, стул, монитор, диван, кресло плюс
  первая партия декорации лаунжа.
- Агенты — персонаж Kenney, оригиненный в Mixamo, с набором поз: ходьба,
  покой, разговор, печать, сидячий покой, сидячий разговор, игра и четыре
  клипа переходов между стоя и сидя.
- Система занятий (`src/web/interests.ts`): разговоры парами по очереди,
  игра вдвоём на диване, одиночные места, распад пары при уходе собеседника.
- Подписи агентов, кольца состояния, выбор кликом, таблички задач.
- Редактор расстановки: перетаскивание мышью, поворот колесом, сетка
  привязки, метки посадочных мест.
- Хотспоты (доска, лог), дверь, метки свободных мест.

Плоский офис (`src/web/Office.tsx`) заморожен, но работает: переключение
клавишей `0`, в 3D по умолчанию.

## Решение, принятое в конце сессии

**Комнату дальше собирает человек в Blender, а не код из JSON.**

Причина: последние часы ушли на подбор координат вслепую — «сдвинь стул на
десять сантиметров, пересобери, посмотри». В 3D-редакторе это два движения
мышью. Заодно отпадают вопросы «куда развёрнута модель», «где у неё начало
координат», «какой у неё след» — в сцене они уже отвечены.

Unity отвергнут: его сцену наш клиент не читает, а Unity WebGL означал бы
переписать весь интерфейс (HUD, доску, чат, панели). Blender → glTF
оставляет клиент как есть.

**Пресеты остаются**: офисов может быть несколько, сцена грузится по имени
из настроек — как сейчас грузится раскладка.

## Что это заменит

- Тайловые раскладки `design/layouts/*.json` — геометрия переезжает в сцену.
- Каталог габаритов, `src/web/office3d/props.ts`, `MODEL_SCALE`, центровку
  моделей, угадывание разворотов, поле `seat`. Всё это существует только
  потому, что комната собирается из данных.
- Редактор расстановки в приложении — редактором становится Blender.
- Плоский рендер — окончательно.

Не трогается: сервер, состояние офиса, задачи, агенты, ходьба (`findPath`),
занятия, подписи, хотспоты как поведение.

## Договорённость о формате сцены

Пустышки (empty) в Blender приезжают в glTF обычными узлами; их custom
properties — в `extras`. Читаются `GLTFLoader` как есть.

Предложенные имена (уточнить в новой сессии):

```
seat.work        рабочее место за столом
seat.game        место у приставки
seat.sit         просто посидеть
spot.talk        точка разговора (ось — из поворота пустышки)
zone.idle        зона отдыха
hotspot.board    доска задач
hotspot.log      экран лога
door.exit        выход в список офисов
walkable         меш проходимой области
```

Поворот пустышки задаёт, куда смотрит сидящий.

**Открытый вопрос — проходимость.** Сейчас это тайловая сетка из следов
мебели, по ней ходит `findPath`. Варианты: (а) плоский меш `walkable` в
сцене, по нему строится сетка; (б) прямоугольники-коллайдеры. Решить в
новой сессии.

## Первый шаг

Не собирать весь офис. Собрать **одну комнату** (лаунж), положить диван,
кресло, столик и три-четыре пустышки, экспортировать glTF, проверить
формат на маленьком. Параллельно написать загрузчик сцены.

## Как запускать

```bash
npm run dev:3d
```

Поднимает изолированный экземпляр: сервер на 3002 со своим файлом
состояния, веб на 5174. Обычный `npm run dev` полезет на 3001 — к рабочему
офису.

## Грабли, на которых уже посидели

- **StrictMode дважды вызывает фабрики `useMemo`.** Фигура, микшер и
  действия анимации должны создаваться одним мемо, иначе разъезжаются.
  Запуск анимации — только в эффекте, иначе после пробного размонтирования
  её никто не перезапустит.
- **Много точек `Suspense` в дереве r3f не поднимают сцену.** Модели грузятся
  одной точкой на всю комнату и раздаются контекстом.
- **`resolve.dedupe: ['three']`** обязателен: загрузчики из
  `three/examples/jsm` тянут вторую копию библиотеки, и `instanceof`
  перестаёт работать молча.
- **Панель браузера у агента не измеряет контейнер** без изменения размера
  окна: канвас остаётся 300×150, сцена пустая, ошибок нет. Лечится ресайзом.
- **`gen.py` перерисовывает PNG побайтово иначе.** После правки каталога:
  `python3 design/sprites/gen.py && git checkout -- design/sprites/out/day
  design/sprites/out/night`.

## Сделано после записки (26 августа)

**Комната перенесена в Blender автоматически.** Начинать сцену с пустого файла
незачем: всё, что уже стоит в офисе, переехало туда скриптом и один раз.

```
tools/blender/office_layout.py   раскладка → геометрия: порт geometry.ts и props.ts
tools/blender/build_scene.py     сборка сцены в Blender (запускается им же)
tools/blender/inspect_glb.py     что на самом деле уехало в glTF
scripts/scene.sh                 npm run scene -- studio
design/scenes/studio.blend       сцена: комната, мебель, маркеры, проходимость
design/scenes/studio.glb         выгрузка для клиента
design/scenes/studio.png         кадр сцены — посмотреть, не открывая Blender
```

Скрипт одноразовый и умрёт вместе с раскладками: он нужен ровно чтобы не
расставлять сорок предметов заново руками.

В файле четыре коллекции: `Room` (пол, стены, окна), `Props` (мебель моделями
набора), `Markers` (пустышки), `Nav` (`nav.walkable`). Свет и камера лежат
отдельно и в glTF не уезжают.

**Формат сцены описан:** `docs/design/office-3d/scene-format.md` — оси, имена
пустышек, три правила, без которых сломается, и решение про проходимость
(меш, не коллайдеры). Имена там отличаются от предложенных в этой записке в
трёх местах, каждое с причиной; согласовать до того, как писать загрузчик.

**Загрузчик ещё не написан** — он весь состоит из этих имён, и писать его до
их утверждения значит переписывать.
