# Ссылки на файлы в чате с PM: как устроено сейчас

Разбор по коду на 2026-10-21 (ветка task/T-663, код не менялся). Выведено из чтения кода; клики и тесты не гонялись. Номера строк сверены 2026-10-21. Копия документа D-9 из библиотеки офиса.

## Коротко

- Отдельной схемы `file:` **нет**. Файл в реплике — это обычный **относительный путь** (`docs/design/T-189/ui.md`), голое имя с известным расширением (`ui.md`) или markdown-ссылка с относительным адресом `[подпись](docs/x.md)`. Веб сам находит их в тексте реплики.
- Клик открывает **окно просмотра внутри приложения** (не вкладку, не `<a href>`). Файл читает сервер: `GET /api/file`.
- Схема `chat:<id>` — единственная «внутренняя» схема в Markdown. Схемы для документов библиотеки (`D-N`) **нет**.
- Файлы из ветки/worktree задачи открываются, если реплика привязана к задаче (`T-N`): сервер ищет сначала в рабочей копии, потом в ветке, потом в коммите слияния, потом в main.

## 1. Что видит пользователь

1. В реплике PM/исполнителя путь выглядит как пунктирная ссылка (`.md-file`, `title` «Открыть файл в приложении»; ключ `fileLink.open`).
2. Клик (или Enter/Пробел — это `role="button"`, `tabIndex=0`) открывает окно `FilePreview` поверх интерфейса: заголовок — найденный путь, ссылка «Скачать», закрытие крестиком, Esc и кликом по подложке.
3. Тело окна — те же просмотрщики, что у результата задачи (markdown, текст, картинка, PDF, 3D-модель, «другое»).
4. Файла нет — «Файл не найден» с подсказкой: либо «нет в основной ветке проекта», либо «нет ни в работе задачи T-N, ни в основной ветке».
5. Путь `*.figcraft` — окно не открывается, вместо этого запускается FigCraft (см. §5).
6. Чип `chat:<id>`: иконка сообщения и актуальное название чата из стора; клик — открывает чат и переключает вид на «чат». Удалённый чат — приглушённый чип с подсказкой «Чат не найден».

## 2. Веб: где что разбирается

| Что | Где |
|---|---|
| Свой Markdown-разбор (без библиотек и без HTML) | `src/web/Markdown.tsx` |
| Схема `chat:` — регэксп `CHAT_HREF` | `src/web/Markdown.tsx:24`, компонент `ChatLink` `:33`, ветка в `inline()` — строка с `CHAT_HREF.test(m[6])` |
| Markdown-ссылка с относительным путём → файл | `src/web/Markdown.tsx`, ветка `fileHref(m[6], files.scan)` в `inline()` |
| Остальные ссылки: только `https?:` и `mailto:` (`safeHref`), остальное — просто текст (`javascript:` и т. п. отсекаются) | `src/web/Markdown.tsx:62`, `link()` — `<a target="_blank" rel="noreferrer noopener">` |
| Пути в обычном тексте и инлайн-коде | `withFiles()` в `Markdown.tsx` → `splitFilePaths()` в `src/web/chat/filePaths.ts` |
| Регэксп путей `PATH`, список расширений для голых имён `BARE_EXTENSIONS` | `src/web/chat/filePaths.ts:41, :12` |
| Привязка реплики к задаче: первая `T-N` в тексте | `mentionedTask()` в `filePaths.ts:113`; применяется в `ChatThread.tsx:128,145`, `QuestionCards.tsx:183`, `ChatCards.tsx:331` |

| Адрес запроса | `projectFileUrl()` в `src/web/result/api.ts:35` → `/api/file?office=…&path=…&task=…&base=…` |
| Блок «Результат» (список `files` из вопроса владельцу) | `src/web/chat/ResultFiles.tsx` (использует тот же `FileLink`) |

Подробности разбора путей:
- Путь с каталогами — любое расширение (`src/x/y.ts`); голое имя — только из `BARE_EXTENSIONS` (md, txt, json, png, jpg, jpeg, webp, gif, svg, pdf, glb, gltf, figcraft), чтобы «Node.js» не стал файлом.
- Не считаются файлами: абсолютные пути, `~/…`, пути сразу после `:`/`@`, адреса со схемой `://`, `www.site.com/a.md`.
- Голое имя ищется в каталоге **ближайшего предыдущего пути** той же реплики (`PathScan.dir`, параметр `base`), потом в корне.
- Блоки кода (```` ``` ````) не трогаются; в подписи markdown-ссылки пути не ищутся.
- Файловые ссылки включены **только** там, где передан `files` у `<Markdown>`: ChatThread (чат с PM, включая черновик-стриминг), QuestionCards, ChatCards. Остальные места — `LifePanel`, `TaskDrawer` (описание, результат, отчёты), `PrPipeline`, `MeetingsPanel`, документы библиотеки (`DocView`) — показывают путь **просто текстом**.

## 3. Сервер: как отдаётся файл

`src/server/files.ts` (подключён в `src/server/index.ts:308`, маршрут `GET /api/file`).

- Проверка пути `cleanPath` (`files.ts:43`): относительный, без `..`, без `.git`, без `.env*`; обратные слеши приравнены к `/`; абсолютные пути, диски Windows и UNC — отказ.
- Для диска — `realpathSync` и проверка, что настоящий путь внутри корня (символические ссылки наружу не работают) — `diskSource` `:102`.
- Лимит размера — `RESULT_FILE_MAX_BYTES` (`taskfiles.ts`); отказ по размеру окончательный.
- Офис должен быть открыт (`isOpened`), иначе 503; неизвестная задача — 404.
- Заголовки: `X-Office-File-Source` (`worktree|branch|delivery|main|disk`), `X-Office-File-Path`, `Cache-Control: no-store` для worktree/disk.

### Файлы, которых нет в main (ветка/worktree задачи)

Без параметра `task` читается **только** основная ветка репозитория офиса (`readProjectFile`, `files.ts:174`). С `task=T-N` источники по порядку (`taskSources`, `files.ts:150`):
1. рабочая копия задачи (`task.worktreePath`, если жива) — в том числе незакоммиченные правки;
2. ветка задачи (`git`-коммит ветки);
3. коммит слияния (`task.delivery.commit`) — после слияния ветку удаляют;
4. основная ветка репозитория задачи (`taskRepo`).

Следствия:
- Пока задача идёт или на ревью — файл виден из worktree, свежая версия; после слияния — из коммита слияния/main; ветка снятой задачи, если её ещё не убрали уборкой, — из ветки.
- Если в реплике нет `T-N` (или номер из другого офиса/опечатка), веб не передаёт `task` (в `FileLink` `known ? task : null`), и файл, которого нет в main, покажет «Файл не найден».
- Привязка берётся из **первой** `T-N` в реплике, а не из задачи, о которой реплика на самом деле. Реплика про две задачи откроет файлы второй не оттуда.
- Агенты никак специально не «отправляют» ссылки: нет инструмента или формата для файловой ссылки. Нашёл ли PM/исполнитель нужный путь и упомянул ли он `T-N` — зависит от текста реплики. Единственный явный формат в промптах — `[Название](chat:<id>)` (`src/server/agents.ts:732`, `chatLink`; в промптах `prompts-ru.ts:1259`, выдаётся `list_chats`/`open_chat`). Файлы идут в вопрос владельцу полем `files` (путь, главный `.md` первым) и в `finish_task` (`files`, `agents.ts:2957`).

## 4. Браузер и Electron

- Клик по файловой ссылке — **не навигация**: `preventDefault`, окно офиса поверх, запрос `fetch('/api/file…')` к тому же серверу. Поэтому в браузере и в Electron поведение одинаковое; на `chat:`-чипе то же.
- Electron (`desktop/main.js:157-166`): `setWindowOpenHandler` и `will-navigate` отправляют любые внешние `http(s)`-адреса в системный браузер (`shell.openExternal`), всё остальное запрещается. Для файловых ссылок это не задействуется. «Показать в Finder/Проводнике» и открытие файла системной программой для обычных файлов **не реализованы**.
- Скачивание — обычная ссылка `<a download>` на тот же адрес.
- Открытый наружу офис: `/api/file` отдаёт файлы тому, кто допущен к офису, как и остальной API; отдельной привязки к машине нет (в отличие от FigCraft).
- `localhost` и `127.0.0.1` — разные origin: запрос `/api/file` относительный, ему это не мешает, но настройки веба в хранилище браузера разойдутся.

## 5. Сравнение: FigCraft

`src/server/figcraft.ts`, веб — `src/web/result/figcraft.tsx`.
- Ссылка на `*.figcraft` в чате ведёт в `openFigcraftRef` (`figcraft.tsx:117`): запрашивает `GET /api/figcraft/files?task=T-N` (живая копия или файлы слияния, либо main), находит запись по пути, концу пути или имени и шлёт `POST /api/figcraft/open` с абсолютным путём.
- Сервер запускает приложение FigCraft **на машине сервера** (`spawn` без шелла). Допуск (`openAccess`, `figcraft.ts:~350`): запрос только с loopback без прокси-заголовков, если офис открыт наружу; чужой `Origin` — отказ; путь только `.figcraft` внутри папки офиса или копии задачи.
- Это единственный случай, когда клик запускает программу на машине сервера. Для остальных файлов такой возможности нет.

## 7. Ограничения и пробелы

1. **Нет документации** (см. §6): ни спеки, ни раздела в guide; этот документ — единственное описание.
2. **Схемы `file:` нет.** Ссылку `[x](file:docs/a.md)` или `[x](/abs/path)` Markdown не считает файлом: `fileHref` отсекает любую схему и абсолютный путь, `safeHref` — всё кроме http(s)/mailto; рендерится **простым текстом без ссылки**.
3. **Нет ссылки на документ библиотеки (`D-N`).** В Markdown нет разбора `D-5` или `doc:D-5`; `D-N` — просто текст. Есть только `ID_RE` на сервере (`src/server/docs.ts:42`) и окно документов; перехода из реплики нет.
4. **Привязка к задаче по первой `T-N`** в реплике; без неё файлы веток недоступны. Нет явного синтаксиса вида `[подпись](docs/x.md?task=T-5)`.
5. **Файловые ссылки включены не везде** (LifePanel, TaskDrawer, PrPipeline, MeetingsPanel, документы — путь остаётся текстом).
6. **Авторы не знают о формате.** В промптах нет требования писать пути относительными от корня репозитория, с каталогом, и упоминать `T-N`; голое имя ищется только рядом с предыдущим путём реплики.
7. **Края регэкспа `PATH` (`filePaths.ts:41`).**
   - Номер строки: в `src/a.ts:10` ссылкой становится `src/a.ts`, потому что после совпадения запрещены только `\w`, `/`, `\`, `-` и «`.`+буква» (`:` не запрещён). Клик откроет файл целиком, `:10` останется обычным текстом рядом и никуда не прокрутит.
   - Перед путём `:` запрещён (lookbehind), поэтому `file:src/a.ts` и `см.:src/a.ts` ссылкой не станут; так же `~/…`, абсолютные пути и путь после `@`.
   - Путь с пробелами файлом не считается: ссылкой может стать только его часть без пробела, если она сама похожа на путь.
   - Голое имя с неизвестным расширением (`a.ts`, `Makefile`) не ссылка; путь с каталогом — ссылка при любом расширении до 8 символов, в том числе не-файлы вроде `and/or.ok`.
   - Не проверялось запуском; выведено из регэкспа.
8. **Нет «показать в папке»/«открыть в системе»** и нет открытия в редакторе; Electron для этого ничего не делает.
9. **Файлы вне репозитория/офиса** (`~/Downloads/x.png`, скриншоты вне worktree) недоступны по дизайну (безопасность).
10. **Ветка убрана уборкой и нет коммита слияния** (снятая/проваленная задача старше `cleanupDays`) → файл исчез, окно покажет «не найден».
11. **Нет автотестов** на `filePaths.ts` и `files.ts` (по поиску тестов с `splitFilePaths`/`readProjectFile` нет; рядом есть `scripts/test-taskfiles.ts` для результата задачи).
12. **Файловые ссылки не привязаны к офису**, если реплика пришла из другого офиса: `officeQuery()` берёт текущий офис вкладки.
