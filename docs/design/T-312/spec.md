### 5.1 TaskCard (реф `task`)
Тона: в очереди (`planned/backlog/assigned/blocked`: «в плане», «бэклог», «назначена», «заблокирована») — muted; «в работе» / «на проверке» — accent; «готово» не влитой — accent (ok, если конвейер выключен или задача закрыта); «влито» — ok; «провал» — danger; «снята» — muted. Мета: чип важности (если не normal; у normal показывается только на hover, в конце строки) · чип статуса · чип стадии конвейера (`pr.stage`: подтягиваю main / проверки / открываю PR / на ревью / доработка / вливаю — accent; встало — danger; при `merged` нет) · `AgentTag` исполнителя · «N из M» критериев. Ниже — компактный `BudgetStopBanner` при остановке по бюджету (файл не разбирался — на макете показать как опциональную полосу). Шеврон — только если есть фича или зависимости; раскрытие: чип «F-9 · название» + «ждёт T-104, T-107», заголовок переносится. Клик по карточке открывает дровер задачи.
Варианты для компонента: в очереди / в работе (+стадия) / влито / провал / снята / развёрнутая / с бюджетным баннером.

### 5.2 EpicCard (реф `epic`)
Шапка: заголовок-ссылка (id в плашке: planned — `--film`/`--ink-3`, active — accent 14%/accent, done — ok 14%/`--ok-ink`) + название + чип статуса («в плане», «в работе», «готова», «снята»). Далее — цель (`--ink-3`, 2 строки), мета «N из M» · «$X.XX» · «ждёт вашего согласия» (не согласована) / «ждёт очереди» (согласована). В «в работе» — до 4 строк задач (точка 6px: run accent, wait `--ink-4`, fail `--board-fail`, done `--board-done`, drop `--board-drop`; id + название) и «и ещё N». Без согласия — кнопка `.merge` «Поехали». «Готова»: одна строка «Готова: N из M задач · $X.XX», вся карточка приглушена (opacity .55 на заголовке/статусе/мете). «Снята»: только шапка, название `--ink-3`.

### 5.3 QuestionCard (реф `question`)
Шапка: чип-бейдж + «{кто} · вопрос по {T-id-ссылка} · {время}» (11px, `--ink-3`; без задачи — «вопрос»; время с датой, если не сегодня). Бейдж: «ждёт ответа» (warn на warn 14%), «отвечен» (`--ok-ink`), «снят» (muted), «объединён с {id}» (muted). Текст (`--ink`, Markdown, перенос), под ним (11px muted) «Офис исходит из: …» / «Офис исходил из: …», файлы результата (`ResultFiles`). Ждёт ответа: ряд кнопок-вариантов `.mini` (2–4; вариант с «…» на конце заготавливает ввод) + ссылка «Ответить своими словами →» (11px, `--accent`). Режим ввода (свои слова или нет вариантов): поле + кнопка «Ответить» (`.allow`), плейсхолдер «Ваш ответ — он ляжет в журнал офиса». Отвечен: ответ зелёным 500 под текстом. Закрытый вопрос свёрнут по умолчанию (одна строка с эллипсисом, `--ink-2`; шеврон справа), развёрнут — полный текст и «исходил из».

1. **Пустой чат** — два случая: (а) вообще нет чатов (`pmChats.empty`): по центру ленты карточка 420 макс. ширины, паддинг 24, surface+hairline+radius 12, 💬 28px, «Чатов пока нет», пояснение «Начните разговор с менеджером. 2. **PM отвечает** — `msg-draft` в двух фазах: «печатает…» и частично набранный текст с курсором.
3. **Длинная лента** — несколько суток с разделителями дня; реплики владельца и PM; группа из 3 задач; фича «в работе»; вопрос с вариантами; событие «влито»; события «встал»; свёрнутый отвеченный вопрос. Лента прокручивается, держится у низа, пока пользователь не уйдёт вверх (порог 48px).
4. **Композер с текстом** — многострочный ввод (до 160px высоты), кнопка отправки активна; рядом — вариант без текста (кнопка неактивна) и вариант с плашкой «нет провайдера».
5. Список чатов: обычный / с активным / с непрочитанным / «ждёт вас» / поиск без результатов / архив раскрыт / редактирование названия (инпут на месте названия) / открытое меню `⋯`.

### Расхождения кода с каталогом T-126 (верен код)

1. **Видов карточек в коде пять:** `task`, `epic`, `plan` (обёртка фич), `question`, `event`. Карточек «выпуск» и «ссылка на другой чат», упомянутых в постановке T-312, **нет ни в каталоге, ни в коде** (`ChatRef` их не содержит). Не нарисованы.
2. **Группа задач и группа фич — разные обёртки:** код: «Менеджер создал задачи: N» (`chatCard.group.tasks`) и «Менеджер завёл фичи: N» (`group.plan`), фича+задачи одной обёрткой не собираются; каталог §5 описывал «фича сверху + задачи под ней» в одной.
3. **Вопрос: четыре состояния, не три** — добавлено «объединён с {id}» (`merged`). Закрытые вопросы в ленте **свёрнуты по умолчанию** с шевроном (каталог: шеврона у вопроса нет). Есть блок «Офис исходит из: …» и файлы результата — в каталоге нет.
4. **Событие «встал»** показывает причину (`why`) второй строкой; в каталоге причины не было. Ссылка — `T-id` без «Т-» кириллицей (в каталоге опечатка «Т-119»).
5. **Задача:** в коде нет отдельной стадии «готово» для ревью — статус `done` без влития и при выключенном конвейере окрашивается как ok/accent по `taskClosed`. Чип важности `normal` показывается на hover в конце строки (каталог говорил «виден в компакте, но кликабелен» — по сути то же, уточнено). Добавлен `BudgetStopBanner` — в каталоге нет.
6. **Фича «снята»:** показывает только шапку и чип, без слова «Снята» отдельной строкой. «Готова: N из M задач · $X.XX» — как в каталоге, но вся карточка приглушена.
7. **Сворачивание группы:** от 5 карточек, видны 3 (`GROUP_FOLD=5`, `GROUP_PEEK=3`); каталог говорил «от пяти» без числа показанных.
8. **Запасная карточка** `Missing` («{id} на доске больше нет») в каталоге не описана.
9. **Раздел §6 каталога** («Ссылки на Figma») — там тоже ничего не собрано; та же причина.
