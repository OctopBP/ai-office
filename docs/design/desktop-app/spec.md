# Спека: офис как приложение для macOS и Windows

Офис скачивается файлом, ставится двойным щелчком и открывается иконкой — без
терминала, git clone, `npm ci` и разговора про Node 22. Внутри тот же сервер и
тот же веб, что и сейчас; меняется только способ доставки и то, откуда
приложение берёт чужие части — движок Claude Code и git.

Состояние: фаза 1 реализована (2026-09-21), см. §8.

Родственные документы:
- `docs/guide/running.md` — запуск из исходников, переменные окружения;
- `docs/design/office-setup/spec.md` — мастер нового офиса, первый экран после установки;
- `docs/guide/architecture.md` — как устроен сервер и изоляция задач.

---

## 1. Чем плохо сейчас

Офис запускается из репозитория: `git clone`, `npm ci`, `npm run office`,
браузер на `localhost:3001`. Это нормальная цена для того, кто правит сам офис,
и запретительная для всех остальных: человеку, который хочет поставить задачу
команде агентов, предлагают сначала стать разработчиком этого проекта.

Мешает ровно четыре вещи, и ни одна не про графику:

1. **Нет исполняемого файла.** Сервер живёт в TypeScript и запускается через
   `tsx`, статика — из `dist` относительно текущей папки.
2. **Состояние пишется в текущую папку** (`.office/state.json`). У приложения
   текущей папки нет — точнее, она случайна.
3. **Движок агентов — чужой нативный бинарь.** `@anthropic-ai/claude-agent-sdk`
   не работает сам по себе: он запускает `claude` весом ~310 МБ, который
   приезжает отдельным npm-пакетом под платформу.
4. **Windows никто не проверял.** Запуск завязан на bash-скрипты, часть кода
   зовёт `/bin/sh`, а git на Windows не предустановлен вовсе.

---

## 2. Решение: Electron вокруг того же сервера

Приложение — это Electron: окно на Chromium и Node внутри. Выбор не про моду, а
про три факта: сервер уже на Node и дёргает процессы, 3D-сцена уже проверена на
Chromium, а установщики, подписи и автообновление у electron-builder штатные.
Системный webview (Tauri) экономил бы ~140 МБ, но сервер всё равно пришлось бы
класть рядом отдельным бинарём, а сцену и шрифты проверять на двух разных
движках.

```
Приложение (Electron)
├─ main               окно, меню, пути данных, первый запуск
│  └─ utilityProcess  сервер офиса (тот же src/server, собранный в один JS)
│     └─ spawn        claude (движок), git (worktree, слияния)
└─ renderer           тот же веб из dist, по http://127.0.0.1:<порт>
```

Сервер живёт **отдельным процессом**, а не внутри main. Так падение сессии
агента не уносит окно, перезапуск офиса не требует перезапуска приложения, и
поведение остаётся тем же, что при `npm run office`, — один процесс, один порт.

Порт выбирает main (свободный из эфемерных) и передаёт серверу в `OFFICE_PORT`;
слушаем только `127.0.0.1`, чтобы офис не оказался открыт в сеть.

## 3. Что приложение приносит с собой, а что берёт снаружи

| Часть | Вес | Откуда |
|---|---|---|
| Electron + сервер + веб | ~200 МБ | в установщике |
| Движок `claude` | ~310 МБ | ставится при первом запуске |
| git | 0 / ~50 МБ | macOS — системный; Windows — вшитый MinGit |

**Движок не вшивается в установщик.** Бинарь `claude` — проприетарный, «all
rights reserved»: класть его внутрь Apache-2.0 приложения и раздавать со своих
релизов нельзя. Поэтому приложение при первом запуске либо находит уже
поставленный Claude Code, либо предлагает скачать его официальным установщиком
Anthropic в свою папку данных. Цена решения честная: первый запуск требует сети
и нескольких минут.

**git на Windows вшивается.** MinGit — сборка Git for Windows под встраивание,
~50 МБ, GPL, распространять можно. Без него приложение на чистой Windows не
сделает ни одной задачи: вся изоляция стоит на worktree. Системный git при этом
не трогается — свой лежит внутри приложения и подставляется только офису.
На macOS git приходит с Command Line Tools и почти всегда уже есть; если нет —
проверка окружения говорит, что поставить.

## 4. Где лежат данные

Всё, что приложение пишет о себе, уходит в папку данных пользователя
(`app.getPath('userData')`), а не в папку программы:

```
macOS:   ~/Library/Application Support/AI Office/
Windows: %APPDATA%\AI Office\
├─ office/state-<id>.json   состояние офисов
├─ office/offices.json      реестр офисов
├─ engine/                  скачанный движок claude
└─ settings.json            ключ доступа, язык, последний офис
```

Журналы — в системной папке журналов (`app.getPath('logs')`):
`%APPDATA%\AI Office\logs\` на Windows, `~/Library/Logs/AI Office/` на
macOS. `server.log` — вывод серверного процесса, `main.log` — главный процесс
(запуск, движок, видеокарта, ошибки страницы офиса). Больше 5 МБ — при старте
уезжает в `.old`.

Рабочие папки проектов при этом остаются там, где их выбрал человек; по
умолчанию — `~/Office`, как и сейчас.

Пути передаются серверу переменными окружения (`OFFICE_STATE_FILE`,
`OFFICE_DIST_DIR`, `OFFICE_PORT`, `OFFICE_CLAUDE_BIN`, `OFFICE_GIT_BIN`), а не
новым способом настройки: переменные уже есть, ими пользуются тесты, и второй
механизм развёл бы поведение приложения и запуска из исходников.

## 5. Первый запуск

До окна офиса — окно ожидания: без него человек смотрел бы на белый экран,
пока поднимается сервер, а при отсутствии движка — на офис, который молча не
берёт задачи.

1. **Движок.** Ищем `claude` по порядку: `OFFICE_CLAUDE_BIN`, своя папка
   данных, `~/.local/bin` (куда кладёт официальный установщик Anthropic),
   пакет рядом с SDK, PATH. Нашли — строчка «Движок на месте». Не нашли —
   вопрос с двумя кнопками: «Скачать» тянет из npm ровно ту версию, под
   которую собран SDK, с проверкой контрольной суммы и видимым прогрессом;
   «Потом» пускает в офис без движка.
2. **Сервер.** Свободный порт на петле, запуск, ожидание ответа. Не ответил
   или упал — экран ошибки, а не пустое окно.
3. **Окно офиса.** Под присмотром: не загрузилось (`did-fail-load`, 45 с без
   ответа), процесс окна упал, сервер завершился сам, или через 20 с после
   загрузки `#root` пуст — окно ожидания становится экраном ошибки: причина,
   путь к папке журналов, «Открыть журналы», «Перезапустить офис», «Выход»
   (T-187: на Windows человек видел только чёрное окно).

Видеокарта: упал GPU-процесс — в папке данных появляется отметка `gpu-off`,
и следующий запуск идёт без аппаратного ускорения (руками — переменная
`OFFICE_DISABLE_GPU=1`; удалить файл — вернуть ускорение). Без WebGL веб
показывает вместо 3D-комнаты пояснение, остальной интерфейс работает.

Дальше человек попадает в обычное меню офисов, а если движка так и нет —
проверка окружения (`envcheck.ts`, id `engine`) держит задачи и говорит, что
сделать. Экран ожидания её не заменяет: окружение меняется мимо приложения, и
единственный честный способ узнать о нём — сходить и посмотреть заново.

Доступ к модели приложение пока не спрашивает: подписка подхватывается из
`~/.claude`, ключ берётся из окружения. Поле для ключа — фаза 2.

## 6. Что в коде мешало и что с этим делается

| Место | Было | Стало |
|---|---|---|
| `src/server/index.ts` | `dist` от `process.cwd()` | `OFFICE_DIST_DIR`, иначе как было |
| `src/server/index.ts` | порт 3001 жёстко | `OFFICE_PORT=0` → свободный, печатается реальный |
| `src/server/checks.ts` | `/bin/sh -lc` | на Windows `cmd.exe /d /s /c` |
| `src/server/git.ts` | `git` из PATH | `OFFICE_GIT_BIN`, иначе из PATH |
| `src/server/agents.ts`, `bench.ts` | `query` из SDK напрямую | обёртка `src/server/engine.ts` подставляет путь к движку |
| `src/server/offices.ts` | имя офиса через `split('/')` | `basename` — на Windows разделитель другой |
| `src/server/mcp.ts` | свой mcp-сервер запускался `node` | в каталоге по-прежнему `node`, на запуске — то, чем node является здесь |
| шесть файлов сервера | у каждого свой `ROOT` от `import.meta.url` | один `src/server/root.ts`, переопределяется `OFFICE_ROOT` |

Сервер собирается в один файл (`esbuild`, цель Node 22) — `npm run build:server`.
Внешним остаётся только `@anthropic-ai/claude-agent-sdk`: он ищет свой нативный
бинарь относительно собственного файла, и бандлить его — значит ломать поиск.

## 7. Сборка и выпуск

`electron-builder` из `desktop/`:

- macOS — `.dmg` и `.zip` под arm64 и x64 (universal не делаем: движок и так
  ставится отдельно, а двойной вес Electron ни к чему);
- Windows — `.exe` (NSIS) под x64.

Выпуск — по тегу `v*` в GitHub Actions: macOS собирается на `macos-latest`,
Windows на `windows-latest`, артефакты уезжают в черновик релиза. Черновик, а
не готовый релиз: Windows-установщик надо открыть руками, прежде чем его
кто-то скачает.

Подпись macOS включается наличием сертификата в окружении сборки, а не
правкой конфига: `desktop/builder.config.js` смотрит на `CSC_LINK`
(секрет сборки) или `CSC_NAME` (связка ключей), и вместе с сертификатом
включает защищённую среду исполнения и нотаризацию. Поэтому конфиг —
код, а не yml: выразить «подписывать по-разному в зависимости от окружения»
списком полей нельзя, а разница тут не косметическая (см. ниже).

Пока сертификата нет, первый запуск требует «Открыть» из контекстного меню на
macOS и «Подробнее → Выполнить» на Windows. Но
**macOS-сборка всё равно подписывается — «для себя» (`identity: '-'`)**, и это
не формальность: Electron приезжает подписанным ad-hoc, сборщик кладёт внутрь
ресурсы офиса, печать перестаёт сходиться, — и приложение, скачанное браузером
(то есть с карантином), macOS объявляет **повреждённым**, без варианта
«открыть всё равно». Именно так выглядел выпуск 0.1.0 с первой попытки:
сборка зелёная, файл скачивается, открыть нельзя. Защищённая среда исполнения
при этом выключена — без нотаризации она ничего не даёт, а ad-hoc подписи
мешает.

### Выпуск и автообновление

Обновлятор (electron-updater) берёт новые версии из GitHub Releases
репозитория `OctopBP/ai-office` — это поле `publish` в
`desktop/builder.config.js`. Оно вшивается в приложение при любой сборке,
поэтому задано всегда, а не только при публикации.

**Версия** берётся из `package.json`: electron-builder читает
`desktop/package.json`, офис показывает корневой. Перед выпуском поднимите
версию в обоих — режим публикации откажется работать, если они разошлись.

**Как собрать и опубликовать:**

```
npm ci && npm ci --prefix desktop
npm run build
GH_TOKEN=… node scripts/pack-desktop.mjs --publish
```

Скрипт собирает ресурсы, затем установщики под **текущую систему** и
выкладывает их в **черновик** релиза `v<версия>`. macOS и Windows выпускают
той же командой каждую на своей машине — файлы ложатся в один черновик.
`GH_TOKEN` (право `contents: write`) читается только из окружения, в
репозиторий и в аргументы не попадает; без него скрипт падает до сборки.
Без флага `--publish` скрипт, как и раньше, собирает только ресурсы и ничего
не публикует. Выпуск по тегу `v*` в GitHub Actions складывает в черновик тот
же набор файлов.

Черновик публикуют руками, проверив установщики: пока релиз черновик,
обновляторы его не видят.

**Что должно быть в релизе:**

| Файл | Кому |
|---|---|
| `AI-Office-<версия>-arm64.dmg`, `AI-Office-<версия>-x64.dmg` | macOS, первая установка |
| `AI-Office-<версия>-arm64.zip`, `AI-Office-<версия>-x64.zip` | macOS, обновление — обновлятор ставит только zip |
| `latest-mac.yml` | macOS, описание последней версии для обновлятора |
| `AI-Office-Setup-<версия>.exe` | Windows, установка и обновление |
| `latest.yml` | Windows, описание последней версии |
| `*.blockmap` | разностная загрузка: качаются только изменившиеся блоки |

Имена без пробелов намеренно: GitHub заменяет пробелы в именах файлов
релиза точками, а `latest*.yml` ссылается на имя с диска — с пробелом
обновлятор искал бы файл, которого в релизе нет. Без `latest*.yml` или zip
установленные приложения новую версию не увидят вовсе.

## 8. Фазы

**Фаза 1 — приложение работает.** Сделано 2026-09-21: портируемость сервера,
Electron-оболочка, окно ожидания, поиск и установка движка, пути данных,
сборка сервера и ресурсов, `.dmg`, MinGit в Windows-сборку, workflow релиза,
документация. Проверено на macOS (arm64): собранный `.dmg` ставится и
открывает офис. Windows-сборка написана, но вживую не гонялась — её первый
прогон даст workflow `release`.

**Фаза 2 — вход и мастер.** Поле для API-ключа в приложении с хранением в
`safeStorage`, кнопка входа по подписке, выбор рабочей папки до первого
офиса.

**Фаза 3 — выпуск.** Первый релиз — 0.1.0 (2026-09-22): три установщика в
черновике релиза, macOS-сборка проверена скачиванием. Подпись и нотаризация
подготовлены: сборка включает их сама, когда в секретах есть сертификат
Developer ID и данные Apple (`docs/guide/desktop.md`), — но вживую не
проверялись, сертификата пока нет. Осталось: автообновление из GitHub
Releases, страница загрузки.

## 9. Чего здесь сознательно нет

**Автозапуска офиса без окна** — офис живёт, пока открыто приложение; фоновый
демон с иконкой в трее это отдельное решение, и принимать его надо отдельно.

**Своего терминала внутри приложения** (xterm + node-pty) ради входа по
подписке. Вход делается один раз, системный терминал для этого годится, а
нативный модуль в сборке — это риск на каждой платформе ради одной кнопки.

**Linux-сборки.** Технических препятствий нет (AppImage добавляется строкой),
но проверять её некому — появится, когда появится тот, кто на ней работает.
