# Спека: стартовый экран «Меню» — выбор и создание офиса

Задача T-6. Экран открывается при запуске приложения, до входа в комнату
конкретного офиса. Сейчас такого экрана нет: `App.tsx` сразу монтирует
`<Office>` и подключается к текущему (последнему открытому) офису; сменить
офис можно только изнутри комнаты через дверь → модалку «Офисы и проекты»
(`src/web/OfficesModal.tsx`). Эта спека описывает **новый экран-прихожую**,
который показывается первым и решает: в какой офис войти или какой завести.
Существующая внутрикомнатная модалка не заменяется — она остаётся быстрым
способом сменить офис, не выходя из комнаты; в неё стоит перенести те же
формулировки и валидацию, что описаны здесь, для консистентности.

подключённых MCP-инструментов их нет вообще, ни одного вызова сделать
не удалось). Это спека **не по свежему скриншоту**, а по памяти о фрейме,

принято самостоятельно и явно помечено «(решение дизайнера)».

## 1. Место экрана в потоке приложения

```
Запуск приложения
   │
   ▼
[МЕНЮ] ── подключение к серверу (WS) ──▶ список офисов
   │                                         │
   │                                         ├─ выбрать существующий → «Войти»
   │                                         └─ «+ Новый офис» → форма → «Создать и открыть»
   ▼
Комната офиса (Office.tsx), как сейчас
   │
   └─ дверь → OfficesModal (тот же список, без выхода из комнаты)
```

Экран меню всегда стоит первым экраном сессии браузера (аналог тайтл-скрина
игры: сначала «в каком офисе работаем», потом сама комната). Он не про
многопользовательность — сервер по-прежнему держит один активный офис на
процесс; меню лишь делает явным момент входа, а не открывает офис молча
при первом рендере.

## 2. Структура экрана

Канвас 1440×900 (как у `menu_bg.png`, сетка 3× от арт-пикселя, как во всём
пиксельном стиле проекта). Слои снизу вверх:

1. **Фон** — `menu_bg.png`: сумеречное небо, силуэты города в три плана,
   луна, звёзды, площадка перед офисом с фонарями, скамейкой, урной,
   кашпо. Центр кадра пуст — туда садится панель меню. По краям — виньетка,
   уже встроенная в PNG.
2. **Затемнение поверх фона** — `#12102A` при 35% непрозрачности (по
   памяти о фрейме), чтобы текст и панель читались поверх городских огней.
3. **Заголовок офиса приложения** — верхний край, по центру: пиксельный
   логотип/название «AI OFFICE» шрифтом Press Start 2P (латиница, есть в
   палитре игрового стиля) + под ним подзаголовок помельче Pixelify Sans
   «выберите или создайте офис».
4. **Центральная панель** (карточка) — крем `#FFF8E8`, рамка 3 px
   `#4A3728`, пиксельная тень смещением +8px вниз-вправо (тот же приём,
   что у модалов в комнате, по памяти о фрейме). Ширина панели 560px
   (совпадает с текущим `.modal.wide` в коде — переиспользуем, чтобы не
   плодить второй размер модалки), высота — по содержимому, максимум
   ~640px со скроллом внутри списка при переполнении.
   - Заголовок панели: «Ваши офисы».
   - Список офисов (см. §3).
   - Разделитель.
   - Кнопка «+ Новый офис» (раскрывает форму создания, см. §4) или сама
     форма, если уже раскрыта.
5. **Подвал экрана** — мелкая подсказка внизу по центру под панелью:
   версия/статус подключения к серверу, тускло-серым.

### Одна колонка, без табов

Фрейм `00G-b` (выбор офиса) и `00G-c` (новый офис), по памяти, — это два
отдельных экрана в Figma-флоу. Для реализации предлагаю **не** делать их
отдельными «страницами» с переходом (это лишний шаг клика и лишнее
состояние истории браузера), а разворачивать форму создания **внутри той
же панели**, вместо списка — ровно как уже сделано в `OfficesModal.tsx`
(`creating` — булев тумблер). Это решение дизайнера: соответствует уже
принятому в коде паттерну и экономит один клик «назад».

## 3. Список офисов

Каждая строка списка:

```
┌──────────────────────────────────────────────────┐
│  🏢  Название офиса                    [Открыть]  │
│      /абсолютный/путь/к/проекту                   │
│      Открывался: сегодня в 14:32                  │
└──────────────────────────────────────────────────┘
```

- Название — жирным, Pixelify Sans или системный жирный (см. §6).
- Путь — мелким моноширинным (переиспользовать класс `.mono`,
  уже есть в `styles.css` и используется в `OfficesModal`), приглушённого
  цвета, обрезается многоточием посередине, если не влезает
  (`…ekts/big-name/backend`), полный путь — в `title` (тултип).
- Строка активности — мелким текстом, приглушённым цветом:
  - `lastOpenedAt > 0` → относительное время: «сегодня в 14:32», «вчера в
    09:10», «3 дня назад», для более старых — абсолютная дата «12 мая».
  - `lastOpenedAt === 0` (офис только что создан и ни разу не открывался
    отдельно от момента создания — по факту редкий случай, `createOffice`
    сразу переключает на него) → «ещё не открывался».
- Текущий офис (`current: true`) помечается бейджем **«открыт сейчас»**
  вместо кнопки «Открыть» (действие не нужно — он уже активен); клик по
  такой строке сразу ведёт в комнату (см. «Войти», §5).
- Остальные строки кликабельны целиком (не только кнопка) — упрощает
  попадание на маленьких экранах.

### Сортировка

По убыванию `lastOpenedAt` (сначала недавно открытые), текущий офис —
всегда первой строкой независимо от времени. Решение дизайнера: список
меню используют, чтобы быстро вернуться туда, где работали, а не искать
алфавитно.

## 4. Форма создания офиса

Раскрывается на месте списка (кнопка «+ Новый офис» переключает панель
в режим формы; кнопка «Отмена» возвращает список).

| Поле | Тип | Обязательное | Placeholder | Валидация |
|---|---|---|---|---|
| Название | текст, однострочный | Нет | «Новый проект» | Если пусто — сервер сам возьмёт имя последней папки пути (`projectDir.split('/').pop()`); клиентской валидации не нужно, повторяет `createOffice()` в `src/server/offices.ts:113`. |
| Директория проекта | текст, однострочный | Да | «/Users/you/projects/my-app» | Кнопка «Создать и открыть» неактивна, пока поле пустое (`!dir.trim()` — уже так в `OfficesModal.tsx:18`). Путь резолвится сервером в абсолютный (`resolve()`), относительные пути допустимы, но лучше подсказать абсолютный. |

Подсказка под полем директории (текст уже используется в коде,
переносим как есть — он объясняет побочный эффект, который иначе
удивит пользователя):

> «Абсолютный путь. Если папки нет, офис создаст её и заведёт
> git-репозиторий — без него не работает изоляция задач по веткам.»

### Ошибки создания — важный технический нюанс

Сейчас сервер **не возвращает ошибку создания офиса как отдельное
событие** — `createOffice()` может отдать `{ error: string }`
(например: `«Офис «X» уже работает в этой директории.»` или
`«Не удалось создать /path: <причина>»`, см. `src/server/offices.ts:116,124`),
и `src/server/index.ts:234` в этом случае просто пишет строку в общий чат
от лица «офис» (`office.addChat('офис', made.error)`), не в отдельное поле
формы. Значит, чтобы показать ошибку **внутри формы**, а не потерять её в
чужой панели чата, клиенту нужно слушать входящие `ChatEntry` с
`from === 'офис'`, пока форма открыта и отправлен запрос, и всё, что
придёт в течение ~2 секунд после `create_office`, показывать как ошибку
формы (красный текст под полем директории) вместо/вместе с чатом.
Это ограничение существующего протокола, а не то, что я меняю в
`shared/types.ts` — прошу фронтенд-разработчика учесть при реализации
или, как альтернатива, завести отдельное событие `office.create_failed`
(это уже требует правки `shared/types.ts` и не входит в мою задачу).

Возможные тексты ошибок (дословно с сервера, показываем как есть,
без дублирования смысла своими словами):
- «Офис «Название» уже работает в этой директории.»
- «Не удалось создать /путь: <системная причина>.»
- «Реестр офисов не загружен.» (крайний случай, сервер ещё не стартовал)

### Кнопки формы

- **«Отмена»** — вторичная кнопка, возвращает к списку офисов, поля формы
  сбрасываются.
- **«Создать и открыть»** — основная кнопка (акцентный цвет), задизейблена
  пока директория пуста **или** пока запрос в процессе (см. состояние
  «создаётся», §5). Текст кнопки не меняется на «Создание…» — вместо этого
  показывается прогресс-точки/спиннер внутри кнопки поверх текста (решение
  дизайнера — не плодить строки под каждое состояние сети).

## 6. Тексты интерфейса (сводно, по-русски)

- Поле 1: «Название» / placeholder «Новый проект»
- Поле 2: «Директория проекта» / placeholder «/Users/you/projects/my-app»

- Кнопка отмены: «Отмена»
- Кнопка подтверждения: «Создать и открыть»

- Подключение: «Открываем офис…»

## 7. Сетка, размеры, цвета, шрифты

Проект уже целиком построен на масштабе ×3 от 16 px арт-тайла — эта спека
следует той же сетке, а не выдумывает новую:

- Канвас: 1440×900 (то же, что у `menu_bg.png`).
- Панель: ширина 560px (совпадает с текущим `.modal.wide` в `styles.css`,
  переиспользуем размер, чтобы разработчику не заводить новый токен),
  внутренние отступы 24px, скругление углов 0 (пиксельный стиль — острые
  углы либо ступенчатое скругление спрайтом рамки, не CSS `border-radius`
  с плавной кривой).
- Рамка панели: 3px, цвет `#4A3728` (тёмно-коричневый, тот же, что рамка
  HUD в дневной теме по памяти о фрейме).
- Заливка панели: `#FFF8E8` (крем, тот же токен, что HUD).
- Текст на панели: `#2F2419` (тёмно-коричневый, тот же, что текст HUD).
- Затемнение фона под панелью: `#12102A` при 35%.
- Акцентная кнопка: сервер и клиент уже используют `--accent: #f0b429` /
  `--accent-ink: #2b2233` (`src/web/styles.css:10-11`) — переиспользуем эти
  же значения, а не вводим новый акцент только для меню.
- Приглушённый текст (путь, время активности): `--muted`, как в остальном
  приложении (см. `.muted` в `styles.css`).
- Моноширинный текст пути: класс `.mono` (уже есть, использует
  `ui-monospace, SFMono-Regular, Menlo, monospace`).
- Заголовки/HUD-надписи: **Pixelify Sans** (кириллица есть) — по памяти о
  Figma-концепте, в коде сейчас не подключён, будет отдельной задачей на
  подключение веб-шрифта (см. §8 «Что нужно художнику/фронтенду»).
- Крупный логотип-заголовок «AI OFFICE»: **Press Start 2P** (только
  латиница — подходит, т.к. это английское название приложения).
- Основной текст форм и списка (за пределами HUD-надписей): Inter — как
  уже принято для панелей и транскрипта по памяти о концепте.

## 8. Данные, которые экран ждёт от сервера

Ничего менять в `src/shared/types.ts` не требуется — нужный контракт уже
есть:

- `ServerEvent` с `t: 'snapshot'` содержит `offices: OfficeView[]` —
  ровно то, что нужно списку (`src/shared/types.ts:109-115,207-212`):
  - `id: string`
  - `name: string`
  - `projectDir: string` — абсолютный путь, показывается в `.mono`
  - `current: boolean` — какая строка получает бейдж «открыт сейчас»
  - `lastOpenedAt: number` (unix ms) — источник для «Открывался: …»
- Отдельное событие `{ t: 'offices'; offices: OfficeView[] }` приходит при
  любом изменении списка (после `create_office`/`rename_office`) — меню
  должно обновлять список по нему, не только по `snapshot` при коннекте.
- Для блокировки входа («задачи в работе») меню использует уже дошедший
  `snapshot.busy` (глобальный флаг занятости у только что открытого
  офиса) — специальной команды спрашивать не нужно, сервер сам откажет
  через `switch_office`, если целевой офис занят задачами, а если занят
  **текущий** офис — это видно по `busy` в уже подключённом снапшоте.
- Команды на отправку (уже есть в `ClientCommand`, ничего добавлять не
  нужно):
  - `{ c: 'switch_office'; officeId }`
  - `{ c: 'create_office'; name; projectDir }`
  - `{ c: 'rename_office'; officeId; name }` (для переименования из
    списка — опционально на этом экране, см. §9)

**Чего не хватает и стоит рассмотреть отдельной задачей (не блокирует
эту спеку, просто отмечаю пробел):** нет отдельного структурированного
события об ошибке создания офиса — см. разбор в §4. Также в `OfficeView`
нет числа задач/агентов в офисе — если в будущем понадобится показывать
в строке списка что-то вроде «2 задачи в работе», это отдельное
расширение контракта, не входящее в эту спеку.

## 9. Что нужно нарисовать/сделать художнику

Большая часть арта для этого экрана уже существует и не требует новой
рисовки:

- **Фон-улица** — готов: `design/sprites/out/menu_bg.png` (1440×900).
  Ничего дорисовывать не нужно, разве что подтвердить с художником, что
  вариант только один (без дневной версии) — по коду генератора
  (`gen_menu_bg.py`) он не принимает тему day/night в отличие от
  `gen.py`, то есть меню всегда в этом сумеречном настроении независимо от
  темы комнаты. Решение дизайнера: это нормально для тайтл-экрана —
  оставляем как есть, не просим художника генерить дневной вариант.

Из нового художнику нужно нарисовать (или сгенерировать через `gen.py`/
новый скрипт по аналогии):

1. **Значок офиса** для строки списка (маленький пиксельный домик/дверь,
   16×16 арт-px → 48×48px), два состояния: обычный и для текущего офиса
   (с лёгкой подсветкой/огоньком в окне) — сейчас в списке предлагается
   эмодзи 🏢 как временная заглушка текста, но по стилю проекта эмодзи в
   HUD не используются (весь остальной интерфейс — спрайты), так что
   нужен пиксельный значок.
2. **Пиксельная рамка панели/карточки** — 9-slice спрайт рамки 3px с
   тенью +8px (по памяти о стиле модалов), чтобы не рисовать тень через
   CSS `box-shadow` (которая даёт мыло, а не пиксельную ступеньку).
3. **Кнопка** в двух состояниях (обычная/hover/disabled) как переиспользуемый
   9-slice спрайт — сейчас кнопки в коде плоские HTML `<button>` с
   CSS-заливкой; для игрового рескина нужен спрайт-подложка.
4. **Индикатор загрузки** — 3-4 кадра простой пиксельной анимации (три
   точки или мигающий курсор), для состояний «Подключение»/«Открывается»/
   «Создаётся».

Не художника, а фронтенда задача (отмечаю, чтобы не потерялось):
подключить веб-шрифты Pixelify Sans и Press Start 2P (сейчас в коде не
подключены, используется системный шрифт) — это интеграция, а не
рисовка.
