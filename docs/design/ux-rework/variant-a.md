## 1. Информационная архитектура

### 1.1. Модель в одной фразе

Офис = **Центр** (Чат) + **Панель** (один вид из корешков). Всё, что не Чат, — вид Панели. Единственное исключение, не принадлежащее офису, — **Обзор офисов** (§1.4).

### 1.2. Дерево

```
Приложение
├─ РЕЙЛ ОФИСОВ (постоянно, слева)
│   ├─ ⌂ Обзор офисов ........................ §1.4 (главный экран, управление офисами)
│   ├─ Офис 1 … Офис N (иконка, состояние, «ждёт меня», непрочитанное)
│   │     └─ клик по числу → всплывающий вид «Ждёт меня» этого офиса
│   ├─ [+] Новый офис → Мастер
│   └─ ⬆ Обновление (точка, только когда есть обновление) → Настройки › Приложение › Обновление
│
└─ ОФИС (одна рабочая область)
    ├─ ШАПКА: название · состояние · «ждёт меня N» · [⏸ Пауза] · шкала лимита · [⌘K] · [⋯]
    │     ├─ шкала лимита → Деньги
    │     ├─ «ждёт меня N» → корешок «Ждёт меня»
    │     └─ [⋯] меню офиса: Переименовать · Иконка · Папка проекта · Настройки офиса · Архивировать
    ├─ ПОЛОСА СИГНАЛОВ (по событию): плашка окружения → Настройки › Провайдеры
    ├─ ЦЕНТР
    │   └─ Чат с менеджером
    │       ├─ [Чаты ▾] список чатов с PM: создать, найти, архив, переименовать
    │       ├─ карточки в сообщениях (задача, согласование, вопрос) → открываются в Панели
    │       └─ композер (единственный в приложении)
    └─ ПАНЕЛЬ (один вид; справа — корешки)
        ├─ Доска (B)
        │   ├─ полоса «Сейчас» (кто что делает)
        │   ├─ сегмент: Задачи │ Направления │ План
        │   └─ Карточка задачи → разделы: Обзор · Разговор · Что случилось · Дифф · Результат
        ├─ Ждёт меня (W)
        │   ├─ вопросы (ask_owner)
        │   ├─ согласования (макет, исследование)
        │   ├─ разрешения инструментов
        │   ├─ предложения офиса (инициативы, самоизменения)
        │   ├─ сорванные задачи (причина + действия)
        │   └─ вопрос о выпуске
        ├─ Результаты (D)
        │   ├─ сегмент: Документы │ Из задач
        │   ├─ Документы: фильтр по 3 категориям → документ → [Текст │ Просмотр], История
        │   └─ Из задач: макеты, отчёты, дифф закрытых задач → их Карточка задачи
        ├─ Ход работы (L)
        │   ├─ сегмент: Лог │ Слияния (Q) │ Совещания (M) │ Жизнь (J)
        │   ├─ Совещания → форма «Созвать» (внутри вида)
        │   └─ Жизнь: журнал (фильтр), инициативы
        ├─ Деньги (E)
        │   ├─ сегмент: Сегодня │ По задачам │ Отчёт
        │   └─ Лимиты и бюджет
        ├─ Команда (T)
        │   ├─ сегмент: В офисе │ Маркет
        │   └─ Сотрудник → вкладки карточки (5, как сейчас); [⋯]: Экспорт пакета
        ├─ Выпуски (R)  — 3 вкладки как сейчас
        └─ Ещё
            ├─ Офис (O) — Сцена 3D + карточка сотрудника
            ├─ Терминал (Ctrl/Cmd+`)
            ├─ Процессы (P) — 4 вкладки как сейчас; редактор открывается в ⤢
            ├─ Настройки (Cmd/Ctrl+,)
            │   ├─ Офис: Провайдеры · Правила · Окружение · Проект · Жизнь офиса (режим) · … (8 разделов → группа → форма, как сейчас)
            │   └─ Приложение: Общие · Обновление и заметки · Расходы по всем офисам · …
            └─ Справка (?) — клавиши и подсказки
```

Палитра `Cmd/Ctrl+K` открывает любой пункт дерева, а также задачи, сотрудников, чаты, документы; рядом с пунктом показана его клавиша.

### 1.4. Обзор офисов (единственное «не-офисное» место) — отступление, см. §7

Концепция A сводит главный экран на нет, но у многоофисного владельца (С4) нужна общая точка: управление офисами (архив, иконка, порядок), сводка по всем и первый экран, когда офис не выбран. Обзор — **развёрнутое состояние панели (⤢)**, открывается кнопкой ⌂ в рейле; Центр и Панель офиса под ним сохраняются, Esc/✕ возвращают точно в тот офис и место. Не новая область экрана, не отдельная форма — состояние ⤢.

Содержимое Обзора: плитка на каждый офис (иконка, название, состояние, «ждёт меня N» с первой записью и кнопкой ответа, что делают агенты — 1 строка, расход за день, шкала), блок «Расходы по офисам» (итог и ссылка в Деньги офиса), «Архив» (свёрнут), кнопки «Новый офис», «Настройки приложения».

## 3. Проход по сценариям

Шаг = клик, клавиша или отправка сообщения от «владелец видит каркас офиса A» до завершения действия. «Сейчас» — оценки из scenarios.md; «станет» — расчёт по этому документу.

### С1. Поставить задачу и следить

1. Фокус уже в композере (или `Enter`).
2. Написать текст — он не считается шагом ввода; **отправить** — шаг 1.
3. Менеджер отвечает в Центре; в Панели (корешок «Доска» открыт по умолчанию) в «Задачах» появляется карточка с подсветкой «новая». Если Панель показывает другой вид — на корешке «Доска» точка «новое»; нажать `B` — шаг 2.
4. Прогресс: «Сейчас» на доске и значок состояния на карточке; клик по карточке — раздел «Обзор».

**Сейчас ≈ 4** (Чат → отправить → Доска → найти) → **станет 1 (Доска рядом), 2 (Панель была на другом виде)**. Цель К1 ≤ 2 достигается.

### С2. Ответить на вопрос / согласовать

1. Сигнал: число «ждёт меня» в шапке, на корешке и в рейле; в Центре — карточка с кнопками.
2. Свой офис: ответ кнопкой в карточке чата — **1 шаг**; через список — `W` → кнопка варианта — **2**.
3. Чужой офис: клик по числу у иконки в рейле → всплывающий «Ждёт меня» офиса → кнопка варианта — **2**, без перехода в офис.
4. Разрешение инструмента: модалка своего офиса — решение кнопкой, 1; чужого — запись в списке и тост, 2.

**Сейчас ≥ 4** → **станет 1–2**. К2 ≤ 2 достигается.

### С3. Понять, что происходит

1. Рейл: у каждого офиса состояние, число «ждёт меня», точка непрочитанного — 0 шагов.
2. Шапка и полоса «Сейчас» на Доске: имя агента, задача, статус, 1 строка — 0 шагов.
3. Подробности: `L` (Ход работы › Лог) — 1; Сцена `O` — 1.

**Сейчас ≈ 3** (Офис → Доска → Лог) → **станет 0 (беглый взгляд), 1 (подробно)**. К4 ≈ 0–1.

### С4. Несколько офисов параллельно

1. Клик по иконке офиса или `Cmd/Ctrl+1…9`, `Cmd/Ctrl+[ ]` — 1.
2. Офис открывается в сохранённом месте: корешок, вложенность Панели, карточка, раскрытые группы, прокрутка, черновик композера, ширина Панели.
3. Возврат — 1, снова на прежнем месте.

**Сейчас 1/1, но место теряется** → **станет 1/1, место сохранено**. К3 достигается.

### С5. Разобрать сорванную работу

1. Сигнал: запись «Ждёт меня» вида «T-14 упала: слияние не прошло (конфликт в `Shell.tsx`)» — причина в одну строку.
2. Действия прямо в записи: «Перезапустить», «Снять», «Спросить менеджера» (ставит ссылку на карточку в композер), «Открыть» — 1–2 шага.
3. Углублённо: «Открыть» → Карточка задачи: раздел «Что случилось» (последние события лога по этой задаче, причина слияния) + «Дифф» — шаги: `W` → «Открыть» → прочитать → действие = 3.
4. Общий лог и очередь слияния: `L` — отдельно, если нужен контекст всего офиса.

**Сейчас ≈ 5** (Доска → карточка → дифф + Лог/Очередь + чат) → **станет 2–3**. К6 ≤ 3 достигается. Это **дополнение** концепции (§7, п. 4): у концепции A К6 был 1 из-за переключения видов; причина и действие собраны в одной записи.

### С6. Посмотреть результат

1. Из карточки в чате/тосте: клик → Панель переходит на Доску с карточкой → раздел «Результат» виден сразу (якорь) → «Открыть» — 2 шага.
2. Или `D` → Результаты › «Из задач» → строка → документ — 2.
3. Принять/вернуть — кнопки «Принять», «Вернуть с правками» в том же разделе; вернуть = текст в композер с ссылкой на карточку.

**Сейчас 3–4** → **станет 2**. К5 ≤ 2.

### С7. Выпустить версию

1. Вопрос приходит записью «Ждёт меня» и карточкой в чате: версия, разряд, что войдёт (3–5 строк заметок), кнопки «Выпускай», «Другая версия…», «Не сейчас» — **1 шаг**.
2. Полный вид — `R` → 3 вкладки — 1–2 шага; из записи — «Открыть выпуск».
3. Результат выпуска: запись в Ходе работы › Лог и статус во «Выпусках».

**Сейчас 2–3** → **станет 1 (ответ), 2 (с полным видом)**.

### С8. Настроить команду

1. `T` → Команда › «В офисе» — 1.
2. Клик по сотруднику — 2 (вид внутри Панели, ⤢ по желанию).
3. Вкладка «Бриф» / «Модель» — 3. Экспорт — «⋯» → «Экспорт пакета» — 3–4.
4. Найм: `T` → «Маркет» → пакет → «Нанять» — 3. Нанятый выделяется в «В офисе».

**Сейчас 4–5** → **станет 3**; **уровней — 2** (К7). Закрытие «с вопросом о несохранённом» сохраняется — решает форма, не навигация.

### С9. Деньги и лимиты

1. Шкала в шапке видна всегда — 0.
2. Клик по шкале (или `E`) → Деньги › «Сегодня» — 1.
3. «Отчёт» — сегмент, 2. «Лимиты и бюджет» — сегмент/раздел, 2.
4. Пауза: `Space` или `[⏸]` — 1, в любом виде.

**Сейчас 3** (шкала → Расходы → Отчёт-модалка) → **станет 1–2**. Деньги — в одном месте (К12).

### С10. Настройки офиса

1. `Cmd/Ctrl+,` или «Ещё › Настройки» — 1 (2 без клавиши).
2. Раздел — 2; группа/форма — 3 (в самом виде, без модалок: «Проект» — раздел с формой, не `ZoneForm`).
3. Из плашки окружения — клик «Выбрать провайдера» → сразу Настройки › Провайдеры на форме — 1.
4. Процессы: `P` — 1; редактор — ⤢.

**Сейчас 2–3 (провайдеры — в пяти местах)** → **станет 3 (редкое)**, плашка — 1. К7 редкое ≤ 3.

### С11. Первый запуск и создание офиса

Первый запуск: один экран **Мастер**; шаг «Движок» показывается, только если провайдера нет. Затем «Название и папка проекта», «Команда», «Направление» и т. д. — пять шагов мастера сохранены как есть (содержимое не разбиралось). «Главного экрана» как промежуточной стадии нет.

Новый офис: «+» (1) → мастер → «Создать с умолчаниями» после ввода названия и папки (2–3) или полный путь из пяти шагов.

**Сейчас:** `FirstLaunch` → главный экран → мастер (5 шагов) или «+» → «Офисы» → «Новый офис» (два пути). **Станет:** один мастер, быстрый путь 3 шага, нет промежуточного экрана. Пустой офис ведёт сразу в чат с предложением сформулировать первую задачу.

### С12. Совещание

## 5. Состояния и правила

### 5.1. Что с чатом и доской, пока открыт вспомогательный раздел

| Ситуация | Чат (Центр) | Доска |
|---|---|---|
| Открыт любой вид Панели (не ⤢) | Виден, живёт: сообщения идут, композер работает, Enter/Space/B действуют | Свёрнута в корешок; её состояние хранится (сегмент, группы, прокрутка, открытая карточка) |
| Появилась карточка/изменение на доске | Карточка-сообщение в чате (как всегда) | Точка «новое» на корешке «Доска»; при возврате карточка подсвечена |
| ⤢ (развёрнуто) | Скрыт; композер остаётся; чип «💬 Чат ●» показывает непрочитанное; отправка из композера работает, ответ приходит тостом-краткой строкой над композером | Скрыта, как выше |
| Панель закрыта (✕) | На всю ширину | Скрыта; корешок «Доска» — клик возвращает |
| Открыта модалка разрешения | Затемнён; Esc = «Отложить» (запрос остаётся в «Ждёт меня», агент ждёт) | — |

Принцип 1 (чат и доска за один клик): из любого вида Панели — клик по корешку «Доска» или `B`; чат всегда в Центре, в ⤢ — чип «Чат» и `Enter`.

**Вложенность и «Esc».** Esc закрывает **верхний слой**: карточка → список → Панель. Последний Esc на закрытой Панели ничего не делает (не уводит на другой экран). ✕ закрывает Панель целиком, из любой глубины. Повтор клавиши раздела (`B` при открытой Доске) закрывает Панель. Закрытие несохранённой формы спрашивает подтверждение — единый диалог внутри Панели.

**Карточка из чужого вида.** Клик по карточке задачи в чате, тосте или «Ждёт меня» открывает её на корешке «Доска» (или в текущем виде, если это «Ждёт меня»/«Результаты»); вложенность прежнего вида не теряется.

**Что сохраняется при смене офиса (на каждый офис):** открытый корешок, стек вложенности и прокрутка каждого вида, сегмент и раскрытые группы Доски, ⤢-состояние, выбранный чат и прокрутка, черновик композера, ширина Панели (общая на приложение). Терминал: живые сессии не закрываются **(допущение; судьба сессий в аудите неизвестна)**.

### 6.4. Слабые места (честно)

1. **Панель одна.** Нельзя держать рядом «Доску» и «Лог» (разбор сбоя) или «Результат» и «Доску» — только переключением. Смягчено: причина сбоя в записи и карточке, ⤢ не нужен, но параллельный просмотр невозможен.
2. **Корешков 8, ядро ≈ 45%.** Риск вернуться к «слишком много пунктов»; список придётся жёстко держать (§7 п. 9).
3. **Центр сужается Панелью.** На 1280 px чат ≈ 730 px, на 1024 — ≈ 560; на < 900 «чат или панель», совместность теряется — главный выигрыш варианта пропадает на ноутбуке с делёным экраном.
4. **Обзор офисов — особая форма.** Это единственный вид, не принадлежащий офису; формально нарушает «всё — вид Панели» (отступление, §7 п. 1).
5. **Модалка разрешения остаётся.** Для своего офиса она блокирует работу; смягчено Esc = «Отложить», но агент тогда ждёт.
6. **Сцена спрятана.** Рабочее слой по допущению scenarios.md; если владелец смотрит Сцену часто — два шага (Ещё › Офис) или `O`, а чат при «⇄» теряет центральность.
7. **Преемственность с нынешним доком.** Правая панель похожа на «правый док»; владелец может не заметить принципиальной разницы (одна форма, один способ закрытия, ничего «окном из окна»).
8. **С12 длиннее на шаг** (просмотр совещаний).
9. **Не разобрано в аудите:** содержимое «Процессов», «Выпусков», просмотрщиков результатов; сохранение терминальных сессий; «Жизнь офиса» в Настройках — решения по ним приняты как допущения, их проверять при реализации.
10. **Шкала и пауза при 5+ офисах — по офису.** Глобальной паузы «всех» нет; если нужна — отдельное решение.

## 7. Отступления от концепции

Концепция варианта A не менялась; ниже — дыры, которые пришлось закрыть здесь.

1. **Обзор офисов (⌂).** В concepts.md главный экран не описан, а С4/С11 требуют общей точки (управление офисами, расходы по всем, пустой запуск). Решение: ⌂ открывает развёрнутое состояние панели, не новую область. Стоимость: единственное место вне «Центр + Панель офиса».
2. **⤢ оставляет композер и чип «Чат».** В концепции развёрнутая Панель могла скрыть чат целиком — нарушало принцип 1 и К1. Композер и чип всегда видны.
3. **Полоса «Сейчас» на Доске.** С3 требует «кто что делает» без перехода; в концепции этого нет. Добавлено в содержимое корешка «Доска», областей не прибавило.
4. **К6: причина сбоя в записи «Ждёт меня».** Концепция оценивала К6 в 1 (переключение видов). Решение: сорванная задача — запись с причиной и действиями; полный разбор — раздел «Что случилось» карточки. Это добавляет вид записи в «Ждёт меня», который уже есть в глоссарии.
5. **Разрешение чужого офиса — не модалка; Esc = «Отложить».** В концепции модалка единственная, но не сказано, что с чужими офисами и с закрытием. Выбрано: чужой — запись и тост, свой — модалка с «Отложить».
6. **Корешок «Ещё» наполнен явно:** Офис (Сцена), Терминал, Процессы, Настройки, Справка; «Маркет» — не в «Ещё», а сегмент внутри Команды (в концепции он перечислен в «Ещё» как ярлык — оставлен как пункт палитры).
7. **Экспорт пакета** из вкладки карточки сотрудника переехал в «⋯» карточки (ужимает глубину С8 до 3 шагов).
8. **Панель закрывается** (✕ — Центр на всю ширину, корешки остаются). В концепции Панель подразумевалась постоянной.
9. **Лимит корешков зафиксирован:** 8 (7 + «Ещё»), новые разделы — только в «Ещё»; иначе вариант вырождается обратно в текущий рейл.
10. **Клавиши.** Добавлены `W`, `D`, `T`, `O`, `?`, `Cmd/Ctrl+,`, `Cmd/Ctrl+Enter`; прежние `J/P/R/E/L/Q/M/B/Space/Enter` сохранены (вопрос 5 concepts.md закрыт допущением «меняем только добавляя»).
