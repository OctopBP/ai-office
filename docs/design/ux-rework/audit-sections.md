# Опись разделов и окон (T-530, часть 2 аудита UX)

Только описание того, что есть в `src/web` на 2026-10-11. Каркас (рейл, левая панель, топбар) сюда не входит. Глубина: 1 — один ряд вкладок, 2 — вкладки внутри вкладки или переключатель внутри раздела.

## 1. Как вообще показывается содержимое

В коде встречается пять способов, и они сосуществуют:

- **Вид главной области** — подменяет сцену офиса. Выбирается сегментами сверху (`TopView`: office, board, chat, life) или пунктами рейла (`RailView`: team, settings, flows, releases). Рендер — `shell/Shell.tsx`.
- **Окно в доке** — вкладка нижнего/правого/левого дока (`WorkColumn` + `layout/Dock.tsx`): terminal, log, merge (внизу), docs, money, meetings (справа). Вкладки можно перетаскивать между доками, сворачивать, разворачивать.
- **Дровер** — выдвижная панель поверх сцены (`AgentDrawer`, `TaskDrawer`).
- **Панель/модалка** — `Panel` или `modal-backdrop` поверх всего: `DiffPanel`, `PermissionModal`, `MeetingModal`, `OfficesModal`, `SetupWizard`, `SpendReportModal`, `ZoneForm`, заметки к выпуску.
- **Экран приложения до выбора офиса** — `MenuScreen` (три вкладки, адреса `/`, `/spending`, `/settings`) и `FirstLaunch` (standalone).

## 3. Окно из окна

- Настройки → «Проект» → `ZoneForm` (модалка зоны) — модалка поверх страницы.
- Расходы (док) → `SpendReportModal`.
- Совещания (док) → `MeetingModal`.
- Меню → `SetupWizard`; офис на сцене → дверь → `OfficesModal` → форма «Новый офис» внутри модалки.
- Доска → карточка задачи (дровер) → дифф (`Panel`) — три слоя; Esc снимает слои по одному: карточку, затем всё прочее.
- Карточка сотрудника (дровер) → «Команда» (страница) — переход, а не наложение; дровер при этом закрывается.
- Уведомление системы (`panelRequest`) → открывает окно дока.
- Встроенные подтверждения в страницах (полный доступ, удаление задачи, «закрыть без сохранения», архивация офиса) рисуются внутри содержимого (`access-confirm`), а не отдельным окном.

## 4. Разделы с двумя и более уровнями вкладок

- **Команда**: «В офисе / Маркет» → карточка сотрудника → «Профиль / Модель / Доступ / Бриф / Результаты» (3 уровня выбора: вкладка, строка списка, вкладка карточки).
- **Настройки**: 8 разделов → группы; в «Провайдерах» ещё карточка → форма ключа / «Свой API».
- **Документы**: «Основа / Документация / Рабочие» → документ → «Текст / Просмотр» (+ история).
- **Жизнь офиса → Журнал**: вкладка → «живые / устаревшие / в архиве».
- **Расходы**: «сегодня / всего»; таблица — период × шаг (два переключателя без вкладок).
- **Отчёт о расходах** (модалка): период × срез.

## 5. Не разобрано

- Внутренности вкладок «Процессы» (`FlowsPage`: Доска/Процессы/Проверки/Статистика) и «Выпуски» (`ReleasesPage`: Цели/Планы/Настройка) — прочитаны только заголовки вкладок; вложенные переключатели и модалки в них не проверялись.
- Внутренности «Меню» → «Расходы» (`MenuScreen.Spending`) и «Меню» → «Настройки» (`AppSettings`) — только факт вкладок.
- Содержимое 3D-офиса (`Office3D`, контекстные меню/тултипы сцены) — не читалось.
- Чат: `ChatThread`, `ChatCards`, `PeerPicker` и композер — не открывались; наличие выпадающего выбора собеседника взято из имён и разметки `PeerPicker`.
- Кто и откуда открывает старые `Panel` `board` и `help` из `Overlays.tsx` (в разобранном коде вызов не найден; `Board` показывается видом).
- Предложения (`Proposals` в `LifePanel`) — компонент есть, во вкладках не перечислен; показывается ли он где-либо ещё, не проверено.
- Точная кнопка рейла, открывающая список офисов (`OfficesModal`) и окна дока — `shell/Rail.tsx` не читался подробно; в модалку ведёт дверь на сцене (`Shell.tsx:65`).
- Просмотрщики файлов результата (`chat/FilePreview`, `result/viewers`, `Model3dViewer`) — открываются ли в модалке или внутри карточки, не проверено.
- `Toasts`, `EnvBanner`, `BudgetStopBanner` — баннеры/уведомления, не окна; не разбирались.
