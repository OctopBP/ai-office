# Опись каркаса оболочки и переключения офисов

Часть 1 аудита UX (T-529). Только описание того, что есть в коде на ветке `task/T-529`. Содержимое окон и страниц (Команда, Маркет, Настройки, Документы и т. д.) не разбиралось — указано лишь, что открывает кнопка каркаса.

Файлы: `src/web/shell/` (Shell, Rail, TopBar, Composer, WorkColumn, RailPages, PmChatList, EnvBanner, UpdateBlock), `src/web/App.tsx` (горячие клавиши, экран меню), `src/web/store.ts` (`view`, `enterOffice`, `leaveOffice`), `src/web/layout/*` (доки).

## 1. Устройство каркаса

`Shell.tsx` собирает окно из слоёв: рабочая колонка `WorkColumn` (основная область + доки справа/снизу) → рейл `Rail` слева → `TopBar` сверху → `Composer` снизу → `EnvBanner` → `Overlays` (модалки).

Три способа открыть «окно» в каркасе:
- **Вид** (`view` в сторе) — подменяет содержимое основной области; рейл, топбар остаются. Сцена `Office3D` не размонтируется, а прячется.
- **Вкладка дока** — окно в правом или нижнем доке `WorkColumn` (раскладка своя у каждого офиса).
- **Модалка** — `Overlays` (`ModalKind = 'meeting' | 'offices'`, `PanelKind = 'board' | 'help'`).

## 3. Переключение между офисами

### 3.1. Шаги

1. Список офисов — секция «Офисы» рейла; показаны только неархивные, в порядке пользователя (перетаскивание, порог 5 px).
2. Клик по строке чужого офиса = **1 клик**. Клик по текущему — ничего. Во время переключения (`pending='enter'`) все строки и «На главный экран» заблокированы.
3. `enterOffice` в сторе: меняется адрес, ставится `pending='enter'` (имя офиса в `pendingLabel`), клиент шлёт `switch_office`. Сервер отвечает снимком — только тогда состояние нового офиса приходит.
4. Через меню: рейл → «На главный экран» → карточка офиса на `MenuScreen` (≈ 2 клика, содержимое экрана не разбиралось). Через окно «Офисы»: «+»/дверь → кнопка перехода в строке (≈ 2 клика), для архивных сначала «Вернуть из архива».

### 3.2. Что сбрасывается и что сохраняется

| Что | При переключении | Где |
|---|---|---|
| Активный вид (`view`) | сбрасывается в «Офис» | `enterOffice` |
| Выделенный сотрудник, открытая карточка задачи, открытый дифф | сбрасываются | `enterOffice`, снимок |
| Ветка чата (`thread`) | сбрасывается в `pm#1` | `enterOffice`, снимок |
| Выбранный чат с PM | восстанавливается запомненный для этого офиса | `restorePmChat` в снимке |
| Черновик нового чата, точка непрочитанного (`chatUnread`) | сбрасываются | снимок |
| Открытые модалки и панели (`panel`, `modal`) | закрываются | `App.tsx`, эффект на `pending==='enter'` |
| Раскладка доков (какие окна открыты, размеры) | загружается раскладка нового офиса, прежняя записывается | `WorkColumn` (`layout.load(officeId)`) |
| Раскрытые группы фич на доске (`taskGroupsOpen`) | сбрасываются | `enterOffice` |
| Свёрнутость рейла, тема | сохраняются (общие, не по офису) | `localStorage` |
| Экран первого запуска | уступает место при смене вида | `Shell.tsx` |
| Задачи в работе прежнего офиса | продолжаются на сервере | комментарий в `enterOffice` |

### 3.3. Как на рейле видно состояние других офисов

| Сигнал | Как показан | Источник |
|---|---|---|
| Идёт работа / простой / пауза | цветная метка справа в строке + подпись: «N в работе · N к слиянию», «работает», «простаивает», «пауза»; пауза — ещё и значок ⏸ | `summarizeOfficeActivity`, `OfficeView.activity` |
| Число задач в работе и готовых к слиянию | в подписи строки (у текущего — «людей N, занято M») | то же |
| Подсказка по метке | всплывающая подсказка на метке; путь проекта — подсказка на строке (в свёрнутом рейле — имя и статус) | `Rail` |
| Ожидание ответа владельца | **на рейле не показано**: `activity.waiting` считается, но выводится только на `MenuScreen` («N запросов ждут решения») | `store.ts`, `MenuScreen.tsx` |
| Непрочитанное в чате | **на рейле не показано**: точка у сегмента «Чат» и бейдж «Жизни офиса» относятся только к текущему офису | `TopBar.tsx` |

### 3.4. Создание и настройка офиса

| Действие | Путь | Результат |
|---|---|---|
| Создать офис | «+» в секции «Офисы» (или дверь в комнате) → окно «Офисы» → «Новый офис» → имя и папка проекта → «Создать» | `requestCreateOffice`: `pending='create'`, затем вход в новый офис |
| Создать офис мастером | вне каркаса (`MenuScreen`, `requestSetupOffice`) | не разбиралось |
| Переименовать, сменить иконку | окно «Офисы» → кнопки в строке офиса | `renameOffice`, выбор иконки |
| Архивировать / удалить | правый клик по строке в рейле или кнопки в окне «Офисы» → подтверждение | если офис текущий — сначала переход в соседний |
| Вернуть из архива | окно «Офисы» → раздел «Архив» | — |
| Порядок офисов | перетаскивание строки в рейле | `reorder_office` |
| Настройки офиса | рейл → «Настройки офиса» | вид `settings` |

## 4. Горячие клавиши навигации

Обработчик — `App.tsx` (две раскладки, RU/EN); не срабатывают в `INPUT` и `TEXTAREA`. Подписи — `hotkeys.ts`.

| Клавиша | Действие |
|---|---|
| `Esc` | по очереди: закрыть карточку задачи → закрыть панель/модалку/дифф/выделение → вернуться из вида в «Офис» → выйти на главный экран |
| `Enter` | вид «Чат» + фокус в композер |
| `Space` | пауза / продолжение |
| `B` / `J` / `P` / `R` | вид «Доска» / «Жизнь офиса» / «Процессы» / «Выпуски»; повтор возвращает в «Офис» |
| `E` / `L` / `Q` | окно «Расходы» / «Лог» / «Очередь слияния»; повтор закрывает вкладку |
| `M` | модалка созыва совещания |
| `Ctrl/Cmd+\`` | терминал (`Shell.tsx`, срабатывает и в полях ввода) |
| `1`–`9` | выбрать/снять сотрудника по номеру |
| `G` | режим разработчика 3D |
| `Enter` / `Shift+Enter` / `Esc` в композере | отправить / перенос строки / убрать фокус |

Клавиш для переключения между офисами, для «Команда и маркет», «Настройки офиса», «Документы» и для сегмента «Офис» нет. Хоткеи раскладки доков (`useLayoutHotkeys`) не разбирались.

## 5. Не разобрано

- `layout/hotkeys.ts` (`useLayoutHotkeys`): клавиши управления доками и вкладками.
- Внутренности `Dock`, `Splitter`, `tabdrag`: контекстное меню вкладок, перенос между доками.
- `MenuScreen` и мастер создания офиса (`setup`): вне каркаса, учтены лишь как точки входа.
- `Overlays`: панели `board`/`help` — какой интерфейс вызывает `help` не выяснялось.
- Жизнь черновиков композера при смене офиса (`inputDrafts`) и сессий терминала при смене офиса.
- Поведение мобильной/узкой раскладки (`narrowMode`) кроме автосворачивания рейла и переноса боковых вкладок вниз.
- `ChatPeer` (собеседник в композере): состав и поведение.
- Стили (`shell.css`) и адаптив — не открывались.
