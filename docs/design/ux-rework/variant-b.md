## 1. Информационная архитектура

### 1.1. Модель в одной фразе

Приложение — один поток работы. Слева Лента: что ждёт меня (по всем офисам), на чём я работаю (ветки), какие есть офисы. В Центре — открытая ветка, а если ветки нет — доска. Всё остальное — Страница в Центре с хлебными крошками и «←». Офис — фильтр, а не место, куда переходят.

### 1.2. Дерево

```
ПРИЛОЖЕНИЕ
│
├─ ВЕРХНЯЯ СТРОКА (постоянная, 48 px)
│   ├─ Область: [Все офисы ▾] / [Приложение ▾] / …      ← фильтр, не навигация
│   ├─ [Разделы ▾]  меню разделов области (то же меню, что в Ленте у офиса)
│   ├─ Поиск / палитра ⌘K  (чаты, задачи, документы, сотрудники, разделы)
│   ├─ Состояние: ● работает N · ⏸ N · ⚠ N
│   ├─ Шкала лимита плана (%, время сброса в подсказке)
│   └─ [⏸ Пауза] — области (одного офиса или всех)
│
├─ ЛЕНТА (постоянная, 320 px)
│   ├─ ВХОДЯЩИЕ  = «Ждёт меня» по всем офисам, действие на месте
│   │    вопрос ask_owner · согласование · разрешение инструмента ·
│   │    сорванная/вставшая задача · вопрос о выпуске · предложение офиса
│   ├─ ВЕТКИ
│   │    Чаты с менеджером (список, поиск, +, переименование, архив)
│   │    Задачи в работе и требующие внимания
│   │    Идущие совещания
│   └─ ОФИСЫ  [+]
│        строка офиса: иконка · имя · состояние · «ждёт меня N» · непрочитанное ·
│        «что делает» (1 строка); клик = область «этот офис»;
│        «⋯» = меню офиса (Разделы, Иконка, Переименовать, Архив)
│        «⋯» у заголовка блока = Управление офисами, Архив, Настройки приложения
│
└─ ЦЕНТР (одна из трёх форм)
    │
    ├─ ВЕТКА  (открывается из Ленты, с доски, из сообщения, из палитры)
    │    ├─ Ветка «Менеджер»  — чат с менеджером офиса (+ карточки задач в тексте)
    │    ├─ Ветка «Задача T-n» — Карточка задачи: разговор + статус + результат +
    │    │                       «Что случилось» + дифф (режим внутри ветки)
    │    └─ Ветка «Совещание» — идущее/прошедшее совещание (стенограмма)
    │
    ├─ ДОСКА  (когда ветка не выбрана; клавиша B)
    │    ├─ область «Все офисы»: колонки по офисам × статус
    │    ├─ область «Офис X»: сегмент [Задачи | Направления | План]
    │    └─ полоса «Сейчас» (кто что делает) + композер «Кому: менеджер офиса»
    │
    └─ СТРАНИЦА  (меню «Разделы», клавиша раздела, палитра, ссылка)
         крошки «Офис › Раздел», «←», закрытие Esc
         ├─ РАБОЧЕЕ (≤ 2 уровней внутри)
         │    ├─ Офис (Сцена: человечки, пузыри, карточка сотрудника)   O
         │    ├─ Документы   (список слева, просмотр справа)            D
         │    ├─ Расходы     (Сегодня | Отчёт | Лимиты и бюджет)        E
         │    ├─ Команда     (В офисе | Маркет; список+деталь)          T
         │    ├─ Журнал      (журнал, инициативы, предложения)          J
         │    ├─ Ход работы  (События = Лог | Очередь слияния)          L / Q
         │    ├─ Выпуски     (3 вкладки как сейчас)                     R
         │    ├─ Совещания   (идущие, архив, форма созыва)              M
         │    └─ Терминал                                               Ctrl+`
         └─ РЕДКОЕ (до 3 уровней)
              ├─ Процессы     (4 вкладки как сейчас)                     P
              ├─ Настройки    (один дом)                                 S
              │    ├─ Офис: Проект · Правила · Окружение · Провайдеры ·
              │    │         Журнал (параметры) · … (8 разделов как сейчас)
              │    └─ Приложение: Внешний вид · Клавиши и справка ·
              │                   О приложении (что нового, обновление)
              ├─ Офисы (управление: порядок, иконка, архив, удаление)
              └─ Новый офис (мастер; быстрый путь — первый шаг)
```

### 1.4. Уровни и способы открытия (итог)

| Слой | Входы | Уровни |
|---|---|---|
| Ядро (Чат, Доска, Карточка задачи, Ждёт меня, Офисы, пауза) | Лента, `Enter`/`B`/`I`/`Space`, ⌘1–9 | ветка из Ленты: 1; запись Входящих: 0 |

## 2. Раскладка

### 2.1. Постоянные области (окно 1440 × 900, светлая и тёмная темы)

| Область | Размер | Что в ней | Поведение |
|---|---|---|---|
| **Верхняя строка** | высота 48, вся ширина | Слева кнопка области `[Все офисы ▾]` (190), `[Разделы ▾]` (110); по центру поиск/палитра (поле 320, «⌘K»); справа состояние «● 3 работают · ждёт меня 4», шкала лимита 96 × 8 с «62%», `[⏸]` | Фиксирована; разделов не содержит. Клик по «ждёт меня 4» ставит фокус на Входящие. Клик по шкале — Страница «Расходы» |
| **Лента** | ширина 320 (280–360 тянется), высота 852 | Три блока сверху вниз: Входящие, Ветки, Офисы | Прокрутка у каждого блока независимая; блок «Офисы» прижат вниз. Сворачивается до полосы 64 (`⌘\`) |
| ↳ **Входящие** | заголовок 40 + записи 96–136 каждая; по умолчанию до 400 | «ВХОДЯЩИЕ (4)», записи, «Ещё N» | Занимает не больше 45% Ленты; остальное прокручивается. Пусто — одна строка «Всё разобрано ✓» (высота 40), блок «Ветки» занимает освободившееся |
| ↳ **Ветки** | гибкий, ≥ 160 | Заголовок «ВЕТКИ» с `+`; строки по 44: чаты (💬), задачи в работе (▶), совещания (🗣) | Жирное — непрочитанное; выбранная — плашка. В области «Все офисы» группируются по офису; в области офиса — плоский список |
| ↳ **Офисы** | заголовок 40 + строка 56 × число офисов, не больше 5 строк, потом прокрутка | Состояние, число «ждёт меня», непрочитанное, «что делает» | Прижат вниз. При 1 офисе — один заголовок «Приложение ● работает ▾» (высота 40), без списка |
| **Центр** | 1120 × 852 при Ленте 320 | Заголовок 48 (название ветки или «Доска · область»; справа действия), тело, композер 72 | Одна из трёх форм. Один композер внизу, пишет менеджеру области (в «Все офисы» — менеджеру офиса из чипа «Кому») |
| **Полоса сигналов** | высота 36, по событию, **внутри Центра** над телом | Ошибка соединения, статус сборки/обновления | Не больше одной; закрывается ✕ или решением. Плашки окружения нет — она во Входящих |

Расчёт сетки F-экранов: Центр = 1440 − 320 = 1120; тело = 852 − 48 − 72 = 732.

| ≥ 1280 | 320, три блока | остаток (≥ 960) |
| 1024–1279 | 280 | остаток; в ветке «Задача» правая карточка 320 вместо 360 |
| 900–1023 | свёрнута в полосу 64: число во «Входящих», значки веток (без заголовков), точки офисов; по hover/клику выезжает на 320 **поверх** Центра (Центр не затемняется) | остаток |
| 640–899 | скрыта; кнопка `☰` слева в верхней строке с числом «ждёт меня»; открывается на всю ширину 320 поверх Центра | на всю ширину |
| < 640 | Лента — отдельный экран-«почта»; открытие ветки заменяет её, «←» возвращает | на всю ширину |

Ручное сворачивание `⌘\` — то же, что 900–1023, независимо от ширины. Состояние (свёрнута/развёрнута) запоминается между запусками.

**1–2 офиса.** Область «Все офисы» скрыта (при одном офисе её нет; при двух — есть, но по умолчанию выбран последний активный). Блок «Офисы» сворачивается в заголовок-меню «Приложение ▾», если офис один. Входящие и Ветки остаются: по сути «чат и доска с входящими». **5+ офисов.** Блок «Офисы» прокручивается; офисы можно закреплять; «спящие» (нет ожидания и работы, нет непрочитанного) сворачиваются в группу «Спят (N)»; Входящие не группируются, пока записей ≤ 7, после — по офису. Предел без группировки — 5–6 строк.

## 3. Проход по сценариям

Шаг = клик, клавиша или отправка сообщения от «владелец видит каркас офиса A» до завершения действия. «Сейчас» — оценки из scenarios.md; «станет» — расчёт по этому документу.

### С1. Поставить задачу и следить

1. Фокус в композер (`Enter`, либо он уже в фокусе на доске/в ветке «Менеджер»), набрать текст, отправить — **1 шаг** (набор не считается, как в варианте A).
2. Чип «T-14 в работе ▸» появляется в ветке «Менеджер», строка ▶ T-14 — в «Ветках», карточка — на доске.
3. Следить: клик по чипу (или по строке в «Ветках») — ветка «Задача T-14» (**2 шага**); или `B` — доска с подсвеченной новой карточкой (**2 шага**).

| Сейчас | Станет |
|---|---|
| ≈ 5 (Чат → чат → написать → отправить → Доска → карточка) | **1** поставить, **2** увидеть; без смены офиса |

### С2. Ответить на вопрос / согласовать

1. Запись появляется во «Входящих» сама, с звуком/тостом только для разрешения.
2. Ответ — кнопкой-вариантом в записи (**1 шаг**); свободным текстом — клик в поле записи, ввод, Enter (**2 шага**). Согласование макета: «Принять» (1), «Правки…» (поле + Enter, 2), «Открыть результат» (1 → ветка задачи, результат видно).
3. В чужом офисе тот же путь — переходить некуда.

| Сейчас | Станет |
|---|---|
| ≥ 4–5 (бейдж → сегмент → вкладка → ответ; чужой — ещё переключение) | **1–2**, из любого офиса и любой Страницы |

### С3. Понять, что происходит

1. Смотрю на экран: Входящие (что ждёт), Офисы (кто работает/ждёт/ошибка, 1 строка «что делает»), доска области (колонки), полоса «Сейчас» в доске.
2. Подробнее по одному офису — клик по офису (1) и строка «что делает» раскрывается полосой «Сейчас» на доске.
3. Картинка со сценой — `O` (1 шаг), как раньше, но не нужна для ответа на вопрос «что сейчас».

| Сейчас | Станет |
|---|---|
| 3 перехода (сцена → доска → лог) | **0** (взгляд), 1 при выборе офиса |

### С4. Несколько офисов параллельно

1. Переключение не требуется: все офисы и их ожидание в Ленте.
2. Войти в «рабочее место» офиса: клик по офису или `⌘2…9` — **1 шаг**; обратно в «Все офисы» — `⌘1` или «←» — **1 шаг**.
3. Место сохраняется по областям (§5.1): последняя ветка, открытая Страница, прокрутка, раскрытые группы, фильтры, черновик.
4. Ответ в чужом офисе — запись во Входящих (С2).

| Сейчас | Станет |
|---|---|
| 1 клик + потеря вида, карточки, групп; ожидание чужих — только на главном экране | **0** для ответа и обзора; **1 / 1** для смены области, место сохранено |

### С5. Разобрать вставшую работу

1. Запись во Входящих «T-12 сорвана: лимит плана, сброс в 18:20 · [Перезапустить после сброса] [Переназначить] [Открыть]» — причина в одной строке; действие — **1 шаг**.
2. Нужна подробность — «Открыть» → ветка «Задача T-12»: блок «Что случилось» (последние события, ревью, слияние) (**2 шага**).
3. Полный лог — «Все события задачи →» → Страница «Ход работы», фильтр по задаче (**3 шага**).

| Сейчас | Станет |
|---|---|
| ≈ 4–5 (доска → карточка → дифф + лог + очередь + чат) | **1–3** |

### С6. Посмотреть результат

1. С доски: клик по карточке → ветка, справа «Результат» с превью/ссылкой (**1**), открыть файл/документ/макет (**2**).
2. Из записи согласования: «Открыть» — **1**.
3. Документы офиса: `D` → документ в списке → просмотр справа — **2 шага** (3–4 сейчас).

| Сейчас | Станет |
|---|---|
| 3–4 | **2** |

### С7. Выпустить версию

1. Запись во Входящих: «Выпуск 0.13.0 (minor): 5 фич. [Выпускай] [Другая версия…] [Не сейчас] [Что войдёт →]» — решение **1 шаг**.
2. Подробности — «Что войдёт →» → Страница «Выпуски» (**2 шага**); контроль выпуска — там же, тост по результату.

| Сейчас | Станет |
|---|---|
| ≈ 2–3 + нет связи между вопросом и видом | **1–2**; вопрос и Страница связаны ссылкой |

### С8. Настроить команду

1. `T` → Страница «Команда» со списком и первым сотрудником (**1 шаг**).
2. Клик по сотруднику — деталь справа (**2**), вкладка «Бриф» / «Модель» (**3**).
3. Найм: «Маркет» (**2**) → карточка пакета (**3**) → «Нанять» (**4**). Экспорт: «⋯» → «Экспорт пакета» (**4**).
4. Короткий путь: ⌘K → «Backend бриф» — **2**.

| Сейчас | Станет |
|---|---|
| 4–5 (самое глубокое место) | **3** (4 для найма/экспорта) |

Принцип 9 (≤ 2 для рабочего) здесь нарушен на 1 — см. §6.

### С9. Деньги и лимиты

1. Глянуть: шкала в верхней строке — **0 шагов**.
2. Разобрать: `E` → Страница «Расходы» (**1**) → сегмент «Отчёт» (**2**).
3. Притормозить: `[⏸]` / `Space` (**1**) в области; бюджет — на той же Странице (**2–3**).

| Сейчас | Станет |
|---|---|
| ≈ 3 (шкала → «Расходы» → «Отчёт»-модалка), пять мест | **0** глянуть / **2** разобрать; один дом |

### С10. Настроить офис

1. `S` → Настройки (**1**) → раздел слева, например «Провайдеры» (**2**) → поле/ключ, сохранить (**3**).
2. По сигналу плашки: запись «Нет провайдера — [Выбрать]» открывает Настройки сразу в разделе (**1–2**).
3. «Проект» — форма внутри раздела на Странице, не модалка. Процессы: `P` → вкладка — **2**.

| Сейчас | Станет |
|---|---|
| 2–4, пять входов, формы по-разному | **2–3**, один дом, все формы на Странице |

### С11. Первый запуск и новый офис

1. Первый запуск: Центр на весь экран, три шага — «Подключите движок» → «Назовите офис и выберите папку» → «Первая задача» (**3 экрана**); Ленты и главного экрана нет.
2. Новый офис: «+» в блоке «Офисы» (**1**) → имя + папка (ввод, **2**) → «Создать» (**3**); дальше шаги по желанию.

| Сейчас | Станет |
|---|---|
| ≈ 4 перехода + 5 шагов мастера, два пути | **3** экрана при первом запуске; **3** шага для быстрого нового офиса |

### С12. Совещание

1. `M` → Страница «Совещания» с формой созыва (**1**) → «Созвать» (**2**).
2. Идущее совещание — строка 🗣 в «Ветках»; клик (**1**).

| Сейчас | Станет |
|---|---|
| ≈ 2 (`M` → модалка), просмотр — отдельный док | **2**; без модалок |

## 4. Ключевые экраны

Обозначения: `█` — выбрано/активно, `●` — работает/ждёт, `○` — простой, `⏸` — пауза, `⚠` — ошибка, `▮` — шкала.

## 5. Состояния и правила

### 5.1. Что с чатом и доской, пока открыта Страница

- Страница **заменяет Центр**; Лента остаётся целиком: Входящие, Ветки, Офисы продолжают обновляться (принцип 1: чат и доска — 1 клик из любой Страницы).
- Клик по ветке в «Ветках» или кнопка «Доска (`B`)» закрывает Страницу и открывает то, что выбрано. `←`, Esc и повтор клавиши раздела делают одно и то же: возврат туда, откуда вошли на Страницу (стек возврата — одно место; переход Страница → Страница заменяет, а не накладывает).
- Композер: на Странице его нет ; **черновик сохраняется** на ветку/область. `Enter` — вернуться в последнюю ветку с фокусом в композере.
- **Место по областям.** Для каждой области хранится: последняя ветка, открытая Страница и её вложенность, прокрутка, раскрытые группы фич, фильтр доски, сегмент «Задачи/Направления/План». Смена области возвращает ровно туда. Состояние сохраняется между запусками.
- **Терминал** при уходе со Страницы не завершается; возврат — та же сессия (допущение: по аудиту судьба сессий при смене офиса неизвестна, нужно проверить).
- Esc — цепочка из трёх шагов: закрыть режим внутри ветки (дифф) → закрыть Страницу/ветку → фокус на Ленте. Выход «на главный экран» отсутствует.

### 5.2. Входящие: что входит, приоритет, закрытие

| Приоритет | Запись | Сигнал |
|---|---|---|
| 0 | Запрос разрешения инструмента | Закреплена сверху; тост + звук; красная точка в верхней строке |
| 1 | Вопрос `ask_owner`; согласование макета/исследования | Тост, если окно не в фокусе |
| 2 | Сорванная/вставшая задача; слияние не прошло; вопрос о выпуске; предложение офиса; «Нет провайдера» | Без звука; точка и число |

Правила:
- Во Входящие попадает только то, что требует **решения владельца**. Непрочитанное сообщение в чате — не запись; оно подсвечивает ветку и офис.
- Запись закрывается действием; если вопрос снят где-то ещё (ответ в чате, задачу сняли) — исчезает сама, строка «разобрано в чате» 5 секунд.
- «Отложить» (`⌫`): час / до завтра; возвращается с пометкой. Отложенные — свёрнутая строка «Отложено (N)».
- Порядок: приоритет, внутри — по времени. Видно 3–4, остальное «Ещё N» (разворачивает без перехода). > 7 записей — группировка по офису.
- Число — «ждёт меня» в верхней строке, в блоке «Офисы» у каждого офиса и в заголовке окна (`9+` потолок).
- Нужно решение владельца: что именно считается «предложением офиса» и входит ли оно во Входящие по умолчанию (см. §7).

### 5.3. Уведомления из других офисов

1. Событие приходит → запись появляется во Входящих сверху своей группы (подсветка 2 с), число у офиса растёт.
2. Если окно в фокусе: только запись; приоритет 0 дополнительно — тост и звук.
3. Если окно не в фокусе: число в заголовке окна / бейдж иконки приложения; приоритет 0–1 — системное уведомление, клик по которому открывает именно запись (область переключается автоматически).
4. Пока открыта Страница или чужая ветка, запись видна в Ленте, ничего не перекрывает.
5. Состояние офиса (работает / пауза / ошибка) — точка в строке офиса; ошибка офиса — ещё запись приоритета 2 «⚠ Лендинг: сервер офиса недоступен».

### 5.4. Горячие клавиши

Сохранены: `B` — доска, `Enter` — последняя ветка и композер, `Space` — пауза области, `E` расходы, `L` лог, `Q` очередь, `R` выпуски, `P` процессы, `J` журнал, `M` совещания (теперь открывает Страницу «Совещания»), `Ctrl+\`` терминал, `1`–`9` на Странице «Офис».

Новые (допущение: владелец допускает смену; concepts.md, вопрос 5):

| Клавиша | Действие |
|---|---|
| `⌘K` | палитра: разделы, ветки, задачи, документы, сотрудники |
| `⌘1` | область «Все офисы»; `⌘2…9` — офисы; `⌘↑/⌘↓` — соседняя область |
| `I` | фокус на Входящие; `↑/↓` — по записям, `1…4` — кнопка записи по порядку, `⌫` — отложить |
| `⌘N` / `⌘⇧N` | новый чат / новый офис |
| `O`, `D`, `T`, `S` | Офис (сцена), Документы, Команда, Настройки |
| `⌘\` | свернуть / развернуть Ленту |
| `?` | справка по клавишам |

Клавиши разделов действуют в области (в «Все офисы» — для последнего активного офиса; название офиса видно в крошках). Не срабатывают в поле ввода. Пустых ячеек «слой × клавиша × вход» нет: у каждого рабочего пункта есть клавиша, пункт меню «Разделы» и запись в палитре.

### 6.3. К11 — как посчитано

Пункты постоянного каркаса: Входящие, Ветки, Офисы, Доска (кнопка/вид), Состояние+пауза — ядро (5); «Разделы ▾» — меню с рабочим и редким слоем (1). Итого 5 / 6 ≈ 83%. Если считать пунктом каждый раздел меню (9 рабочих + 4 редких), доля падает до 5/18 ≈ 28% — но они не в постоянной области, а в меню (по принципу 6 не считаются).

### 6.4. Слабые места (честно)

1. **Чат и доска не видны вместе.** Для владельца, который ведёт 1 офис диалогом «пишу — смотрю на доску», B хуже A. Смягчение: чипы карточек в чате и строка «Сейчас» в ветке; полностью не лечится.
2. **Стоимость миграции высокая.** Нужны: новая сущность «Входящие» по всем офисам, область «Все офисы» (агрегат доски), единая ветка «Задача» (склейка карточки, диффа и результата), полная ломка рейла и доков. Пока этого нет, B неосуществим по частям: сначала нужен единый список «ждёт меня» (общий для всех вариантов).
3. **Входящие легко превращаются в свалку.** Спасают только правила §5.2 (что входит, приоритет, откладывание); без решения владельца об «предложениях офиса» список может зарасти.
4. **Лента постоянно занимает 320 px.** Для одного офиса избыточна; на 900–1023 переходит в полосу и «ждёт меня» перестаёт быть читаемым.
5. **Рабочее спрятано за меню «Разделы».** Документы, Расходы, Лог — на втором клике; без клавиши и без привычки владелец их не найдёт. Принцип 10 выполнен, но «видимый вход» — один выпадающий список.
6. **Команда — 3 шага, глубже цели.** Список+деталь помогает, но «Команда → сотрудник → вкладка» остаётся.
7. **Терминал на Странице** отделён от чата и доски; тот, кто сверяется с логом и пишет менеджеру, будет прыгать.
8. **Сцена «Офис» — вторична.** Если владелец смотрит на неё как на главный экран (вопрос 2), B теряет смысл (сцена показывает один офис, B — все). Витрина мини-сцен — только заплатка.
9. **Привычка «я в офисе» ослабевает.** Область «Офис X» — фильтр, а не место; владельцы, мыслящие офисом как местом, могут растеряться.
10. **Числа шагов** — расчёт, не замер: проверять прогоном на макете.

## 7. Отступления от концепции

Концепция варианта B в `concepts.md` не менялась. Дыры, которые закрыты здесь:

| № | Дыра в концепции | Решение в спеке |
|---|---|---|
| 1 | Не сказано, кому пишет композер в области «Все офисы» | Чип «Кому: Менеджер · офис ▾», по умолчанию — последний активный офис |
| 2 | Не сказано, что значит «пауза» в области «Все офисы» | Пауза **области**; в «Все офисы» — «Пауза всех» с подтверждением; пауза одного офиса — меню офиса и `[⏸]` в области этого офиса |
| 3 | Вход в разделы — только «клик по имени офиса» и палитра: скрытый вход (принцип 10) | Видимая кнопка `[Разделы ▾]` в верхней строке; то же меню по клику на офис в Ленте; палитра как дополнительный вход |
| 4 | Не описано, что значит открытая Страница в области «Все офисы» | Страница принадлежит последнему активному офису (крошки показывают его); без офиса — Настройки приложения, Новый офис, Расходы (сводка), Офисы |
| 5 | Ветка «Задача» названа, но не разложена | Две колонки: разговор (760) + карточка (360: статус, результат, «Что случилось», изменения); дифф — режим внутри ветки с «←» |
| 6 | Что именно в блоке «Ветки» и когда исчезает | Чаты, задачи в работе или требующие внимания, идущие совещания; закрытые задачи — только на доске; чаты архивируются |
| 7 | Правила «Входящих» не заданы (концепция сама называет это риском) | §5.2: что входит, приоритеты, закрытие, откладывание, группировка |
| 8 | «Что показывать, когда ветка не выбрана» — настройка есть, умолчание Доска | Умолчание подтверждено; значение «Сцена» — в Настройки › Приложение › Внешний вид |
| 9 | Два пункта «Очередь» и «Лог» не сказаны как одно | Слиты в Страницу «Ход работы» (сегменты «События | Очередь слияния»); клавиши `L` и `Q` сохранены |
| 10 | Судьба карточки сотрудника при отсутствии дровера | Клик по человечку → ветка текущей задачи, иначе «Команда» |
| 11 | Идущие совещания не имели места | Строка 🗣 в «Ветках» + Страница «Совещания» |
| 12 | Вопрос «нужно ли показывать область Все офисы при 2 офисах» | Показывается (скрыта только при 1 офисе) |

**Открытые решения владельца** (не блокируют, допущения выше): состав «Входящих» по умолчанию (входят ли инициативы и предложения); нужна ли витрина мини-сцен; допустима ли смена клавиш.
