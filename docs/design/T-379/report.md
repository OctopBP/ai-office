# Пилот Penpot (T-379): отчёт

**Итог: пилот не проведён.** Инструменты Penpot MCP в сессию дизайнера не попали, поэтому ни токены, ни шапка в Penpot не сделаны. Ничего не измерено и не придумано.

Файл отчёта лежит в `docs/design/T-379/`, а не в `docs/design/penpot-pilot/`: запись за пределы папки задачи требует подтверждения. Если нужен путь из задачи, файл надо перенести.

## Ссылка на файл Penpot

Файла нет: его не создавали.

## Что выяснено

- Сервер `penpot` описан в `src/server/mcp.ts:133` (T-378): `@penpot/mcp`, плагин в активной вкладке редактора, инструкция в `docs/design/penpot-mcp/setup.md`.
- В набор инструментов этой сессии он не подключился. Были только `mcp__figma-bridge__*` и `mcp__office__*`; никаких `execute_code`, `high_level_overview`, `penpot_api_info`, `export_shape` или `import_image`.
- Вероятные причины, по убыванию:
  1. Сервер Penpot не запущен владельцем (`npx @penpot/mcp@stable`, порты 4401/4402).
  2. Не открыта вкладка Penpot с запущенным MCP-плагином.
  3. Роль design запущена до T-378, и сессия не подхватила новый сервер.
  4. Сервер не включён в настройках роли.
- Проверить, какая из причин верна, из этой сессии нельзя: порты локальной машины песочница не даёт ни слушать, ни проверять.

## Что нужно от владельца

1. Запустить `npx @penpot/mcp@stable` (Node 22) или включить удалённый MCP в настройках аккаунта Penpot.
2. Открыть в браузере файл Penpot, запустить MCP-плагин и оставить вкладку активной.
3. Убедиться, что у роли design включён сервер `penpot`, и перезапустить сессию дизайнера.
4. Завести задачу повторно. Задел: токены из `src/web/styles/tokens.css`, затем шапка по `docs/design/T-349/spec.md` (образец — `docs/design/T-352/figma.md`).
