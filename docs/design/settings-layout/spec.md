# Вкладки настроек: аудит вёрстки и план исправлений (T-181)

Владелец жалуется, что вкладки настроек «съехали»: блоки слились, не видно, где кончается одна группа и начинается другая. Ниже — что именно сломано, почему, единый шаблон вкладки на существующих токенах и разбиение правок на порции для разработчика.

Анализ статический: читал исходники и CSS, в браузере не гонял. Номера строк ориентировочные — сверяйтесь с файлом перед правкой. Код этой задачей не меняется.

## 1. Корневая причина

Формы настроек раньше жили в модалке. Стили полей (`label`, `.hint`, `.row2`, `label.checkbox`, `label.slider`, `h4`) лежат в `src/web/styles/modal.css` (≈74–118) и заскоуплены на `.modal` и `.team-detail`. Коммит T-172 (9dce0d4) перенёс настройки офиса и приложения на страницу оболочки (`ShellPage`, `.shell-page-body` в `shell.css` ≈73–92), а стили остались под старыми селекторами. На странице настроек `.modal` уже нет, поэтому:

- `label` не получает `display: block` и отступ снизу — поля идут вплотную, друг за другом;
- `.hint` теряет цвет, кегль и отступы — подсказка выглядит как обычный текст;
- `.row2` не становится двумя колонками;
- `label.checkbox`, `label.slider`, `h4` остаются в стилях браузера.

Поверх этого `settings.css` (42 строки) лечит только часть симптомов: поля `.section-title` и `.hint`. Остальное держится на том, что вкладка «Роль» в `.team-detail` стилей не потеряла, и поэтому выглядит иначе, чем вкладки офиса, хотя строится из тех же классов. Итог — три разных вида «настроек» при одном и том же содержимом.

Вторая, мелкая причина: каскад. `button.on:hover:not(:disabled)` (специфичность 0,3,1) из кита перебивает `.settings-nav button.on` (0,2,1), поэтому активный пункт меню при наведении теряет подсветку.

## 4. Единый шаблон вкладки

Принцип: один набор классов `.form-*`, не зависящий от контейнера (`.modal`, `.settings-content`, `.team-detail`, `.menu`). Только существующие токены, новых цветов нет. Все три страницы (офис, приложение, роль) переходят на него.

### Структура

```
<div class="form">                         ← колонка вкладки
  <section class="form-section">
    <header class="form-section-head">
      <h3 class="form-section-title">Заголовок группы</h3>
      <p class="form-section-desc">Одно-два предложения: зачем эта группа.</p>
    </header>
    <div class="form-rows">
      <div class="form-row">               ← «подпись — поле — подсказка»
        <div class="form-row-label">
          <label for="…">Подпись</label>
          <span class="form-hint">Подсказка под подписью.</span>
        </div>
        <div class="form-row-control"> …поле… </div>
      </div>
      <label class="form-check">           ← строка-переключатель
        <input type="checkbox" />
        <span class="form-check-text">Текст <span class="form-hint">Подсказка</span></span>
      </label>
    </div>
  </section>
  <section class="form-section form-section-danger"> … </section>
</div>
```

### Стили (эскиз для `src/web/styles/forms.css`)

```css
.form { display: flex; flex-direction: column; max-width: 720px; }

.form-section { padding-top: var(--space-6); margin-top: var(--space-6); border-top: 1px solid var(--hairline); }
.form-section:first-child { padding-top: 0; margin-top: 0; border-top: none; }

.form-section-title { margin: 0 0 var(--space-1); font: 600 var(--fs-md)/1.3 var(--font); color: var(--ink); }
.form-section-desc  { margin: 0 0 var(--space-4); font-size: var(--fs-body); line-height: 1.45; color: var(--ink-3); }

.form-rows { display: flex; flex-direction: column; gap: var(--space-4); }

.form-row-label label { display: block; font-size: var(--fs-md); color: var(--ink-2); }
.form-hint { display: block; margin-top: var(--space-1); font-size: var(--fs-small); line-height: 1.4; color: var(--ink-3); }
```

### Таблица отступов

| Расстояние | Значение | Токен |
|---|---|---|
| Между группами (линия + воздух с обеих сторон) | 24 + линия + 24 | `--space-6`, `--hairline` |
| Заголовок группы → описание | 4 | `--space-1` |
| Описание → первая строка | 16 | `--space-4` |
| Между строками внутри группы | 16 | `--space-4` |
| Подпись → подсказка | 4 | `--space-1` |
| Подпись ↔ поле (колонки) | 24 | `--space-6` |
| Подпись ↔ поле (узко, колонкой) | 8 | `--space-2` |

Правило различимости: расстояние между группами (48 с линией) всегда минимум втрое больше расстояния внутри группы (16 → 4 до подсказки). Раньше они почти совпадали — это и есть «слипание».

### Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Заголовок секции | 13px / 600 / `--ink` вместо 10px капсом `--ink-3` | Десятикегльный серый заголовок слабее подписей полей, поэтому группа не читается. Кегль из шкалы (`--fs-md`), без нового токена |
| Описание группы | `--fs-body`, `--ink-3` | Одна роль текста — вторичный, как `.muted` |
| Разделитель | `border-top: 1px solid var(--hairline)`, а не карточка с фоном | Карточки в карточке (`.shell-page-body.card.fixed`) дали бы двойную рамку; линия уже используется в `.danger-zone`, `.settings-elsewhere`, `.role-export` |
| Подсказка | `--fs-small`, `--ink-3` | Совпадает с существующим `.hint` в ките |
| Подпись поля | `--fs-md`, `--ink-2` | Так уже выглядит у офиса; у роли `--ink-3` заменяется на `--ink-2` |
| Двухколонная строка | подпись слева 220px | Короткие поля не растягиваются на всю ширину; на ≤720px складывается в колонку |
| Опасная группа | тот же шаблон, заголовок `--danger` | Единое правило и для офиса, и для роли |
| Вложенные карточки (`.mcp-item`, `.engine`, `.report-cell`) | остаются на `--film` и `--radius-card`, внутри `.form-rows` | Это элементы, не группы |
| Ширина | `max-width: 720px` | Длинные `textarea` и сетка в две колонки читаются лучше; на широком окне пустота справа допустима |
| Поля ввода, кнопки, `.seg`, `.tabs`, `.chip` | не трогаем | Кит (`kit.css`) уже даёт их вид; чиним только раскладку вокруг |

## 5. Порции для разработчика

Порции независимы по файлам, кроме порции 1: она вводит `.form-*` и должна влиться первой. Порции 2–4 идут параллельно после неё и могут быть разобраны разными разработчиками (в том числе `backend`/`backend-2`/`backend-3` — по решению владельца нагрузка делится поровну). `SettingsPage.tsx` большой: порция 2 разбита по вкладкам, читать файл срезами.

### Порция 1. Основа: `.form-*`, меню, стенд

Файлы:
- `src/web/styles/forms.css` — новый, стили из раздела 4;
- `src/web/styles/index.css` — `@import './forms.css';` рядом с `settings.css`;
- `src/web/styles/settings.css` — убрать правила, которые переезжают (`> .section-title`, `.hint`, `label:last-child`), оставить раскладку `.settings-layout`/`.settings-nav`/`.settings-content` и `.settings-elsewhere`; выровнять `padding` с `.team-detail` (20px 24px); исправить `.settings-nav button.on` на специфичность, перебивающую `button.on:hover:not(:disabled)` (например `.settings-nav button.on, .settings-nav button.on:hover:not(:disabled)`);
- `src/web/KitBench.tsx`, `kit-bench.css` — секция «Поля» (≈142–148) показывает шаблон `.form` на примере: группа, строка с подсказкой, чекбокс, опасная группа.

Приёмка:
- `?kit=1` рисует шаблон в светлой и тёмной теме;
- в `forms.css` нет ни одного цветового литерала и нового токена, только `var(--…)`;
- при наведении на активный пункт меню подсветка остаётся.

### Порция 2. Настройки офиса

Файлы:
- `src/web/SettingsPage.tsx` — все семь разделов на шаблон (читать срезами: 223–293, 295–375, 377–476, 478–581; `Slider` 48–71 переделать в `.form-row` с значением справа);
- `src/web/McpCatalog.tsx` — список и форма добавления в `.form-rows`;
- `src/web/OfficeIcon.tsx` — `OfficeIconSetting` как строка `.form-row`;
- `src/web/styles/offices.css` — `.engine` и `.office-icon-setting`: убрать собственные внешние отступы, оставить внутренние;
- `src/web/styles/team.css` (только блок 132–157: `.mcp-*`, `.role-mcp`) — отступы между карточками, перенос `.mcp-head` (`flex-wrap: wrap`);
- `src/web/i18n/ru.ts`, `src/web/i18n/en.ts` — заголовки и описания групп.

Приёмка:
