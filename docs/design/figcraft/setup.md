# figcraft у дизайнера: что сделать владельцу

figcraft — открытый клон Figma на Rust (MIT или Apache-2.0, альфа). Мы
пробуем его **пилотом рядом с Penpot**, Figma он не заменяет. Разбор и план
пилота — документ офиса D-4, раздел 7.

Инструкция под **0.6.0**. Запись в каталоге сверена с <https://figcraft.run/mcp>
и проверена живой MCP-сессией (T-595, итоги — в конце).

В каталоге MCP офиса (`src/server/mcp.ts`) есть сервер `figcraft`:

```
figcraft-cli mcp --no-system-fonts
```

Это stdio: офис сам запускает CLI на каждую сессию дизайнера. Окно figcraft,
плагин и ключи не нужны — движок работает внутри процесса (headless).
`--no-system-fonts` берёт только встроенные шрифты, так что макет рендерится
одинаково на любой машине. Кириллица во встроенных шрифтах есть (Inter, Roboto,
Open Sans и др.).

По умолчанию сервер **никому не подключён**: на время пилота его включают
дизайнеру вручную, галочкой.

## 1. Поставить figcraft-cli 0.6.0

CLI для macOS — отдельный архив, в десктопное приложение он не входит:
`figcraft-cli-0.6.0-macos-universal.zip` (~77 МБ) из релиза v0.6.0 на
<https://github.com/storytold/figcraft/releases> или со страницы
<https://figcraft.run/mcp>. В архиве — папка с бинарником `figcraft-cli`,
README, лицензиями и `OFL-*.txt` шрифтов. Скриптов установки нет, и запускать
из архива ничего, кроме `figcraft-cli`, не нужно.

SHA-256 архива, который проверялся в T-595:
`119446cc8f50b719dad7a73e0356de6194aa262b6520b362dfe310ee9f05b3be`.

Ставим в отдельную пустую папку под версию, а офису показываем её симлинком.
Скопируйте в терминал целиком:

```sh
mkdir -p ~/.office/tools/figcraft-0.6.0 ~/.office/tools/bin
shasum -a 256 ~/Downloads/figcraft-cli-0.6.0-macos-universal.zip
unzip -q ~/Downloads/figcraft-cli-0.6.0-macos-universal.zip -d ~/.office/tools/figcraft-0.6.0
F=~/.office/tools/figcraft-0.6.0/figcraft-cli-0.6.0-macos-universal/figcraft-cli
codesign --verify --strict -v "$F"
codesign -dv "$F" 2>&1 | grep -E 'Identifier|TeamIdentifier'
spctl -a -t open --context context:primary-signature -vv "$F"
xattr -l "$F"
ln -sf "$F" ~/.office/tools/bin/figcraft-cli
~/.office/tools/bin/figcraft-cli --version
```

Что должно получиться:

- `codesign --verify` — `valid on disk` и `satisfies its Designated Requirement`;
- `Identifier=ai.storyteller.figcraft-cli`, `TeamIdentifier=DJ6XS33FX8`;
- `spctl` — `accepted`, `source=Notarized Developer ID`. Команда
  `spctl -a -t exec` на голом бинарнике может ответить «not an app» — для
  консольных программ это нормально, смотрите вариант с `-t open` выше;
- `xattr` — может быть `com.apple.quarantine`. Подписанный и заверенный
  бинарник запускается и с ним. Если macOS всё же откажет («не удаётся
  проверить разработчика») — `xattr -d com.apple.quarantine "$F"`;
- `--version` печатает `figcraft-cli 0.6.0`.

CLI сам не обновляется. Новая версия ставится рядом в
`~/.office/tools/figcraft-<версия>/`, а переключается одним `ln -sf`. Откат —
тот же `ln -sf` на старую папку. Обновлять лучше по решению пилота: формат и
команды figcraft меняются от релиза к релизу.

## 2. Где офис ищет бинарник

В каталоге записано голое имя `figcraft-cli`. Путь к бинарнику офис
определяет при запуске сессии (`toolCommand` в `src/server/mcp.ts`):

1. **`FIGCRAFT_CLI`** — переменная окружения сервера офиса с полным путём. Это
   способ переопределить путь, например когда бинарник лежит в другом месте.
2. **`~/.office/tools/bin/figcraft-cli`** — место по умолчанию. Для него и
   нужен симлинк из раздела 1.
3. **`PATH`** — если ни переменной, ни файла нет.

Почему не просто `PATH`: приложение офиса для macOS запускается из Finder и
берёт `PATH` у входного шелла (`zsh -ilc`). Если шелл не ответил за 4 секунды
(медленный `.zshrc`), остаётся системный `PATH` с `/usr/local/bin` и
`/opt/homebrew/bin`, но без `~/.local/bin`. Путь из пункта 2 от шелла не
зависит.

Третий способ — вписать в каталоге (**Настройки офиса → Инструменты → FigCraft**,
поле команды) полный путь вместо `figcraft-cli`. Полный путь запускается как
есть, но тогда он хранится в настройках этого офиса.

## 3. Включить сервер дизайнеру

1. В левой панели открыть окно **«Команда и маркет»**, вкладка
   **«В офисе»**.
2. В списке слева выбрать сотрудника роли **«Дизайн»**. В его карточке —
   вкладка **«Доступ и инструменты»**, блок **«Внешние инструменты»**.
3. Поставить галочку **FigCraft**. Остальные галочки (Figma, Figma Console,
   Penpot) не трогать — пилот идёт параллельно. Галочка сохраняется сразу и
   относится к роли целиком, а не к одному сотруднику.

Строка **FigCraft** в этом блоке есть у любой роли и у любого офиса, даже
заведённого до 0.14.0-beta.1: каталог, который получает интерфейс, сервер
доливает умолчаниями (до T-602 интерфейс брал сохранённый каталог офиса как
есть, и у старых офисов FigCraft там не было). Нужен только сервер офиса не
старше этой правки: из репозитория — перезапустить сервер офиса (`npm run dev`)
после `git pull`; приложение для macOS — обновить до выпуска с T-602. Каталог
в приложении берётся из того же кода сервера, отдельного списка у него нет.

Если `figcraft-cli` не найден ни одним из трёх способов из раздела 2, под
строкой **FigCraft** видна подсказка: что скачать и куда положить. Галочку
можно поставить и до установки; подсказка пропадёт после установки бинарника
и перезагрузки окна офиса. Без бинарника сессия дизайнера поднимется, но
FigCraft у неё не подключится — см. раздел 4.

Тот же сервер виден и в **«Настройки офиса» → «Инструменты»**: там его можно
выключить для всех ролей разом или поправить команду.

Сервер подключается со следующей сессии дизайнера, уже идущую задачу это не
меняет. Снять пилот — снять галочку.

## 4. Проверить, что сервер подключился

Статус приходит от живых сессий, поэтому сначала дайте дизайнеру любую задачу
(например, пилотный макет FC-2). Затем в **Настройки → Инструменты** у строки
**FigCraft** должен стоять статус **«подключён»** (`connected`).

- **«не подключился»** (`failed`) — офис не нашёл или не смог запустить
  `figcraft-cli`. Проверьте `ls -l ~/.office/tools/bin/figcraft-cli` и
  `~/.office/tools/bin/figcraft-cli --version`; симлинк должен указывать на
  существующий файл. Затем перезапустите офис.
- **«пока неизвестно»** — ни одна сессия с сервером ещё не запускалась.

Проверить сервер руками без офиса (ответ — строка JSON с
`"serverInfo":{"name":"figcraft","title":"FigCraft","version":"0.6.0"}`):

```sh
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"check","version":"0"}}}' \
  | ~/.office/tools/bin/figcraft-cli mcp --no-system-fonts
```

Каталог команд без MCP: `~/.office/tools/bin/figcraft-cli commands --filter layout`.

## 5. Режим `--attach`: агент правит открытое окно

По умолчанию дизайнер работает headless — документ живёт в процессе сервера и
пропадает с концом сессии, если его не сохранить (`save_file`). Чтобы смотреть
правки вживую, figcraft умеет вести открытое приложение:

1. Запустить приложение с каналом управления на порту (по документации
   figcraft, в T-595 вживую не проверялось — из песочницы GUI не запустить):

   ```sh
   /Applications/FigCraft.app/Contents/MacOS/FigCraft --control 7979
   ```

   Канал слушает только `127.0.0.1`, снаружи машины до него не достучаться.
2. В **Настройки → Инструменты** добавить свой сервер, например `figcraft-app`:
   stdio, команда `figcraft-cli`, аргументы `mcp --attach 7979`. Офис найдёт
   бинарник по тем же правилам, что в разделе 2.
3. Поставить дизайнеру галочку `figcraft-app` вместо `figcraft`.

Оговорки:

- Порт один на машину — значит, один дизайнер за раз.
- Если приложение не запущено, сервер сразу завершается с ошибкой
  `can't reach the FigCraft app at 127.0.0.1:7979 … (start it with figcraft --control PORT)`,
  и статус будет «не подключился».
- Агент правит **ваш открытый документ**: несохранённое в нём он может
  изменить. После обрыва связи вызовы сами не повторяются — агент должен
  перечитать документ, прежде чем править снова.

## 6. Что помнить

- **«Share ▸ Online» макеты офиса не отправлять.** Эта кнопка загружает файл
  на `collab.craftapps.dev`, и, как прямо пишут авторы, **без сквозного
  шифрования**. Файл видит сервер чужого проекта. «Share ▸ Local network» тоже
  без шифрования. Если нужен совместный просмотр — только свой
  `figcraft-server`.
- **У сервера нет периметра записи.** `save_file` и `export` с `path` пишут
  куда угодно на диске. Сам figcraft помечает `export` как чтение даже с
  `path`, но офис строже: это запись, и она спрашивается по правилам
  разрешений. Дизайнеру велено писать только внутрь рабочей копии.
  `screenshot` и `export` без `path` (картинка или SVG возвращаются в ответ) —
  чтение, без вопроса.
- **Это альфа.** Падения, смена команд и формата `.figcraft` между релизами —
  ожидаемы. Реальные `.fig` из Figma ещё не проверены (это задача FC-3).

## Живая проверка 0.6.0 (T-595, 2026-10-16)

Бинарник из архива выше, `figcraft-cli mcp --no-system-fonts`, построчный
JSON-RPC по stdio:

| Запрос | Результат |
|---|---|
| `initialize` | `serverInfo` figcraft 0.6.0, протокол `2025-06-18`, есть `instructions` (~1,4 КБ); ответ 1 615 байт |
| `tools/list` | **18 инструментов, 16 720 байт**. Имена те же, что в 0.5.1: `list_commands`, `run_command`, `batch`, `create_node`, `set_properties`, `inspect_document`, `get_node`, `select`, `export`, `screenshot`, `open_file`, `save_file`, `undo`, `redo`, `pointer`, `key`, `type_text`, `inspect_ui` |
| `list_commands {filter: "layout"}` | 17 команд, 6 926 байт |
| `inspect_document {depth: 2}` | пустой документ «Untitled», одна страница; 521 байт |
| `create_node {type: "frame", 320×200}` | узел `id: 2`, кириллическое имя сохранилось; 530 байт |
| `screenshot {}` | PNG 320×200 картинкой MCP; 2 574 байта |
| `export {format: "svg"}` без `path` | SVG текстом в ответе; 303 байта |
| `resources/list`, `prompts/list` | `figcraft://document`, `figcraft://commands`; промпты `mobile_screen`, `design_system`, `landing_page`, `prototype_flow` |

Что поменялось против 0.5.1: у `screenshot` появился параметр `window`, у
`export` — опции печати и SVG (`bleed`, `cmyk`, `svgOutlineText`…), у
`create_node` — `path` и `text`. Набор и имена инструментов прежние. В
`instructions` сервер сам упоминает ресурс `figcraft://command/{id}`, а в
`resources/list` его нет — это шаблон, на работу не влияет.

Префикс дизайнера: схемы инструментов с `alwaysLoad` — около 16,7 КБ, то есть
порядка 4–5 тысяч токенов, плюс `instructions` сервера. Для сравнения: у
figma-console инструментов больше сотни.
