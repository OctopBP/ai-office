## Не удалено и почему

### Песочница: 75 worktree и 17 веток при них

`--apply` на каждой копии упал так:

```
error: failed to delete '<…>/worktrees/o-2/T-108': Operation not permitted
error: failed to delete '.git/worktrees/T-108': Operation not permitted
```

Песочнице разрешена запись только в свою копию (`…/o-2/T-580`) и в `.git`
репозитория, а каталоги чужих копий в этот список не входят. Ветки
`task/T-108, T-114, T-121, T-122, T-15, T-177, T-210, T-23, T-241, T-247,
T-253, T-260, T-266, T-32, T-35, T-86, T-93` инструмент не удаляет, пока не
снят их worktree («её worktree не снят»). `git worktree prune` прошёл, но
ничего не убрал: каталоги копий на месте.

### Копия слияний офиса `_base/office-b0cc4212`: не удалять

Инструмент пометил её как «сирота без задачи → удалить». Это ошибка
классификации: копию офис ведёт сам (`integrationDir` в `src/server/merge.ts`,
`_base/<repoSlug>`) и через неё сливает задачи в main. Сейчас она на HEAD main.
На время `--apply` я её закрыл `git worktree lock`, инструмент такие
пропускает. После прогона снял блокировку, чтобы не помешать пересборке копии
офисом (`worktree remove --force` на заблокированной не проходит). Правка
`cleanup.ts`, чтобы `_base` считался защищённым, как `_release`, — отдельная
задача: код в этой задаче не меняю.

### Грязные копии (оставлены инструментом, удалять нельзя)

`git worktree remove --force <копия>` и `git branch -D task/T-N`.

## Что выполнить снаружи (не из песочницы)

Из рабочей копии этой задачи или из любой копии с main, где есть
`scripts/cleanup-branches.ts`:

```sh
cd ~/Projects/ai/office
A="$HOME/Library/Application Support/AI Office"
BASE="$A/.office/worktrees/o-2/_base/office-b0cc4212"
git worktree lock --reason "копия слияний офиса" "$BASE"
npm run cleanup:branches -- --orphans --office o-2 \
  --state "$A/office/state.json" --repo ~/Projects/ai/office \
  --worktrees "$A/.office/worktrees/o-2" --apply
git worktree unlock "$BASE"
git worktree prune
npm run cleanup:branches -- --orphans --office o-2 \
  --state "$A/office/state.json" --repo ~/Projects/ai/office \
  --worktrees "$A/.office/worktrees/o-2"      # проверка: к удалению 0
```

Без `lock` прогон снесёт копию слияний. Офис заведёт её заново при следующем
слиянии, но если в этот момент идёт слияние, оно упадёт.
