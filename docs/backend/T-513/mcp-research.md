# T-513. Внешние MCP-серверы в офисе: что работает, чего не хватает (на примере Notion)

Исследование, код не менялся. Состояние — ветка `main` на 2026-10-09
(SDK `@anthropic-ai/claude-agent-sdk` 0.3.280).

**Коротко.** Каталог внешних MCP-серверов, привязка к ролям, экран в настройках
и статус подключения уже есть. Поддерживаются stdio, http и sse. Локальный
Notion (`@notionhq/notion-mcp-server` с токеном интеграции) подключается
сегодня, но с одной оговоркой: токен должен лежать в окружении процесса
сервера офиса. В приложении для macOS это практически недостижимо, потому что
оно берёт из шелла только `PATH`. Удалённый официальный Notion
(`https://mcp.notion.com/mcp`) работает только через OAuth, а OAuth офис не
умеет: сервер навсегда останется в статусе `needs-auth`. Главные пробелы:
секреты офиса не доходят до MCP, OAuth нет, нет проверки «сервер жив» без
запуска задачи, нет учёта цены описаний инструментов в промпте.

## 1. Как устроено сейчас

### 1.1. Файлы

| Файл | Что делает |
|---|---|
| `src/server/mcp.ts` | Каталог по умолчанию `DEFAULT_MCP_SERVERS`, слияние с каталогом офиса `mcpCatalog`, отбор серверов роли `serversFor`, раскрытие `${VAR}` (`resolveEnv`), перевод в формат SDK (`toSdkConfig` → `externalMcp`), проверка каталога из формы (`checkMcpServers`), опрос статуса (`pollMcpStatus`), бриф по серверам (`mcpBrief`) |
| `src/shared/types.ts` | `McpServerDef` (id, title, transport, command, args, url, env, alwaysLoad, disabled), `McpServerState` (connected / failed / needs-auth / pending / disabled), `Settings.mcpServers` |

| `src/server/agents.ts` | Сессия исполнителя: `mcpServers: { office, ...externalMcp(settings, role, cwd) }`, `systemPrompt.append += mcpBrief(...)`, `settingSources: []`, `settings: { disableClaudeAiConnectors: true }` (`OFFICE_SESSION_SETTINGS`, стр. ~246) |

| `src/server/permissions.ts` | Классификатор риска для `mcp__<сервер>__<инструмент>` |
| `src/web/McpCatalog.tsx`, `src/web/SettingsPage.tsx` | Раздел «Инструменты» в настройках офиса: список серверов, добавление и правка, вкл./выкл., статус, просьбы пакетов |
| `src/web/AgentPanels.tsx` (стр. ~436–512) | В окне роли галочки подписки на серверы каталога |

### 1.2. Каталог и умолчания

- В коде задан только **набор по умолчанию** (`DEFAULT_MCP_SERVERS`):
  `figma-bridge`, `figma-console`, `penpot` (http, localhost:4401), `blender`,
  `unity`, `imagegen`, `browser`. Им заводится новый офис.
- У офиса свой каталог в `Settings.mcpServers`, он хранится в состоянии офиса.
  `mcpCatalog()` дописывает к нему умолчания, которых нет по id, а сохранённые
  записи не трогает. Убрать сервер можно только выключив его (`disabled`).
- Роль подписывается на серверы по id (`Role.mcp`). Отсутствие поля и `[]`
  означают «ничего». Умолчание роли приходит из `runtime.mcp` её пакета при
  найме. Неизвестный id отбрасывается с предупреждением в лог, выключенный
  отбрасывается молча.
- Пакет может **попросить** сервер (`servers` в `agent.json`): просьба
  показывается в «Инструментах» (`McpRequest`), и владелец сам добавляет
  сервер в каталог. Автоматически пакет ничего не подключает.

### 1.3. Откуда берётся конфиг сессии

`externalMcp(settings, role, cwd)` берёт каталог офиса, подписку роли,
отбрасывает выключенные серверы и превращает каждый в `McpServerConfig` SDK:

- stdio: `command`, `args`, `env` (после раскрытия `${VAR}`) плюс
  `OFFICE_WORKDIR` = рабочая копия. Если `command === 'node'`, в приложении
  подставляется бинарь Electron с `ELECTRON_RUN_AS_NODE=1`;
- http / sse: `url`, а `env` уезжает как **заголовки** (`headers`);
- `alwaysLoad` передаётся как есть: инструменты лежат в промпте с первого хода
  и не прячутся за поиском инструментов.

Настройки Claude Code пользователя (`~/.claude.json`, `.mcp.json` проекта) в
сессию не попадают: `settingSources: []`.

### 1.4. Транспорты

| Транспорт | Claude Code | Codex / OpenCode |
|---|---|---|
| stdio | да (SDK поднимает процесс) | да (`StdioClientTransport`, окружение `projectEnv()` + env сервера) |
| http (Streamable HTTP) | да | да (`StreamableHTTPClientTransport`, заголовки из env) |
| sse | да | да (`SSEClientTransport`) |
| `claudeai-proxy` (коннектор claude.ai) | SDK умеет, офис **не пропускает**: `checkMcpServers` знает только stdio/http/sse | нет |

OAuth нет ни в одном движке. У Codex и OpenCode офис сам MCP-клиент без
`authProvider`, у Claude Code headless-сессии некому открыть браузер.

### 1.5. Где хранятся ключи

- **В каталоге ключей нет и быть не может.** `checkMcpServers` отклоняет любое
  значение env или заголовка, которое не является целиком ссылкой `${NAME}`
  (`badEnv`). Причина: настройки уезжают на фронт в каждом снимке и лежат в
  `state.json`.
- `${NAME}` раскрывается в `resolveEnv` **только из `process.env` сервера
  офиса**. Если переменной нет, подставляется пустая строка.
- **Секретные переменные офиса** (`src/server/secrets.ts`, системная связка
  ключей, привязка к id офиса) сейчас идут только в окружение сборки выпусков
  (`releases.ts` → `secretsEnv`). В шапке модуля прямо сказано, что
  `secretsEnv` нельзя звать для окружения сессий агентов. В MCP они **не
  попадают**.
- Ключи провайдеров (`engines/keys.ts`) получает только сам движок
  (`engineEnv`), к MCP они отношения не имеют.
- Приложение для macOS (`desktop/server.js`) берёт из login-шелла **только
  `PATH`**. Переменная `export NOTION_TOKEN=…` из `~/.zshrc` до сервера
  приложения не доходит. При запуске из терминала (`npm run dev`) доходит.

### 1.6. Статус «сервер жив»

`pollMcpStatus` опрашивает `session.mcpServerStatus()` уже идущей сессии
исполнителя (`collectWorker` → `state.pollMcp`): до 4 попыток, пока есть
`pending`. Сервер, о котором сессия не знает, получает `failed` /
`not-in-session`. Статус показывается в «Инструментах». **Без запущенной
задачи статуса нет** («неизвестно»), отдельной кнопки «проверить» нет.

### 1.7. Коннекторы claude.ai

Отключены в `src/server/agents.ts`: константа `OFFICE_SESSION_SETTINGS =
{ disableClaudeAiConnectors: true }` уходит в `settings` **всех** сессий офиса
(менеджер, исполнитель, ревью, ритуалы, процессы). У исполнителя она входит в
`workerSettings(window)` вместе с `autoCompactWindow`. Это сделано
2026-09-18 из-за раздутого префикса: все коннекторы аккаунта (Figma, Claude
Docs и др.) приезжали тысячами токенов схем в каждую сессию, мимо каталога и
разбора рисков.

Что будет, если включать **выборочно**. По документации SDK флаг перекрывает
только *автоматически подтянутые* коннекторы, а сервер `type: 'claudeai-proxy'`,
переданный явно через `mcpServers`, подключается по обычным правилам. Отсюда
правильный путь: флаг не трогать, а добавить в каталог транспорт
`claudeai-proxy` (`url` + `id` коннектора) и подписывать на него роли как на
любой другой сервер. Получится:

- плюс: Notion, подключённый владельцем на claude.ai, работает **без нашего
  OAuth**, потому что авторизацию держит аккаунт Anthropic;
- плюс: в префикс попадает один коннектор и только у подписанных ролей, а не
  все коннекторы у всех;
- минус: работает только у движка Claude Code и только при входе по аккаунту
  claude.ai (не по ключу API); у Codex и OpenCode такого транспорта нет;
- минус: `id` и `url` коннектора нужно где-то взять. В SDK нет публичного
  списка коннекторов аккаунта, и это надо проверить на живой сессии (см. риски);
- если просто снять `disableClaudeAiConnectors` у одной роли, вернётся ровно
  проблема 2026-09-18 для этой роли: все коннекторы целиком, без выбора.

## 2. Можно ли подключить Notion сегодня

### 2.1. Локальный Notion MCP с токеном интеграции — да, с оговоркой

Сервер `@notionhq/notion-mcp-server` (stdio, токен внутренней интеграции
Notion `ntn_…`).

1. В Notion: Settings → Connections → Develop integrations → создать
   internal integration, скопировать токен. На нужных страницах выдать доступ
   интеграции («Connections → Add»), иначе поиск вернёт пусто.
2. Положить токен в **окружение процесса сервера офиса**:
   `export NOTION_TOKEN=ntn_…` в том шелле, из которого запускается
   `npm run dev` / `npm start`.
   **В приложении для macOS этот шаг не выполняется:** приложение берёт из
   шелла только `PATH`. Обходы (`launchctl setenv NOTION_TOKEN …` до запуска
   приложения) ненадёжны и не документированы, считать их рабочими нельзя.
   Секретные переменные офиса здесь **не помогают**: они не доходят до MCP.
3. Настройки офиса → «Инструменты» → добавить сервер:
   - id `notion`, транспорт stdio;
   - команда `npx`, аргументы `-y @notionhq/notion-mcp-server`;
   - переменные: `NOTION_TOKEN=${NOTION_TOKEN}`;
   - «всегда в промпте» (`alwaysLoad`) лучше снять у ролей с поиском
     инструментов (см. §3.6).
4. Окно роли → поставить галочку `notion` у нужной роли.
5. Запустить задачу этой роли. Статус в «Инструментах» станет `connected`
   или `failed` с текстом ошибки.

Подводные камни этого пути:
- версия пакета не зафиксирована (`npx -y` без `@x.y.z`), и набор
  инструментов, а значит и цена префикса, может молча поменяться. Лучше
  писать `@notionhq/notion-mcp-server@<версия>`;
- имена инструментов у сервера вида `API-post-search`, `API-patch-page`. Под
  читающий шаблон `permissions.ts` (`^(get|list|read|search|…)_`) они не
  попадают, поэтому **каждый** вызов, включая поиск, уйдёт владельцу на
  подтверждение как запись;
- сетевой доступ: stdio-сервер поднимает SDK, а не песочница роли. Сеть до
  `api.notion.com` у него есть, но это стоит перепроверить на роли с
  `sandbox` (см. риски).

### 2.2. Удалённый официальный Notion MCP (OAuth) — нет

`https://mcp.notion.com/mcp` (Streamable HTTP; есть и `/sse`) требует OAuth
2.1 с динамической регистрацией клиента, статических токенов он не
принимает. Что мешает:

1. В каталог его можно добавить (http, url), но сессия получит статус
   `needs-auth`. Провести OAuth некому: в headless-сессии SDK нет браузера и
   нет API, чтобы пройти авторизацию, а у Codex и OpenCode офис подключается
   без `authProvider`.
2. Вписать токен руками в заголовок `Authorization: Bearer ${NOTION_OAUTH}`
   формально можно, но токен OAuth короткоживущий, а обновлять его некому.
3. Вариант через коннектор claude.ai заблокирован дважды: флагом
   `disableClaudeAiConnectors` для автоподключения и тем, что
   `checkMcpServers` не пропускает тип `claudeai-proxy` для явного.

## 3. Пробелы

1. **Добавление своего сервера из интерфейса.** Уже есть: форма в
   «Инструментах», галочки у роли, просьбы пакетов. Не хватает:
   - шаблонов популярных серверов (Notion, GitHub, Linear, Slack), чтобы не
     вписывать команду и переменные руками;
   - фиксации версии пакета в форме (подсказки «укажите версию»);
   - ограничения инструментов сервера (SDK умеет `tools:
     McpServerToolPolicy[]` с `always_allow / always_ask / always_deny`,
     офис это не использует).
2. **Привязка к ролям и офису.** Каталог живёт на офис, подписка на роль.
   Это достаточно. Нет подписки на уровне направления или подпроекта, но
   острой нужды в ней не видно.
3. **Секреты.** `${VAR}` раскрывается только из `process.env`, секреты офиса
   в MCP не идут. В приложении для macOS ключ для MCP фактически некуда
   положить. Экран «Инструменты» не показывает, каких переменных не хватает
   (пустая строка подставляется молча).
4. **OAuth.** Отсутствует полностью: нет хранения токенов, обновления,
   экрана «Войти в Notion». Нет и пути через коннекторы claude.ai.
5. **Проверка «сервер жив».** Статус бывает только у идущей сессии. Нет
   кнопки «проверить» в форме. Ошибку конфигурации владелец видит только
   после того, как задача уже стартовала без инструментов.
6. **Цена в контексте.** Нигде не считается, сколько токенов стоят описания
   инструментов сервера. При этом:
   - `checkMcpServers` и пустая форма ставят `alwaysLoad: true` **по
     умолчанию**, то есть каждый добавленный сервер целиком лежит в префиксе;
   - у ролей с явным списком `tools` нет `ToolSearch`, и им `alwaysLoad`
     действительно нужен. У ролей без списка (`tools` не задан) поиск есть,
     и для них отложенная загрузка дешевле;
   - локальный Notion отдаёт порядка двадцати инструментов, сгенерированных
     из OpenAPI, со схемами в несколько тысяч токенов. Для исполнителя с
     префиксом около 57К (см. thrash автосжатия 2026-09-18) это заметно.
7. **Разрешения.** `permissions.ts` знает только глаголы `get_/list_/…`.
   Notion (`API-post-search`) и большинство серверов, сгенерированных из
   OpenAPI, весь трафик отправят на подтверждение. Нет способа пометить
   инструмент как «читающий» из каталога.

## 4. Предложение фичи «Внешние MCP: Notion и другие»

### Задачи

**MCP-1. Секреты офиса для MCP-серверов** — backend.
`${NAME}` в env и заголовках сервера раскрывается сначала из секретных
переменных офиса, потом из `process.env`. Значение получает только
конфиг MCP (env stdio-процесса или заголовок), а не окружение сессии
агента. В `secrets.ts` добавить узкую функцию `secretsFor(officeId,
names)`, которая отдаёт только названные переменные, и пометить её в шапке
модуля как второй разрешённый потребитель. Перевести `externalMcp` в async
(он вызывается из async-кода сессий). В снимок для фронта добавить
«недостающие переменные» по серверу, только имена.
Зависимости: нет. Это разблокирует локальный Notion в приложении.

**MCP-2. Проверка сервера и цена в токенах** — backend.
Эндпоинт «проверить сервер» поднимает MCP-клиент (`@modelcontextprotocol/sdk`,
как в `codex-tools.ts`), делает `initialize` + `tools/list` и закрывает
соединение. Возвращает статус, версию, число инструментов и оценку токенов
описаний (длина JSON схем / 4, достаточно для порядка). Результат кладётся в
`McpServerState` и показывается без запуска задачи. Сюда же:
- `alwaysLoad` по умолчанию `false`, кроме ролей без `ToolSearch` (решать
  при сборке сессии по `role.tools`, а не флагом в каталоге);
- поле `readTools: string[]` (или шаблон) в `McpServerDef`, которое
  `permissions.ts` учитывает как «безопасно».
Зависимости: MCP-1 (проверка должна видеть те же секреты, что и сессия).

**MCP-3. Подключения из claude.ai (выборочные коннекторы)** — backend.
Транспорт `claudeai-proxy` (`url`, `connectorId`) в `McpServerDef` и
`checkMcpServers`, проброс в SDK только для движка Claude Code. Флаг
`disableClaudeAiConnectors` остаётся. Первый шаг задачи — спайк на живой
сессии: откуда брать `id` и `url` коннектора и работает ли прокси при входе
по аккаунту. Если спайк покажет, что не работает, задача закрывается
документом, а Notion по OAuth переходит в MCP-5 (вне этого плана: свой OAuth
2.1 клиент с хранением токенов в связке ключей, это большая отдельная
фича).
Зависимости: нет, можно параллельно с MCP-1.

**MCP-4. Экран «Инструменты» 2.0** — design, затем frontend.
Шаблоны популярных серверов (Notion локальный, Notion через claude.ai,
GitHub, Linear) с готовыми полями. Выбор переменной из секретов офиса
вместо ручного `${…}` и предупреждение о недостающих. Кнопка «Проверить» со
статусом, числом инструментов и «≈N токенов в промпте». Поле «читающие
инструменты». Для `claudeai-proxy` вариант «из claude.ai». Сначала макет
(design), потом вёрстка (frontend).
Зависимости: MCP-1, MCP-2; часть про claude.ai — после MCP-3.

```
MCP-1 (backend) ──► MCP-2 (backend) ──► MCP-4 (design → frontend)
MCP-3 (backend, спайк) ─────────────────┘
```

### Риски

- **Контекст.** Каждый сервер с `alwaysLoad` дорожает префикс всех сессий
  подписанной роли. Повторение thrash автосжатия 2026-09-18 реально, если
  подписать роль на 2–3 больших сервера. Меры: оценка токенов (MCP-2),
  `alwaysLoad` выключен по умолчанию, предупреждение в форме при большом
  суммарном весе на роль.
- **Безопасность секретов.** Секрет в env stdio-сервера читает сам процесс
  сервера, то есть стороннего npm-пакета. Это осознанное доверие к пакету,
  и его надо назвать в интерфейсе. Секрет не должен попадать в окружение
  сессии агента, в логи и в `mcp.status.error`: ошибки клиента MCP могут
  цитировать заголовки, их надо пропускать через `maskSecrets`.
- **Утечка данных наружу.** Notion и прочие серверы — канал вывода данных
  проекта за периметр. Классификатор сейчас считает запись во внешний сервис
  `write`, а не `danger`. Для серверов «во внешнюю сеть» стоит рассмотреть
  отдельный уровень или `always_ask` через `McpServerToolPolicy`.
- **permissions.ts.** Разметка «читающих» инструментов из каталога — это
  доверие словам владельца. Ошибка в шаблоне откроет запись без вопроса.
  Шаблоны готовых серверов надо держать в коде с тестом, а не в настройках.
- **Песочница.** stdio-серверы поднимает процесс движка, а не песочница
  роли. Сетевые ограничения роли (`sandbox`) на них не действуют, и это надо
  проверить, а не предполагать. Обратный случай: при `allowLocalBinding: false`
  сервер, которому нужен локальный порт, может не подняться.
- **Разные движки.** Codex и OpenCode получают MCP через клиент офиса. Всё
  из MCP-1/2 нужно сделать в общем месте (`mcp.ts`), иначе движки разойдутся.
  `claudeai-proxy` у них не появится вовсе.
- **Непроверенное в этом исследовании:** точный набор и вес инструментов
  `@notionhq/notion-mcp-server` текущей версии, поведение `claudeai-proxy`
  без публичного списка коннекторов, доступ stdio-сервера к сети при
  включённой песочнице роли. Всё это проверяется на живой сессии, которой
  в этой задаче не было.
