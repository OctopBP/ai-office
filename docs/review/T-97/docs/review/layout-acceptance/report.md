## Расхождения и недоделки

1. **Ходьба не с постоянной скоростью, CSS-transition не заменён на Web
   Animations API.** `docs/design/office-layout/spec.md` §7: «Анимация — Web
   Animations API по ломаной вместо одного CSS-перехода; скорость постоянная
   (тайлов в секунду), а не фиксированные 0.9 с на любое расстояние». По факту
   (`src/web/store.ts:404`, `stepWalk()`) каждый отрезок ломаной анимируется
   через `useStore.setState` + CSS-transition `left .9s ease, top .9s ease`
   (`src/web/styles.css:362`), с фиксированной длительностью `WALK_LEG_MS =
   900` на **любой** отрезок независимо от его длины. Диагональный отрезок
   длиннее ортогонального в `√2` раз, но идёт за то же время — то есть по
   факту скорость по диагонали выше, чем по прямой, ровно то несоответствие,
   которое спека просила убрать. В комментарии авторы честно фиксируют
   сознательное решение: «этап 3 меняет только траекторию ..., не темп и не
   саму анимацию ходьбы» (`store.ts:400-402`) — то есть это не забытое, а
   осознанно упрощённое место. Формальный критерий приёмки в §9 («агент идёт
   через проём, а не сквозь стену») это не нарушает — это чисто визуальная
   недоделка, но раз в разделе задачи прямо просили сверить «движение по
   ломаной», указываю: движение по ломаной есть, а обещанная в §7 деталь
   реализации (WAAPI, постоянная скорость) — нет.
   **Предложение:** доработать `stepWalk()`/`walkTo()` — считать длительность
   отрезка из его длины (`WALK_LEG_MS * legLength`) и/или перейти на
   `element.animate()`, если требуется соответствие спеке буквально. Не
   критично для слияния этой задачи (T-97 — только приёмка, без правок кода),
   но стоит завести отдельную задачу.

2. **`OfficeEntry.layoutId` из §8 реализован иначе, чем описано буквально,
   но эквивалентно по результату.** Спека (§8) предполагала поле `layoutId?`
   у `OfficeEntry` (`src/server/offices.ts:10`). По факту `layoutId` живёт в
   `Settings` (`src/shared/types.ts:139`, `this.settings.layoutId` в
   `state.ts`), то есть внутри состояния офиса, а не в записи реестра
   офисов. Свойство от этого не страдает: `test:state` подтверждает, что у
   каждого офиса раскладка своя, переживает перезапуск и не переставляет
   мебель соседям. Отмечаю просто как расхождение с буквой документа, не как
   дефект — реализация закрывает тот же сценарий приёмки из §9 («в двух
   офисах одновременно разные раскладки»), проверено тестом.

Больше расхождений с текстом §9 и детальными разделами (§3, §4, §6, §7) не
найдено: каталог, раскладки, отрисовка, столы/места, автотайлинг стен, темы
day/night, проходимость и A* — всё в коде `main` соответствует спеке и
подтверждено прогонами.
