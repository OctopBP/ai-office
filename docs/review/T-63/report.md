## Гейт слияний и повторы (git.ts / premerge.ts / review.ts)

Один связный вариант, не смесь:

- `git.ts`: `integrationWorktree` — единая функция подъёма рабочей копии офиса под
  слияние с разбором завалов (`raiseCopy`: протухшая запись → свой же застрявший
  worktree → брошенный хвост → чужие копии внутри каталога) и запасным путём —
  каталог `<dir>-<uuid>` (не строго `_base-<id>`, но соответствует описанию «запасной
  каталог рядом»), плюс `releaseIntegration` для его уборки. `assembleMerge` и
  `mergeBranch` используют её последовательно, дублей старой логики не осталось.
- `premerge.ts`: стадия `'integration'` выделена отдельно от `'conflict'` (см.
  комментарий на строке 46–52) — именно то исправление T-56/T-58, что не поднятая
  копия для слияния не выглядит как «база уехала».
- `review.ts`: `stopOnRedGate` (красные проверки — конец пути, `needsDecision: true`),
  `retryAfterGate` (расхождение веток/уехавшая база — `outcome: 'moved'`, второй
  круг) и `stopOnBrokenGate` из T-61 (сломанная обстановка гейта — тоже
  `needsDecision: true`, а не второй круг) — три разных исхода гейта разведены по
  `gate.stage`: `'checks'` → red, `'conflict'`/`'merge'` → retry, иначе `!gate.ok` →
  broken. Логика T-58 (второй круг на `stage === 'merge'`) и T-61
  (`stopOnBrokenGate` для прочих `!ok`) не конфликтуют — это последовательные ветки
  одного if-каскада, а не два параллельных механизма.
