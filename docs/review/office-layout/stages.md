## Словарь терминов и формат данных (для исполнителя одного этапа, без чтения всей спеки)

- **Каталог спрайтов** — `design/sprites/out/catalog.json`, генерируется
  `gen.py` вместе с PNG; хранит `size` (тайлы), `footprint` (занятая на полу
  область), `layer`, `slots` для каждого спрайта. Один каталог на обе темы.
- **Раскладка (layout)** — `design/layouts/<id>.json` (пресеты `classic`,
  `studio`); описывает `size`, `rooms`, `walls`, `props`, `zones`, `hotspots`
  конкретного офиса.
- **Комната (room)** — прямоугольник (`rect`) + материал пола (`floor`).
- **Стена (wall)** — отрезок по сетке (`a`/`b`), горизонтальный или
  вертикальный, толщина всегда 1 тайл; `doors: [[смещение, длина]]` — проёмы.
- **Предмет (prop)** — `sprite` + `at` (позиция) + опционально `id`, `flip`,
  `scale`. Без `id` — автоимя `<sprite>#<n>`.
- **Зона (zone)** — не координаты, а смысл: `work` (рабочие места, может
  иметь `fill` — сетку столов cols×rows с шагом `step`), `meeting`
  (переговорный стол), `idle` (где ждут свободные агенты), `entrance` (дверь).
- **Хотспот (hotspot)** — кликабельный предмет, открывающий панель
  (`board`, `logscreen`), с `key` для бейджа.
- **Слот (slot)** — точка на предмете, где что-то стоит/сидит. Виды (`kind`):
  `work` (место инстанса за столом), `seat` (сидячее место), `plate` (якорь
  таблички задачи), `mount` (крепление к стене). Разворачивание слотов:
  `side + count` (ряд вдоль грани предмета), `ring + rx/ry` (эллипс вокруг
  центра, `grow: true` — эллипс растёт при превышении ёмкости), либо явный
  список `{x, y}`.
- **Индекс рабочего места** — порядковый номер в общем списке мест из зон
  `work`; контракт с сервером (`Desk.index`), должен быть детерминированным
  (§3.3). Стол менеджера — спрайт `desk_pm`, иначе индекс 0.
- **Слой (layer)** — `floor_overlay`, `furniture`, `wall`, `wall_mounted`,
  `hotspot`; определяет только правило сортировки z, не жёсткое число (§5:
  пол z=0, наложения z=1, мебель/стены/люди — y-сортировка от 100,
  настенное — 900, подписи/бейджи — 1000).
- **Тайл** — 16 арт-пикселей = 48 экранных пикселей (`T`), координаты в
  раскладке — в тайлах, дробные значения разрешены. Якорь предмета — левый
  верхний угол спрайта.

## Явные запреты и ограничения из спеки

- Этапы 0 и 1 **не меняют картинку** — это перестановка кода/данных без
  визуальных изменений (§9, текст после таблицы).
- Этап 3 обязателен до релиза раскладки `studio`, но не блокирует этапы 0–2
  (§7).
- Координаты из `docs/design/office-layout-draft.md` **брать нельзя** — они из
  несуществующей сетки 30×18 по 32px (см. «Родственные документы» в начале
  спеки).
- Цельный `floor.png` остаётся до конца этапа 2 ради раскладки `classic`,
  потом удаляется (§6.1).
- Нынешний `wall()` 24×2 тайла остаётся для `classic` до этапа 2 (§6.2).
- Система координат (§2) не меняется — она задана артом, `GRID.cell` (48px)
  остаётся константой, `GRID.cols/cells` уходят в раскладку.
- Темы дня/ночи не меняются по механизму — раскладка оперирует именами
  спрайтов, подстановку темы делает `spriteOf()`; ночная версия новых тайлов
  обязана существовать под теми же именами (§3.4).
- Каталог — это свойство арта: и веб, и сервер читают один и тот же
  `out/catalog.json` из репозитория, а не пересчитывают его отдельно (§8).
- Раскладка едет в веб в снапшоте, а не импортируется вебом отдельно — иначе
  оверрайд не сработает (§8).
- Совместимость: офис без `layoutId` и без `layout` получает `classic` —
  никакой миграции состояния не требуется (§8).
