## Проверенный штатный путь

Проверены `desktop/updater.js`, `desktop/main.js`, `desktop/server.js`, `desktop/paths.js`, `desktop/channel.js`, `desktop/builder.config.js`, `.github/workflows/release.yml`, `workflows/release.json` и соответствующие участки `src/server/releases.ts`, `agents.ts`, `index.ts`.

У приложения уже выбран **beta** в `update-channel.json`. Менять канал или получать новое согласие на переход к beta не требуется. Источник обновлений — GitHub `OctopBP/ai-office`. Для macOS штатному обновлению нужны опубликованный выпуск, манифест `beta-mac.yml` и ZIP своей архитектуры; DMG служит ручной установке. CI проверяет наличие файлов macOS обеих архитектур и Windows перед снятием draft. Наличие конфигурации CI не подтверждает успешную будущую сборку, подпись или загрузку ZIP.

Действие владельца после поставки: **«Офис → Проверить обновления…» → «Скачать»; после загрузки снова открыть этот пункт и подтвердить перезапуск в готовую новую версию** (либо воспользоваться теми же командами в окне). В коде меню фазы проверки, загрузки и готовности обрабатываются раздельно.

`restartNow` ждёт принятия обновления Squirrel.Mac, затем останавливает свой сервер и вызывает `quitAndInstall(true, true)`. Сервер получает SIGTERM с ожиданием, резервный SIGKILL через 3 секунды. При отказе нативной проверки до остановки сервер продолжает работать. Признак busy читается из `/api/busy`; он предупреждает о прерывании работ, но не блокирует решение владельца. Установка может также произойти при обычном выходе после скачивания (`autoInstallOnAppQuit=true`).

Отдельная команда **«Офис → Перезапустить офис» только перезапускает сервер из имеющихся ресурсов**. Она не скачивает новую сборку и сейчас не решает задачу. После успешного перезапуска самим обновлятором повторять её не нужно. Данные остаются в прежней пользовательской папке; ручная замена ресурсов, перенос состояния и запуск dev-сервера не требуются.

## Точное оставшееся действие команды

1. PM через свои штатные `release_status` / `get_release` сверяет свежий выпуск и отсутствие уже начатого выпуска с тем же составом. Этих инструментов нет у данного исполнителя. Повторный запрос владельцу о доступе к сети не нужен для передачи этой подготовки PM.
2. Если подходящего опубликованного выпуска нет, PM готовит бета-выпуск **существующей цели `desktop` («Приложение»), канал beta**, с включением обоих коммитов. Штатная точка входа — `start_release({target:"desktop", channel:"beta", note:...})`. В T-753 её не вызывали: запуск выпуска прямо запрещён заданием. Не создавать новую цель, не подменять установленное приложение.
3. Цель из сохранённых настроек: kind=tag, beta branch=`beta`, assets=[`beta-mac.yml`], **policy.approve=always**. Поэтому после подготовки снимка, версии и заметок нужен один штатный gate согласования выпуска. Это конкретное решение владельца по действующей политике, а не просьба ему собирать приложение. Номер следующего выпуска не назначен: его должен рассчитать и показать конвейер (не обещать заранее beta.20).
4. Команда доводит согласованный выпуск до успешного CI и публикации; сохраняет ссылку, точную версию и SHA тега с обоими исправлениями, проверяет отсутствие draft, наличие `beta-mac.yml` и соответствующих ZIP, совпадение ссылок манифеста и фактическую доступность загрузки. Сейчас этих свидетельств для нового выпуска нет. Самостоятельную установку или перезапуск исполнителем не планировать.
5. После этого PM передаёт владельцу готовый шаг установки ниже. Перед перезапуском команда сама проверяет занятость офисов штатными средствами и согласует безопасный момент. В этой сессии живой busy не проверен, локальный API не вызывался.
6. После установки команда подтверждает версию приложения, оба изменения в установленном ресурсе и новый запуск сервера после обновления. Версия сама по себе не доказывает загрузку исправленного кода. Штатно проверяет отсутствие старой активной сессии; дальнейшие действия с существующими задачами остаются у PM и не входят в T-753.

Не просить владельца искать сборку, проверять SHA, заменять файлы, выполнять команды или собирать доказательства загрузки.
