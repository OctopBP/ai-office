# Приложение для macOS и Windows

Офис можно скачать файлом и поставить двойным щелчком — без клона репозитория,
Node и терминала. Внутри тот же сервер и тот же веб, что при `npm run office`:
меняется способ доставки, а не офис.

Спека и принятые решения — [docs/design/desktop-app/spec.md](../design/desktop-app/spec.md).

## Что нужно на машине

| | macOS | Windows |
|---|---|---|
| Само приложение | `.dmg` | `.exe` (NSIS) |
| Движок Claude Code | ставится при первом запуске | ставится при первом запуске |
| git | системный (Command Line Tools) | вшит в приложение (MinGit) |

Движок — нативный `claude` на ~310 МБ. В установщик он не вшит сознательно:
бинарь проприетарный, и раздавать его со своих релизов нельзя. При первом
запуске приложение либо находит уже поставленный Claude Code, либо скачивает
из npm ровно ту версию, под которую собран SDK, — один раз, в свою папку
данных.

Доступ к модели — как и везде в офисе: подписка Claude (вход через
`claude` → `/login` в терминале) или `ANTHROPIC_API_KEY` в окружении.

## Где лежат данные

Программа только читает, данные только пишутся — и лежат они порознь:

```
macOS:   ~/Library/Application Support/AI Office/
Windows: %APPDATA%\AI Office\
├─ office/       состояние офисов и реестр
├─ employees/    свои сотрудники
├─ engine/       скачанный движок
└─ server.log    журнал сервера
```

Папку и журнал открывает меню «Офис». Рабочие папки проектов остаются там, где
их выбрал человек; по умолчанию — `~/Office`, как и при запуске из исходников.

Удаление приложения данные не трогает: доски и журналы — не часть программы.

## Перенести офисы из запуска из исходников

Офис из исходников и приложение — две независимые установки: первый держит
состояние в `.office` рядом с репозиторием, второе — в папке данных
пользователя. Поэтому и список офисов у них разный: приложение не видит то,
что вы завели в терминале.

Перенести (приложение перед этим закройте — открытое, оно держит свой список
в памяти и перепишет реестр при первом же сохранении):

```bash
node scripts/import-offices.mjs --dry-run   # посмотреть, что переедет
node scripts/import-offices.mjs             # перенести
```

Переезжают состояния офисов (доски, ленты, расходы), иконки офисов и кеш
лимитов плана. Офис узнаётся по папке проекта: тот, что в приложении уже
есть, скрипт не трогает, и повторный запуск дублей не заводит. Папка данных
перед записью копируется целиком рядом — `office.backup-<дата>`.

После переноса это **две независимые копии одних и тех же офисов**. Работать
надо в одной: если запустить обе на тех же проектах, два сервера начнут вести
задачи в одних и тех же репозиториях — ветки и рабочие копии столкнутся, а
доски разойдутся.

Рабочие копии задач (`.office/worktrees`) не переезжают, и это не потеря:
задача, которая уже в работе, помнит свой путь и продолжит в нём, а новые
получат копии в папке данных приложения.

## Меню «Офис»

- **Движок агентов…** — поставить или переустановить движок;
- **Перезапустить офис** — поднять сервер заново, не выходя из приложения
  (живые сессии исполнителей при этом обрываются, как и при `npm run office -- --restart`);
- **Папка данных**, **Журнал сервера** — то, что спросят при первой же поломке.

## Собрать установщик самому

```bash
npm ci
npm run build:desktop          # веб + сервер одним файлом + ресурсы
npm --prefix desktop ci
npm --prefix desktop run dist  # установщик для текущей системы
```

Готовое лежит в `desktop/out/`. Собрать Windows-установщик на macOS нельзя —
для этого есть workflow `release` по тегу `v*`, он собирает обе системы на
своих машинах и складывает результат в черновик релиза.

Проверить приложение без установщика:

```bash
npm run desktop                # соберёт ресурсы и запустит окно
```

## Как это устроено

```
Приложение (Electron)
├─ main               окно, меню, папки данных, первый запуск
│  └─ дочерний node   сервер офиса (src/server, собранный в один файл)
│     └─ процессы     claude (движок), git (ветки и worktree)
└─ окно офиса         тот же веб, по http://127.0.0.1:<свободный порт>
```

Сервер живёт отдельным процессом: падение сессии агента не уносит окно, а
перезапуск офиса не требует перезапуска приложения. Слушает он только петлю —
в сеть офис приложения не выходит.

Пути и порт сервер получает теми же переменными окружения, что и при запуске
из исходников (`OFFICE_PORT`, `OFFICE_STATE_FILE`, `OFFICE_ROOT`,
`OFFICE_DIST_DIR`, `OFFICE_CLAUDE_BIN`, `OFFICE_GIT_BIN` — см.
[running.md](running.md)). Второго способа настройки у приложения нет
намеренно: иначе поведение приложения и офиса из исходников разошлось бы.

## Если что-то не так

**«Не удаётся проверить разработчика».** Сертификата у сборки пока нет:
приложение подписано «для себя» (ad-hoc), и этого хватает, чтобы система
пустила его после явного разрешения. macOS: правый щелчок по приложению →
«Открыть» → «Открыть». Windows: «Подробнее» → «Выполнить в любом случае».

Если macOS говорит «приложение повреждено» — это не про сертификат, а про
сломанную подпись: так выглядит .app, который собрали и положили в образ, не
переподписав. Лечится на стороне сборки (`identity: '-'` в
`desktop/electron-builder.yml`), а не на стороне того, кто скачал.

**Окно открылось, но офис говорит про движок.** Меню «Офис» → «Движок
агентов…» → «Скачать», затем «Перезапустить офис».

**Задачи падают на проверках проекта.** Приложение берёт `PATH` из вашего
входного шелла, но если node стоит через что-то экзотическое, его может не
быть видно — проверьте журнал сервера.
