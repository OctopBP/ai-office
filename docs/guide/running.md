# Запуск и настройка

## Провайдеры

Офису нужен хотя бы один провайдер — программа-агент, на которой работают
сотрудники. Его ставят и подключают при первом запуске на экране Настройки →
«Провайдеры». Кнопка «Установить» скачивает движок в
`OFFICE_ENGINE_DIR`, доступ к моделям даётся ключом API (уходит в системную
связку ключей) или входом самого провайдера. Сейчас поддерживаются Claude Code
и Codex; новые провайдеры появятся на том же экране. Провайдер выбирается для
каждой роли, и у каждого свои шкалы лимитов.

Ключи из окружения сервера тоже работают и имеют приоритет над входом по
подписке, подменяя его молча: `ANTHROPIC_API_KEY` или `ANTHROPIC_AUTH_TOKEN`
для Claude Code, `OPENAI_API_KEY` для Codex. Поэтому источник доступа вынесен
в интерфейс на видное место: 🔑 — вход по подписке, расход идёт в её лимиты;
💳 — ключ API, расход идёт в платный API.

Сумма расходов в шапке — оценка по прайсу API от провайдера. На подписке она
полезна как мера расхода, но счётом не является.

Пользовательские настройки, плагины и навыки провайдеров не наследуются:
офис подключает только инструменты, MCP и навыки выбранной роли.

## Запуск

**1. Провайдер.** Подключите хотя бы одного на экране «Провайдеры» — его
можно открыть и после запуска офиса (шаг 2). Проверки доступа из терминала,
если провайдер уже стоит на машине:

| Провайдер | Проверка | Если не прошла |
|---|---|---|
| Claude Code | `npm run smoke` → `RESULT: success \| работает` | `claude` → `/login` или ключ API |
| Codex | `npm run test:providers` (адаптер, без расхода токенов) | `codex login` или ключ API |

Codex офис сначала ищет внутри Codex/ChatGPT Desktop, затем `codex` в `PATH`;
явный путь — `OFFICE_CODEX_PATH`. Для Claude Code явный путь —
`OFFICE_CLAUDE_BIN`.

**2. Запуск офиса.** Два режима.

Как приложение — собранный веб и WebSocket одним процессом на одном порту:

```bash
npm run office
```

Откройте http://localhost:3001

Для разработки самого офиса — с пересборкой на лету:

```bash
npm run dev
```

Откройте http://localhost:5173

Разница не только в удобстве. `npm run dev` держит сервер под `tsx watch`, и
любая правка исходников перезапускает его, обрывая живые сессии исполнителей.
`npm run office` запускает сервер один раз: код уже в памяти, и команда может
править исходники того самого офиса, в котором работает. Поэтому офис,
работающий над собой, запускают так.

Перезапуск — осознанное действие:

```bash
npm run office -- --restart
```

Перед остановкой скрипт прогоняет `npm run typecheck` и сборку: не сошлось —
работающий офис не трогается и остаётся на прежнем коде. Если в этот момент есть
задачи в работе, скрипт откажется их обрывать и назовёт их (обойти — `--force`).

**3. Поставьте задачу PM'у.** Например:

> Сделай CRUD для заметок: JSON API на бэке и страницу на фронте

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OFFICE_PROJECT_DIR` | `./workspace` | Директория, в которой работает команда |
| `OFFICE_CODEX_PATH` | Codex/ChatGPT Desktop или `codex` из PATH | Путь к актуальному Codex CLI |
| `OFFICE_CODEX_HOME` | рядом с файлом состояния | Изолированная конфигурация Codex для офисных сессий |
| `OFFICE_CODEX_PRICING` | — | JSON с ценами моделей Codex за миллион токенов; нужен только для долларовых бюджетов |
| `OFFICE_GITHUB_TOKEN` | — | Токен GitHub для облачного режима. Без него вводится в настройках и живёт только до перезапуска |
| `OFFICE_PORT` | `3001` | Порт WebSocket-сервера |
| `OFFICE_LANG` | `en` | Язык, на котором заводится новый офис: `en` или `ru`. У уже заведённого язык свой — он в его настройках |
| `OFFICE_HOST` | все интерфейсы | На чём слушать. Приложение ставит `127.0.0.1` — в сеть его офис не выходит |
| `OFFICE_ROOT` | папка репозитория | Откуда сервер читает пакеты ролей, процессы, раскладки и реестр маркета |
| `OFFICE_DIST_DIR` | `./dist` | Где лежит собранный веб |
| `OFFICE_CLAUDE_BIN` | — | Чем считать: путь к `claude`. Пусто — движок, поставленный с экрана «Провайдеры», иначе SDK ищет свой бинарь сам |
| `OFFICE_ENGINE_DIR` | `~/.office/engines` | Куда экран «Провайдеры» ставит движки: `<папка>/<движок>/<версия>/`. Приложение ставит папку данных |
| `OFFICE_KEYCHAIN` | системная связка | `memory` — ключи провайдеров только в памяти процесса (для проверок, чтобы не трогать настоящий Keychain) |
| `OFFICE_GIT_BIN` | `git` из PATH | Чем делать ветки и worktree |
| `OFFICE_NODE_BIN` | `node` из PATH | Чем запускать свои mcp-серверы (в приложении своего node нет) |

Директория по умолчанию отдельная, чтобы агенты не редактировали исходники
самого офиса. Укажите свой проект, чтобы команда работала в нём.

Последние пять переменных существуют ради приложения
([desktop.md](desktop.md)): у него нет ни репозитория, ни текущей папки, и
всё, что офис из исходников берёт от них, приходит ему явно.

## Бриф проекта (OFFICE.md)

`OFFICE.md` в рабочей директории — общий контекст команды. Он подклеивается к
системному промпту **всех** сессий: менеджера, исполнителя, разговора и
совещания.

Без него команда работает вслепую. У менеджера вообще нет доступа к файлам — он
декомпозирует только по тексту вашей просьбы; а исполнителю не достаётся
`CLAUDE.md` или `AGENTS.md` проекта, потому что настройки провайдеров
сознательно не наследуются, иначе поведение офиса зависело бы от локальных
настроек машины.

Что стоит держать в брифе: чем занят проект, главный принцип, карту файлов,
правила («комментарии по-русски», «перед сдачей — `npm run typecheck`»,
«промпты — это код, правите их — гоняйте `npm run test:pm`») и то, чего в
проекте сознательно нет.

Файл читается на старте каждой сессии, а не при запуске сервера: правку
подхватит следующая задача, перезапускать офис не нужно. Ограничение — 8000
символов, дальше обрезается.

Рядом с ним — `RULES.md`: правила офиса списком. Отдельный файл, потому что у
него своя область действия: такой же `RULES.md` в корне репозитория роли
достаётся только тем, кто в этом репозитории работает. Заводятся и правятся они
в «Жизни офиса» → «Правила» (см. [office.md](office.md#правила)).

## Полезные команды

```bash
npm run office     # запустить как приложение (сборка + сервер на :3001)
npm run build      # только собрать веб в dist/
npm run restart    # перезапустить сервер разработки (убивает процесс по порту)
npm run smoke      # проверить авторизацию SDK
npm run probe "…"  # отправить задачу PM'у из консоли и смотреть события
npm run test:perm   # классификатор рисков (без токенов)
npm run test:state  # пауза, критерии и разнесение расходов (без токенов)
npm run test:plan   # план: порядок фич, зависимости, фокус, согласие (без токенов)
npm run test:merge  # мержабельность и ручная очередь слияния (без токенов)
npm run test:review # конвейер ревью: синхронизация, конфликты, вердикт, слияние
npm run test:workflow # процессы: разбор файла, встроенный feature, раннер и пределы петель
npm run test:flows  # процессы офиса: «что дальше», дельта, затухание, совещание о развитии
npm run test:money  # лимиты плана и расход задачи по дням (без токенов)
npm run test:packages # пакеты агентов: манифест, валидатор, роль из пакета, привязка сохранений
npm run test:market # маркет: ссылки, реестр, установка из git в кеш, найм, обновление (без сети)
npm run test:cli # авторский путь: заготовка, валидатор, экспорт роли, publish, registry-check (без сети)
npm run test:registry # сервис индекса: зеркало, поиск, публикация, админ, клиент на зеркале (без сети)
npm run test:skills # наборы скилов: разбор и имена скилов (без токенов)
npm run test:mcp    # внешние MCP-серверы ролей и строки о них в промпте (без токенов)
npm run test:imagegen # генератор картинок: запрос к API, разбор ответа, периметр записи (без сети)
npm run typecheck  # проверка типов
```
