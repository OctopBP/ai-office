# Figma Console: плагин и проверка подключения

`figma-console` — второй сервер Figma в каталоге офиса, рядом с `figma-bridge`.
Мост рисует фреймы, тексты и фигуры; Figma Console сверх того умеет
компоненты, варианты, инстансы, переменные и `figma_execute` — произвольный код
Plugin API в открытом файле. Почему именно он и чем отличается от остальных —
`docs/backend-2/T-328/figma-mcp-research.md`.

По умолчанию сервер подключён дизайнеру (`packages/@office/design/agent.json`).
Запускается он сам, `npx -y figma-console-mcp@1.40.9`, на каждую сессию
агента — ставить пакет руками не нужно. Руками нужно одно: поставить плагин
Desktop Bridge в Figma Desktop и держать его запущенным, пока агент работает.

## Что нужно заранее

- **Figma Desktop**, не веб-версия: плагин работает только в приложении.
- **Node.js 18+** с `npx` в PATH на машине, где работает офис: сервер
  поднимается через `npx`.
- Сервер `figma-console` включён в «Настройки → Инструменты», и у роли стоит
  на него галочка.

## 1. Поставить плагин (один раз)

Файлы плагина сервер кладёт сам при первом запуске в
`~/.figma-console-mcp/plugin/`. Поэтому сначала дайте ему подняться хотя бы
раз: поставьте дизайнеру любую задачу — или запустите вручную
`npx -y figma-console-mcp@1.40.9` и остановите через пару секунд.

1. Откройте Figma Desktop и любой файл.
2. Меню **Plugins → Development → Import plugin from manifest…**
3. Выберите `~/.figma-console-mcp/plugin/manifest.json`. Папка скрытая: в
   окне выбора файла на macOS её показывает `⌘ Shift .`
4. Плагин **Figma Desktop Bridge** появится в Plugins → Development. Импорт
   одноразовый: дальше плагин просто запускается из этого списка.

## 2. Запускать перед работой

Откройте файл, в котором агент будет работать, и запустите в нём
**Plugins → Development → Figma Desktop Bridge**. Окно плагина держите
открытым: закрыли — агент теряет файл.

Плагин сам находит серверы на портах 9223–9232 и подключается ко всем сразу,
поэтому несколько сессий агентов одновременно ему не мешают. Предел — десять
серверов: столько портов в диапазоне. Открыто несколько файлов с плагином —
агент видит все и переключается между ними.

## 3. Проверить, что агент подключился

1. **Каталог.** «Настройки → Инструменты»: у `figma-console` статус
   «подключён». Он про сам сервер, не про Figma — сервер поднимается и при
   закрытом плагине, а появляется статус после первой сессии с ним.
2. **Плагин.** В окне Figma Desktop Bridge виден статус подключения к серверу.
3. **Агент.** Поставьте дизайнеру короткую задачу: «вызови `figma_get_status`
   и напиши в отчёте, какой файл активен». В ответе должны быть подключение
   по WebSocket и имя вашего файла. Для проверки записи — «создай в файле
   фрейм с синим фоном»: фрейм должен появиться на холсте.

Агент ответил, что подключения нет, — значит плагин не запущен в этом файле
или запущен раньше, чем поднялся сервер. Запустите плагин заново (или вызовите
у агента `figma_reconnect`).

## Токен Figma (по желанию)

Плагинному пути токен не нужен. `FIGMA_ACCESS_TOKEN` нужен только части
инструментов, которые ходят в REST API Figma: комментарии, история версий,
общие библиотеки. Если они нужны:

1. Создайте персональный токен в Figma (Settings → Security → Personal access
   tokens) с правами File content, File versions, Variables — на чтение,
   Comments — на чтение и запись. Токен начинается с `figd_`.
2. Положите его в окружение офиса под именем `FIGMA_ACCESS_TOKEN` (секретные
   переменные офиса или окружение сервера). В каталоге уже стоит ссылка
   `${FIGMA_ACCESS_TOKEN}` — сам токен в настройки сервера не вписывайте.

## Что важно знать

- **`figma_execute` спрашивает владельца каждый раз.** Он исполняет в файле
  любой код и может стереть что угодно, поэтому классификатор риска отдаёт ему
  `danger` даже в режиме «только про необратимое» (`src/server/permissions.ts`).
- **Обновление плагина.** Figma держит свою копию файлов плагина. После
  смены версии сервера в каталоге плагин в баннере попросит переимпорт — тогда
  Plugins → Manage plugins и снова `~/.figma-console-mcp/plugin/manifest.json`.
  Путь не меняется.
- **Мост остаётся.** `figma-bridge` работает через свой плагин, Figma MCP
  Bridge; для него Desktop Bridge не нужен, и наоборот.
