# T-284. Где теряется MCP `browser` у роли QA

## Итог

Сервер выпадает на шаге 2–3 пути: в **`src/server/mcp.ts:189-191`** (`serversFor`)
имя `browser` из подписки роли ищется в каталоге офиса `mcpCatalog(settings)`
(`mcp.ts:172`), не находится и молча отбрасывается фильтром `s !== undefined`.

Почему не находится: каталог берётся из `settings.mcpServers` офиса, а не из
`DEFAULT_MCP_SERVERS`. Новый офис получает **снимок** умолчаний
(`src/server/state.ts:125`), и снимок живёт в сохранении. Офис o-2 заведён до
появления `browser` в умолчаниях — его сохранённый каталог:
`figma-bridge, blender` (у o-3, o-4 так же; у остальных `figma-bridge, blender, imagegen`
— `browser` нет ни в одном офисе). Миграции, которая доливает новые серверы
умолчания в сохранённые каталоги, нет; найм из пакета каталог тоже не трогает
(серверы пакета идут только в `mcpRequested`, `state.ts:3783`).

## Путь по шагам

| # | Где | `browser` есть? |
|---|---|---|
| 1 | `packages/@office/qa/agent.json`: `runtime.mcp: ["browser"]` и `servers[]` с `node tools/browser/server.mjs` | **есть** |
| 2 | `src/server/mcp.ts:157-168` — в `DEFAULT_MCP_SERVERS` есть; но `mcpCatalog` (`:171-172`) отдаёт сохранённый каталог офиса, а в нём `browser` нет | **в коде есть, в каталоге офиса o-2 нет** |
| 3 | `src/server/skills.ts:291` `employeeServers` — серверы пакета только показываются как просьба (`mcpRequested`), в сессию не подключаются (намеренно, комментарий `:36-38`). Роль qa в o-2: `mcp: ["browser"]` — подписка цела | подписка **есть**, сервер в сессию отсюда не идёт |
| 4 | `src/server/agents.ts:2962` (исполнитель) и `:3952` — `...externalMcp(settings, role, workdir)` → `serversFor` (`mcp.ts:188-192`) | **нет** — выпал здесь |
| 5 | Команда: `resolve(ROOT, 'tools/browser/server.mjs')` (`mcp.ts:161`), `ROOT` = `OFFICE_ROOT` или корень репозитория (`root.ts:15-17`), не рабочая копия задачи. `tools/browser/server.mjs` и `node_modules/playwright-core` (`package.json:78`) в корне есть | **есть**, до запуска дело не доходит |

Карточка, судя по всему, показывает подписку роли (`role.mcp`), а не её
пересечение с каталогом, — отсюда расхождение с сессией (веб не проверял).

## Предложение починки

1. `src/server/mcp.ts`, `mcpCatalog`: доливать к сохранённому каталогу серверы из
   `DEFAULT_MCP_SERVERS`, которых в нём нет по `id` (сохранённые записи сильнее,
   выключенные остаются выключенными). Чтобы удалённый владельцем сервер не
   возвращался, хранить в настройках список убранных id (`mcpRemoved`) и не доливать их.
2. Либо адресно: при найме из пакета (`market.ts`/`state.ts`, где ставится `role.mcp`)
   добавлять в каталог офиса недостающие серверы, на которые подписана роль, из
   `DEFAULT_MCP_SERVERS`.
3. В `serversFor` не терять молча: имя из подписки, которого нет в каталоге, писать в
   `mcpStatus` роли как «нет в каталоге», чтобы карточка не врала «включён».
