## 1. Что существует и что добавляем

В `src/shared/providers.ts` движок `EngineId = 'opencode'` уже есть. Подключения `ProviderId = 'opencode'` нет. Сегодня через этот движок работают семь самостоятельных пресетов: xai, deepseek, openrouter, google, alibaba, ollama, custom.

Сейчас `src/server/providers/opencode.ts → buildConfig` создаёт искусственный upstream `office`: `enabled_providers: ['office']`, пакет `@ai-sdk/openai-compatible` (для Google — `@ai-sdk/google`), вручную объявленная модель, запросы с `providerID: 'office'`. Это НЕ нативный каталог OpenCode. `engines/opencode.ts` получает модели через API пресета и каталог цен офиса, авторизацию — через `engines/keys.ts`. Сам факт наличия движка не предоставляет нативные подключения.

Добавляем отдельный пункт **OpenCode** в общий список подключений, обслуживаемый прежним движком. Внутри него выбираются нативный поставщик и модель. Нативный поставщик `opencode` (Zen) — один из внутренних поставщиков, а не название всего нового подключения. Не заменять все пресеты пунктом OpenCode и не переносить их ключи автоматически.

Офис по-прежнему управляет промптом, правами, инструментами и жизнью сессии. OpenCode управляет циклом модели. Произвольного редактора opencode.json, импорта личного профиля или пользовательского npm-пакета не будет.

Старые пресеты в этой задаче не блокировать новой политикой. Проверку моста в следующей задаче считать инженерной приёмкой, а не новым исследованием.

## 4. Каталог и доступность

Нативный `GET /provider` возвращает `{ all, default, connected }`; `GET /config/providers` — подключённые/настроенные поставщики с умолчаниями. `GET /provider/auth` возвращает методы входа. Это внутренние запросы сервера офиса, не прокси для браузера.

Отдельный управляющий процесс OpenCode с пустым проектом и изолированным профилем получает каталог. Не использовать конфиг существующей сессии с enabled_providers=['office']: он обрезает нативных поставщиков. Для каталога не давать проектные инструкции, инструменты, внешние плагины или ключи других подключений.

Сервер преобразует результат в собственный DTO. Разрешены только id/name, признаки доступности, выбранные метаданные моделей. Запрещено возвращать сырой объект поставщика, key, options, headers, npm, URL с авторизацией и содержимое variants. Значения вариантов остаются на сервере; UI получает только их имена.

Идентификатор модели нового подключения — полный `nativeProviderID/modelID`. Разделять по ПЕРВОМУ /: у OpenRouter modelID уже содержит /. Не нормализовать регистр и не обрезать части идентификатора. Для сессии передавать отдельные providerID и modelID; не использовать alias office. Сохранять нативный ID, SDK и его метаданные: некоторые преобразования зависят от настоящего поставщика.

Первый выпуск реализации: исполняемый список нативных одноключевых подключений — `opencode`, `openai`, `anthropic`, `google`, `deepseek`, `openrouter`, `xai`, только если они присутствуют в каталоге совместимой версии и используют встроенный проверенный SDK. Бесплатные публичные модели Zen допустимы без ключа, если это подтверждено каталогом. Остальные поставщики видны как «Пока не поддерживается офисом» с причиной; их нельзя выбрать для старта. Наличие в Models.dev не равно готовности офиса работать с этим способом входа. Bedrock/Vertex/Azure и многошаговые облачные реквизиты требуют отдельных типизированных адаптеров. Существующие Ollama/custom/alibaba остаются доступным путём для своих сценариев.

Пригодность модели: текстовый вход и выход, toolcall=true, не deprecated; alpha/beta можно выбрать с обозначением статуса. Никакого принудительного tool_call=true для неизвестной модели. Пустые или неполные метаданные дают запрет запуска с конкретной причиной. Для новой ветки свободный ввод неизвестного modelID не включать; он остаётся в прежних пресетах.

Кеш каталога: 15 минут в памяти, обновление по кнопке; ключ — фактическая версия + ревизия подключений. При сетевой ошибке показывать последний снимок с датой и признаком устаревания. Если работающая версия не может разрешить сохранённую модель, остановить запуск с причиной, не переключаться на другую модель.

## 5. Авторизация и секреты

| Возможность OpenCode | Решение для офиса |
|---|---|
| API-ключ конкретного поставщика | Реализуем в первом выпуске для списка выше |
| Публичная модель без входа | Реализуем только для подтверждённых моделей; не считать все модели поставщика бесплатными |
| OAuth через штатные плагины | Технически существуют authorize/callback, method и prompts; в первом выпуске API офиса возвращает 501 unsupported-auth |
| Подписка ChatGPT/Copilot/других сервисов | Не наследуется из подключения Codex или внешнего OpenCode; не обещаем поддержку |
| Вход Google аккаунтом | Не включать: сохраняется существующая политика проекта API-key-only |
| Импорт auth.json, личных переменных и профиля | Не поддерживать |

Это техническое ограничение первого безопасного адаптера: не выполнять неизвестные методы входа и плагины. OAuth позже возможен отдельным адаптером с конкретным встроенным плагином, проверкой условий поставщика, хранением refresh-токенов в связке, отменой и очисткой. Простое включение всех плагинов недопустимо.

Новые секреты хранить в системной связке «AI Office» под `provider:opencode:<nativeID>`. Не добавлять один общий ключ `KEY_VAR.opencode`: у подключения несколько независимых поставщиков. Сузить тип KEY_VAR и цикл loadKeys до прежних одноключевых ProviderId; для opencode сделать отдельные методы связки с nativeID. В providerView и других общих потребителях не вызывать providerKey('opencode') — состояние новой карточки собирает её адаптер. Старые `provider:xai` и другие записи остаются на месте. Для первого выпуска не поддерживать неявное чтение ключей из окружения сервера для новой ветки: только явно сохранённый ключ.

Передавать выбранный ключ процессу через одну служебную переменную `OFFICE_OPENCODE_API_KEY`, а в сгенерированном конфиге — `{env:OFFICE_OPENCODE_API_KEY}` в options.apiKey выбранного nativeID. Добавить эту переменную в удаление секретов команд проекта. Для нового движка строить окружение по разрешённому списку; существующий engineEnv наследует окружение сервера и ключи всех пресетов, что для нативного обнаружения непригодно.

Не вызывать PUT /auth для обычного API-ключа: он создаёт дополнительное дисковое хранилище. Управляющий процесс каталога не получает ключи; проверка реквизитов выполняется отдельным запросом метаданных конкретного поставщика, если он это поддерживает. Само сохранение ключа и connected в каталоге не доказывают валидность реквизитов. Не делать платный ход автоматически. Возвращать «Ключ сохранён, запрос к модели ещё не проверен», если безопасной проверки нет; ошибка 401 реального запроса переводит только это подключение в needs-login.

DELETE удаляет только ключ выбранного nativeID и его служебный кеш. Активные сессии этого nativeID прерываются до завершения удаления, чтобы копия ключа не оставалась рабочей в процессе. Другие поставщики и пресеты не затрагиваются. В ответах только наличие ключа и tail из четырёх символов; тело login и ошибки upstream не логировать.

## 6. Расширенные параметры

Существующий офис сейчас не передаёт эти настройки в OpenCode. Таблица описывает будущую реализацию. Отсутствующее поле означает нативное умолчание, ноль не равен отсутствию.

| Поле офиса | Подтверждённый механизм | Валидация и UX |
|---|---|---|
| вариант?: string | Имена итогового model.variants; в prompt_async отдельное верхнее поле variant | Только имя из каталога конкретной модели. Пусто — умолчание; reasoning=true с пустыми variants не создаёт переключатель уровней |
| температура?: number | agent.office.temperature, применяется при model.capabilities.temperature | Конечное число 0–2, дополнительно ограничения проверенного SDK/модели; скрыто при отсутствии поддержки. Если точный диапазон/совместимость неизвестны, параметр недоступен с причиной |
| пределОтвета?: number | provider[nativeID].models[modelID].limit.output; движок вычисляет maxOutputTokens | Целое от 1 до min(известный output модели, 32000). Уменьшаем только output, сохраняем context/input. Не заявлять это общим лимитом расхода задачи |
| Окно контекста / вход | Каталожные limit.context/input | Только чтение. Не увеличивать окно числом из UI |
| top_p / top_k | top_p есть в схеме агента, topK выбирается движком | В первом выпуске не редактируются: нет универсального признака поддержки и диапазона в каталоге |
| reasoningEffort, thinking.budgetTokens, thinkingConfig и подобные | Различные provider/model options | Напрямую не открывать. Штатные variants покрывают проверенные комбинации. Нельзя обещать один словарь уровней для всех моделей |
| maxTokens, maxOutputTokens в произвольном options | Не являются универсальным полем конфигурации агента | Не принимать; использовать только пределОтвета по механизму выше |
| steps, retries, таймауты, compaction, small_model | Внутренние параметры движка/офиса | Не открывать в этой форме; бюджет, maxTurns и разрешения офиса имеют приоритет |

Диапазон 0–2 — ограничение DTO офиса, не гарантия всего upstream. Серверный проверенный список возможностей для пары SDK/модель определяет доступность температуры и допустимые сочетания с reasoning. Не выводить совместимость из имени модели. Варианты с токенным бюджетом могут конфликтовать с уменьшенным пределом ответа: для первого выпуска **пределОтвета недоступен для всех reasoning=true моделей**; сервер отвергает такую комбинацию, включая вариант по умолчанию. Это консервативное ограничение снимается отдельной реализацией проверки бюджета. Для reasoning=false предел ответа доступен при известном output.

Умолчание предела ответа — нативное min(output, 32000), а не размер контекста/4 из старого искусственного провайдера. Повышение выше 32000 и пользовательская переменная outputTokenMax не входят в контракт. Данные цены — оценка; неизвестная цена остаётся неизвестной, не нулём. До сессии с maxBudgetUsd требуется цена, иначе отказ как в нынешнем адаптере.

## 7. Типы, выбор и наследование

Новые названия собственных типов и полей — на языке реализации. Имена существующих типов и нативного протокола сохраняются.

```ts
interface ПараметрыOpenCode {
  вариант?: string;
  температура?: number;
  пределОтвета?: number;
}
// Дополнить существующий ModelChoice:
interface ModelChoice {
  provider: ProviderId; // ProviderId дополнен литералом 'opencode'
  model: string;       // для opencode строго nativeProviderID/modelID
  opencode?: ПараметрыOpenCode;
}
```

Пример без секретов: `{ provider: 'opencode', model: 'openrouter/vendor/model', opencode: { вариант: 'high' } }`. Пример демонстрирует форму, а не наличие такой модели.

Параметры допустимы только при provider='opencode'. Расширить Role/RoleEditable/RoleView и SessionOptions тем же opencode. `Role.provider/model/opencode` образуют единый выбор. При «Как у офиса» копируется целиком актуальный ModelChoice офиса; собственный выбор роли не получает отдельные недостающие параметры от офиса. Пустой объект означает нативные умолчания. Отключение ownModel удаляет собственные параметры вместе с моделью.

Смена модели или поставщика одной операцией сбрасывает параметры и tier. Параметры применяются при следующей сессии; для работающего исполнителя сохраняется уже разрешённый снимок. Для PM действие при смене — существующий механизм перезапуска/новой сессии, без подмены конфигурации живого процесса. `sameChoice` должен сравнивать нормализованные параметры, а не только provider/model. `roleRuntime` сейчас возвращает только пару: его и всех потребителей снимка запуска нужно расширить, иначе параметры потеряются.

Нет фиксированной defaultModel для нового подключения: в ProviderSpec допустим служебный 'default', но его нельзя сохранять/исполнять как нативную модель. Кнопка «Использовать» сначала открывает выбор поставщика/модели и сохраняет полный выбор после подтверждения формы. Текущая логика SettingsPage.choose с немедленной записью defaultModel требует отдельной ветки. Также обновить полные Record<ProviderId, ...>, реестр engines/index, матрицу уровней моделей и все валидаторы ProviderId; отсутствие уровней у opencode не должно подставлять уровень Claude.

Миграция: старые данные и ключи не изменять, отсутствие provider по-прежнему означает Claude по существующим правилам. Отсутствие opencode — прежнее поведение. Settings.model=null остаётся null. При загрузке неизвестные/кривые поля параметров очищаются с диагностикой, без переноса в конфиг; при записи API неизвестные поля отвергаются 400. Некорректный сохранённый nativeID не заменять default — показать причину и запретить старт. Префикс sessionID остаётся opencode:; права и конфиг перестраиваются и при resume, старая история не является источником разрешений.

## 8. API офиса и хранение

Все маршруты — за существующей границей доступа API офиса. Не открывать пользователю адрес/пароль OpenCode serve и не предоставлять прокси произвольных его маршрутов.

| Маршрут | Контракт |
|---|---|
| GET /api/providers | Добавляет карточку opencode с engine=opencode; старые карточки неизменны. auth=['api-key']; не объявлять subscriptionLogin=true всему движку |
| GET /api/providers/opencode | Сохраняет верхние status/models для общего контракта; models содержит полные id только выбираемых моделей. Дополнительный opencode — версия, ревизия, дата каталога, устаревание, внутренние поставщики и причины недоступности |
| GET /api/providers/opencode?force=1 | Обновить каталог, дедуплицировать параллельные запросы; не сбрасывать рабочий снимок при сетевой ошибке |
| POST /api/providers/opencode/install | Прежняя общая установка движка; прогресс общий с семью пресетами |
| POST /api/providers/opencode/login | `{провайдер: nativeID, kind:'api-key', apiKey:string}`; только поддержанный nativeID; пустой ключ — 400, не «оставить старый» |
| DELETE /api/providers/opencode/login?provider=<nativeID> | Удалить одну авторизацию; nativeID обязателен. Нет операции молчаливого удаления всех ключей |
| POST /api/providers/opencode/validate | `{выбор: ModelChoice, ревизия:string}` → `{выбор, предупреждения:[], ревизия}`; проверка без генерации и записи. Та же валидация обязательна в updateSettings/editRole и перед стартом |
| Существующие updateSettings/editRole | Принимают расширенный выбор атомарно; старые сообщения совместимы |
| Существующие WS provider_* | Для opencode добавить поле провайдер и применить ту же серверную логику, что HTTP; без него login/logout — 400. Не создавать обход через WS |

Ошибки новых маршрутов: `{код, поле?, сообщение}`. 400 — форма/модель/параметр; 401 — upstream явно отверг ключ; 409 — изменившаяся ревизия каталога/параллельная операция; 501 — неподдержанный способ входа; 502 — upstream/сеть; 503 — движок отсутствует/несовместим. Сообщения фильтруются от ключей, заголовков и тел upstream. На изменённую ревизию UI обновляет описание модели и просит повторить сохранение, не меняет выбор автоматически.

Дополнительный DTO `opencode`:
- `версия`, `совместима`, `проверенныеВерсии: string[]`, `ревизия`, `обновлёнВ: number`, `устарел: boolean`.
- `провайдеры: {id, название, доступен, причина?, авторизация, модели}[]`.
- `авторизация: {состояние: 'нет'|'ключ'|'не-проверен'|'отклонён'|'без-входа'|'не-поддерживается', хвост?:string}`.
- модель: существующие ModelInfo плюс `opencode: {провайдер, модель, статус, инструменты:boolean, рассуждение:boolean, варианты:string[], температура?:{мин,макс}, пределОтвета?:{мин,макс}, контекст?:number, вход?:number, выход?:number, доступна:boolean, причина?:string}`. Цену передавать в существующем price. Наличие поля температуры/предела означает возможность редактирования, отсутствие — запрет. Для неподдержанного параметра дополнительно передавать `причиныПараметров?: {температура?:string, пределОтвета?:string}`, чтобы UI мог объяснить ограничение.

Агрегат ready на карточке значит «есть хотя бы одна пригодная модель с настроенным способом доступа»; он не подтверждает каждый внутренний nativeID. Перед назначением и запуском envBlock/status проверяет именно выбранные provider/model. При лимите блокируется выбранный nativeID, а не все подключения движка: расширить ключ лимита до `{provider:'opencode', провайдер:nativeID}`, прежние ключи лимитов сохранить.

Общие несекретные метаданные подключения — новый `подключения-opencode.json` рядом с DEFAULT_STATE_FILE, версия формата 1: список явно подключённых nativeID и ревизия настроек. Запись атомарной заменой, каталог не является настройкой и кешируется отдельно в памяти. Связка ключей — отдельно. Выбор офиса с параметрами — Settings.model в state.json; выбор роли — её provider/model/opencode и оверрайды теми же путями, что сейчас. Дисковые auth/config движка не являются источником истины подключения.

## 9. Сборка сессии и граница прав

Разделить старую ветку buildConfig и новую нативную. Для нового подключения:
1. Разрешить и проверить полный выбор; получить нативные метаданные и только его ключ.
2. Сгенерировать конфиг с enabled_providers=[nativeID], model и small_model одной выбранной пары. Сохранить нативный SDK/описание модели, внести лишь проверенные overrides. Не переписывать нативного поставщика в office.
3. agent.office — управляемый промпт роли, без пользовательских instructions/agent/tools. В prompt_async передать `{agent:'office', model:{providerID,modelID}, variant?, parts}`; variant — верхнее поле. В summarize также передать нативную пару.
4. Сохранить изолированные XDG, запреты project config/Claude instructions/внешних skills, pure, autoupdate/share/snapshot off. Удалять из окружения унаследованные OPENCODE_CONFIG, CONFIG_DIR, CONFIG_CONTENT, экспериментальные флаги и произвольные provider credentials перед выставлением своих. Учесть managed/remote config: изоляция должна проверяться итоговым конфигом и каталогом инструментов, а не наличием одного флага.
5. Единственный MCP в OpenCode — сессионный office remote, oauth=false, Bearer в заголовке. Внешние MCP роли входят только через officeCatalog и шлюз офиса, не вторым прямым соединением.
6. Нативные инструменты выключены на верхнем уровне и у agent.office, permission.asked получает reject. Формировать deny по всем фактически известным нативным инструментам совместимой версии, а не доверять неизменности сегодняшнего списка. Разрешены только имена инструментов сессионного моста; неизвестный новый инструмент — отказ/несовместимость.
7. Все вызовы моста проходят canUseTool с подменёнными аргументами при allow; Bash идёт через projectEnv и существующую песочницу. Сохранить scoped cwd, временный пароль serve, loopback и время ожидания подтверждения владельца.
8. Не допускать shallow/deep merge пользовательского JSON: server-generated config собирается заново из разрешённых полей. Запрещены headers, env/files substitutions из ввода, npm, plugin, mcp, permission, tools, prompt, instructions, shell, server и экспериментальные опции.

Протокол моста совместим по устройству: OpenCode поддерживает remote Streamable HTTP и headers, существующий офисный мост реализует его с отдельным токеном и таблицей имён. Смена LLM-поставщика не меняет MCP-транспорт. Однако toolcall=true в каталоге не доказывает качество схем у каждого SDK: нужен интеграционный тест вызова офиса и отказа прав для каждой открываемой семьи SDK.

Сохраняются ограничения платформ: nativeHands=false; команды под Seatbelt только на поддерживаемой macOS; localBinding=false в матрице роли не запрещает самому серверу служебный MCP loopback. Не обещать системную песочницу OpenCode на всех ОС. Картинки/аудио не включать по capabilities модели: текущий opencodeQuery превращает вход в текст, передача мультимедиа — отдельная работа.

## 10. UX-состояния

| Состояние | Поведение |
|---|---|
| Не установлен / установка / несовместимая версия | Общая установка движка, версия и причина; старт заблокирован |
| Каталог загружается | Индикатор; текущий выбор сохраняется |
| Ошибка каталога / устаревший снимок | Ошибка с повтором и датой; не показывать пустой список как «нет моделей» |
| Поставщик без ключа | Модели видны; «Подключить»; выбор для запуска заблокирован |
| Ключ сохранён, не проверен | Явная подпись; отсутствие платной проверки не маскируется «успешным запросом» |
| Публичная модель | «Без входа» для конкретной модели |
| OAuth/сложная авторизация | Отключённый способ с причиной; не вести в чужой CLI |
| Нет моделей / нет tool calling | Отдельная причина; не разрешать ручную замену capability |
| Лимит / сеть / ключ отклонён | Отдельные причины и действие; остальной каталог доступен |
| Смена поставщика/модели | Сброс расширенных параметров виден до сохранения |
| Удалённая модель или вариант | Сохранённое значение видно как недоступное; требуется новый выбор |
| «Как у офиса» | Видны разрешённые модель и параметры офиса; собственные поля не смешиваются |
| Расширенные параметры | Свёрнутый блок; только поддержанные поля; «Умолчания OpenCode» удаляет overrides |
| Настройки работающей роли | Пометка «Со следующей сессии» |

ProviderPick сегодня отбрасывает все метаданные кроме id/label, кеширует только по ProviderId и допускает свободный ввод для всех движков кроме Claude. Для OpenCode нужен отдельный выбор поставщика → модели с сохранением metadata, запросной ошибкой и loading; кеш учитывает ревизию, сбрасывается при login/logout/install/refresh. SettingsPage и AgentPanels используют один компонент параметров и одинаковый валидатор; общий datalist OpenAI-совместимых пресетов не подходит.

## 11. План реализации и приёмка

1. Сервер/типы: ProviderId, DTO каталога, хранение ключей нескольких nativeID, маршруты, нормализация и snapshot выбора, env/лимиты по выбранной модели.
2. Движок: отдельная нативная сборка конфигурации, параметры, безопасное окружение, продолжение и summarize с нативной парой.
3. Веб: карточка OpenCode, вложенный каталог, подключение ключом, общий компонент выбора/параметров для офиса и роли, все состояния выше.
4. Проверки: расширить test:providers и typecheck; новая модель/параметры проходят через HTTP и WS, наследование, сохранение/загрузку и запуск. Старые семь пресетов и sessionForProvider сохраняют поведение.
5. На изолированном стенде для 1.18.34 и отдельно 1.19.5: /doc и каталог; вариант в запросе; температура только при capability; понижение output у модели без рассуждений; вызов MCP; canUseTool deny; попытки включить bash/plugin/mcp/project-config; отсутствие ключей в ответах, логах и Bash; resume/compact; удаление ключа во время сессии; исчезновение модели. Использовать фиктивный LLM endpoint/ключи; реальные платные запросы не нужны для базовой приёмки.

Результат исследования достаточен для этих задач. Непроверенные живым запуском пункты перечислены в §2 и являются конкретными проверками реализации. Ограничения первого выпуска — OAuth, сложные облачные реквизиты, прямые provider options, неизвестные модели, мультимедиа и произвольный конфиг — должны оставаться явно видимыми, а не молча приниматься.
