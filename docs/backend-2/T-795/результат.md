# T-795: типы, каталог и ключи OpenCode

Реализована первая часть карты T-792. Использованы только фрагменты сохранённого T-727.patch для общих типов, KEY_VAR, белого DTO и проверки выбора. Контракт D-15 прочитан адресно в docs/backend-2/T-726/контракт-opencode.md (§1–2, §4–7); повторное исследование движка не проводилось.

## Изменённые файлы

- src/shared/providers.ts: отдельный ProviderId, ПараметрыOpenCode, МодельOpenCode, КаталогOpenCode, нормализованное сравнение sameChoice. Пресеты и default старых подключений сохранены. Параметры при сравнении старых пресетов игнорируются.
- src/shared/types.ts: объявление opencode в RoleEditable, без подключения сохранения.
- src/server/engines/types.ts: метаданные модели и объявление SessionOptions.opencode; значения в запуск ещё не передаются.
- src/server/engines/keys.ts: KEY_VAR частичный, новый ProviderId не загружает общий ключ и не читает окружение; общие saveKey/deleteKey отказывают для opencode. Существующий экспорт keychain пригоден, его менять не потребовалось.
- src/server/providers/ключи-opencode.ts: отдельные записи provider:opencode:<nativeID>, чтение, сохранение, удаление, сведения только с хвостом; ошибки системных программ заменяются безопасной диагностикой. Секреты не пишутся в JSON или кеш каталога. Ограничение ключа 1500 знаками обеспечивает запас для stdin-команды macOS Keychain. Платные запросы и проверка валидности реквизитов отсутствуют.
- src/server/providers/подключение-opencode.ts: каталогOpenCode, каталогDTO, проверитьВыбор, моделиКаталога. Белый DTO, полный nativeProvider/model с сохранением вложенных слешей, проверенный список SDK и версии 1.18.34, фильтры текстовых моделей с инструментами, публичный Zen только с нулевой ценой и connected в каталоге. Температура и предел ответа консервативно выключены у reasoning-моделей. Неподдерживаемые поставщики отображаются с причиной.
- src/server/providers/кеш-каталога-opencode.ts: TTL 15 минут, объединение параллельных загрузок, раздельные версия/ревизия ключей, копии снимков, устаревший снимок с прежней датой при ошибке. Проверка выбора отвергает stale и изменённую ревизию.
- src/server/providers/каталог-процесс-opencode.ts: временный пустой HOME/XDG/cwd, белый список окружения, запрет инструментов, плагинов, MCP и инструкций; проверка итогового конфига, остановка процесса и удаление профиля. Процесс каталога не получает ключи даже для подключённых поставщиков.
- src/server/providers/opencode.ts: только экспорт существующего startServer для управляющего процесса; рабочий opencodeEnv и запуск сессий сохранены.
- src/server/engines/opencode.ts: минимальная регистрация ProviderId с защитными отказами status/login/logout/start и пустым общим списком моделей. Это предотвращает падение общего списка провайдеров и случайный запуск через alias office; серверный каталог доступен отдельными функциями.
- src/server/childenv.ts: OFFICE_OPENCODE_API_KEY заранее удаляется из окружения команд проекта.
- scripts/test-opencode-каталог.ts: адресные проверки типов параметров, границ и нуля, sameChoice, DTO/SDK/версии/Zen, вложенных modelID, TTL/stale/ревизии, отдельных ключей, отказов связки и отсутствия секретов в окружении.
- scripts/test-providers.ts: совместимая проверка частичного KEY_VAR (непустое значение для существующих Google/Alibaba).
- package.json: команда test:opencode-каталог.

## Проверки

Успешны: npm run typecheck; OFFICE_KEYCHAIN=memory node --import tsx scripts/test-opencode-каталог.ts; npm run test:providers; git diff --check. test:pm и scripts/test-pm.ts не запускались. Реальная Keychain и живой бинарь OpenCode не использовались адресными тестами; проверка настоящего протокола и полного запуска остаётся частью 3.

## Следующие две части

1. **API и хранение.** Подключить HTTP каталог/validate/login/logout; проверку выбора до сохранения и обработку 409; Role/roleRuntime/packageRuntime, копирование, нормализацию и наследование параметров, сброс при смене модели/ownModel, настройки офиса/ролей. Перед удалением ключа остановить активные сессии выбранного nativeID. Файл подключений из старого патча не перенесён: наличие ключей сейчас получается непосредственно из отдельных записей Keychain. API должен явно сообщать, что сохранение ключа не проверяет платный запрос.
2. **Запуск сессий.** Подключить сборку SessionOptions, реальный status/models адаптера, обнаруженную версию, native providerID/modelID/variant и параметры, нативный конфиг с одной OFFICE_OPENCODE_API_KEY и ссылкой env вместо секрета, проверку модели/ревизии непосредственно перед стартом. Доказать изоляцию рабочих сессий, запрет чужих инструментов/MCP/плагинов, summarize/resume, остановку и очистку с подставным сервером и коротким запуском закреплённого движка. Защитные отказы адаптера заменить после этой интеграции.

Каталог серверный, HTTP-маршрутов и записи настроек в этой задаче нет. Временный управляющий профиль не используется как профиль рабочих сессий. Текущие ключи пресетов, настройки и разрешения не мигрируются.
