# T-798: HTTP-каталог и проверка параметров OpenCode

- `GET /api/providers/opencode` — `{status, models, opencode}` по §8 D-15; метаданные поддерживаемых параметров находятся в каталоге.
- `GET /api/providers/opencode?force=1` — обновление через существующий каталог T-797.
- Полные идентификаторы сохраняются: например, `openrouter/vendor/model`; неподдерживаемые модели не подменяются.
- `POST /api/providers/opencode/validate` принимает `{выбор:{provider:"opencode",model:"openrouter/vendor/model",opencode:{температура:0}},ревизия:"<ревизия каталога>"}`.
- Успех: `{выбор:<проверенный выбор>,предупреждения:[],ревизия:"<ревизия каталога>"}`.
- Ошибки имеют форму `{код,поле?,сообщение}` без ключей и произвольного текста upstream.
- Примеры: 400 `invalid-choice` при неверной модели/параметрах; 409 `catalog-changed` при смене ревизии.
- Нет движка: 503 `{код:"not-installed",сообщение:"Движок OpenCode не установлен"}`; несовместимая версия — 503 `incompatible-version`.
- Произвольный сбой подключения: 502 `{код:"upstream",сообщение:"Не удалось получить метаданные OpenCode"}`.

## Доработка по ревью

- Замечание о UTF-8 верно: отдельное декодирование чанков повреждало кириллические ключи на границах сетевых пакетов.
- Буферы собираются с контролем суммарного размера до 64 КиБ и декодируются один раз.
- Регрессия разрывает первую «в» ключа «выбор» между байтами: исправное подключение возвращает 200, отсутствующий движок — 503.
- Замечание об отсутствии отчёта устранено этим файлом; остальные выводы ревью не требуют изменений.
