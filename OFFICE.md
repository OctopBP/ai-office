# Что за проект

**AI Office** — приложение, где команда AI-агентов визуализирована как офис с
видом сверху. Пользователь ставит задачу менеджеру, тот раздаёт её исполнителям,
человечки в комнате показывают, кто чем занят.

Сейчас команда работает **над самим этим приложением**. То есть проект, который
вы правите, — это тот же офис, в котором вы сидите.

## Главный принцип

> Офис — это визуализация, а не источник правды.

Источник правды — доска задач и лента событий. Ходьба, пузыри и анимации
рендерятся **из** событий и ничего не блокируют. Поэтому графику можно выключить,
и всё продолжит работать. Не заводите логику в компонентах отрисовки.

## Стек

Node + TypeScript, React 19 + Zustand на фронте, `ws` для связи, Vite для сборки.
Движок агентов — `@anthropic-ai/claude-agent-sdk`. Хранилище — JSON-файл, не БД:
данных мало, а нативный модуль вроде better-sqlite3 добавил бы риск сборки.

## Карта файлов

| Файл | Ответственность |
|---|---|
| `src/server/agents.ts` | Сессии менеджера и исполнителей, MCP-инструменты, разбор событий SDK |
| `src/server/state.ts` | Состояние офиса, задачи, шина событий |
| `src/server/roles.ts` | Роли: промпт, модель, лимит клонов, изоляция |
| `src/server/offices.ts` | Реестр офисов: офис = проект со своей директорией и состоянием |
| `src/server/permissions.ts` | Классификатор риска вызова инструмента |
| `src/server/git.ts` | Ветки, worktree, коммиты, слияние |
| `src/server/cloud.ts` | Облачный режим на Managed Agents (написан, вживую не проверен) |
| `src/server/index.ts` | HTTP + WebSocket, раздача собранного веба, команды от клиента |
| `src/shared/types.ts` | Контракт между сервером и вебом |
| `src/web/Office.tsx` | Рендер комнаты и человечков |
| `design/sprites/gen.py` | Генератор пиксель-спрайтов (темы day и night) |

## Несколько репозиториев

У роли может быть свой репозиторий (поле «Репозиторий роли»). Тогда ветка задачи,
её diff и слияние идут туда, а не в общий репозиторий офиса. Репозиторий
фиксируется на задаче в момент старта — `task.repoDir`; всё, что потом делается с
результатом, обязано брать путь оттуда, а не из настройки роли. Одна задача живёт
ровно в одном репозитории.

## Правила работы в этом проекте

- **Комментарии и текст интерфейса — по-русски.** Комментарий объясняет «почему
  так», а не пересказывает код.
- **Перед сдачей задачи прогоняйте `npm run typecheck`.** Зависимости в вашей
  рабочей копии есть — `node_modules` подключён симлинком.
- **Не трогайте `src/shared/types.ts` мимоходом**: это общий контракт сервера и
  веба. Меняете — скажите об этом в отчёте, иначе соседняя ветка сломается при
  слиянии.
- **Промпты — это код.** Правка `PM_PROMPT` или `brief` роли меняет поведение
  офиса сильнее, чем правка функции. Изменили — прогоните `npm run test:pm`.
- Не пишите заглушки вместо рабочего кода.
- Не создавайте файлы «на будущее» и не переписывайте то, о чём не просили.

## Как запускается

```
npm run dev      # разработка: сервер с watch + vite на :5173
npm run office   # как приложение: сборка + сервер со статикой на :3001
npm run typecheck
npm run test:pm  # регрессия поведения менеджера (исполнители заглушены)
```

## Чего в проекте сознательно нет

Аутентификации, мультиюзера, облачного хранения, редактора планировки офиса,
автоматического слияния веток. Это осознанные решения, а не недоделки.
